# Точная проверка состава COMBOBOX: 108

```json
{"check_combo":"Список77","items":["Первый","","Дубль","Дубль"," а "]}
```

Шаг сравнивает все пункты по порядку. Регистр, пробелы, дубликаты и пустой
текст значимы. При первом различии сценарий завершается failed с индексом,
ожидаемым/фактическим значением и обеими длинами. Проверенный фактический
список остаётся в `form/combo-step-NNNN.json` с SHA-256, в том числе при failed.
Отсутствующий пункт обозначается null с флагом присутствия false и отличается
от существующего пустого пункта. Чтение использует механизм 106 без смены
фокуса/выбора и вызова обработчика.

Нужны установленный harness77 0.15.0 с bundled runtime forms, квалифицированный
FIO.ERT и профиль прежнего Windows/1С 7.70.027/DBF-стенда с copy_path.
Подготовка не запускает 1С и создаёт редактируемые form.json/module.1s/steps.json.

```powershell
python examples/combo-check/prepare.py --template <FIO.ERT> --stand <stand.toml> --output .local/combo108
python -m harness77 run --project .local/combo108/project.toml --stand .local/combo108/stand.toml
python examples/combo-check/run.py --project .local/combo108/project.toml --stand .local/combo108/stand.toml --output .artifacts/combo108
python examples/combo-check/verify.py --output .artifacts/combo108 --project .local/combo108 --template <FIO.ERT>
```

Полная серия — десять случаев через run, CLI suite и MCP. Baseline,
исправление, повтор и пустой список проходят. Удаление, добавление,
переименование, перестановка, изменение регистра и пробелов невыбранных
пунктов дают ожидаемые failed. Первоначально выбранный «Первый» не меняется
в отрицательных случаях. Все ожидания основного цикла побайтно одинаковы;
исправление возвращает модуль побайтно. Отдельный пустой случай ожидает [].

Положительный сценарий читает состав дважды, повторяет текущий select без
вызова обработчика, выбирает пустой пункт и подтверждает ровно один вызов.
Затем снова проверяет весь состав. Сверяются фактические snapshots,
первое различие, JSON/JUnit, ping MCP, сохранность шаблона/базы/реестра/чужих
процессов и очистка копии. После проверенного инфраструктурного отказа
можно явно использовать `--resume`: прежние результаты и журналы сохраняются.

Охват и ограничения — в [контракте 108](../../docs/tasks/108-check-combo.md).
