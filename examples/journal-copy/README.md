# Пример 039: копирование существующего документа из журнала

Закреплённый DBF-стенд `base-for-test`, 1С 7.70.027, установленный 1С++.
Нужен checkout: launcher находится в `research/forms`. Каждый run использует
новую проверенную копию; модули и диалоги конфигурации исходные.

Подготовка создаёт три похожих документа «Готовая продукция»: сосед
31 июля, исходник и второй сосед 1 августа 2026 года. В каждом две строки
1 × 10, 2 × 20, итог 50. Сохраняются точные ссылки, даты, номера и исходное
число документов. Новый объект независимо читает данные, проведение,
пометку и все проводки каждого из трёх документов до UI.

```toml
{ journal_period = true, start = "2026-07-31", end = "2026-08-01" }
{ find_document = true, limit = 100, open = false }
{ journal_copy = true }
```

Поиск клавишами End/Up останавливается на точной ссылке без Enter.
`journal_copy` заново проверяет ссылку/HWND и сохранённое состояние всех
трёх документов. Команда `0x8016` «Копировать» (F9) установлена по ресурсам
135/253 `1crcrus.dll`, найдена в меню своей главной формы и проверена на
доступность; WM_COMMAND получает проверенная MDI-рамка журнала.

Контроллер читает активный контекст: вид документа должен совпасть,
ссылка ещё не выбрана, HWND новый. Переносятся комментарий, обе строки,
товар, количества, цены и суммы. На закреплённом стенде копия получает
дату 8 ноября 2026 года и номер `000000000004`; она непроведённая и без
пометки, даже когда исходник проведён или помечен на удаление.
До записи число сохранённых документов остаётся исходным.

Форма меняет количество первой строки на 3 и комментарий на
«Harness77 копия 039». «Записать» сохраняет новый документ; `created`
свежим объектом подтверждает новую ссылку, отличную от исходника,
данные, дату, номер и отсутствие проведения/проводок.
«ОК» и «Да» на «Провести документ?» проводят копию; `reopen` открывает
ту же сохранённую ссылку и заново проверяет все поля строк и итог 70.
Независимое чтение подтверждает ровно один новый документ и две проводки
Дт 43 Кт 40: количество/сумма 3/30 и 2/40. Все исходные документы,
включая даты, номера, поля, строки, признаки и проводки, сохранены.

Отмена закрывает MDI-рамку копии через WM_CLOSE и отвечает «Нет» на
«Сохранить Документ?»: нового сохранённого документа нет.
Варианты `unposted` и `deleted` подготавливают непроведённый и помеченный
исходник; программные операции разрешены только для предпосылок.
Сама копия создаётся, записывается и проводится через UI.

```powershell
python -X utf8 examples/journal-copy/prepare.py --stand .local/s38a/stand.toml --output .local/journal039
python -m harness77 suite --suite .local/journal039/suite.toml --stand .local/journal039/stand.toml --output-root .artifacts/suites/journal039-main
python -m harness77 suite --suite .local/journal039/suite-failure.toml --stand .local/journal039/stand.toml --output-root .artifacts/suites/journal039-negative
python -m harness77 suite --suite .local/journal039/suite-limit-failure.toml --stand .local/journal039/stand.toml --output-root .artifacts/suites/journal039-limit
```

Основной набор: успех, повтор на свежей копии, непроведённый исходник,
помеченный исходник, отмена копии. Отрицательные наборы дают ровно один
failure JSON/JUnit и успешное продолжение: неверное финальное ожидание и
недостаточный предел поиска. При пределе 1 не отправляются Enter и Copy.
`no-copy/project.toml` блокируется до запуска 1С.

`scripts/verify_journal_copy77.py` принимает три `--suite UUID_DIR`,
`--blocked-run UUID_DIR`, `--output NEW_JSON`; `--excluded-run`, `--test-log`,
`--regression-report`, `--control-report` связывают остальные свидетельства.
Он перечитывает сырые ответы/протоколы, команды, HWND/PID/TID, исходную и
новую ссылки, данные/проводки, JSON/JUnit, хеши и очистку.
`scripts/verify_journal_copy_controls77.py --run SUCCESS_UUID_DIR --output NEW_JSON`
проверяет намеренные искажения свидетельств, включая сырой файл ответа в
отдельной временной копии; исходные свидетельства не меняются.

Кириллический `WM_CHAR` доставляется из одноразового потока на private desktop
своей 1С. Для преобразования символа проверяются русские раскладки отправителя
и редактора; обе прежние раскладки восстанавливаются после символа. Код,
HWND/PID/TID, desktop, раскладки и восстановление сохраняются в свидетельствах.
Пользовательский input desktop не переключается. После выхода из поля
контроллер отдельно читает реквизит комментария до записи документа.

Другие документы, журналы, SQL и варианты интерфейса не проверены.
Нативные дата/номер выше относятся к закреплённому стенду и этой серии.
