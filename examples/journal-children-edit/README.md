# Изменение подчинённого документа из смешанного списка (044)

Нужен checkout, закреплённый DBF-стенд 1С 7.70.027/1С++ и зарегистрированный
`copy_path`. Каждый запуск использует новую проверенную копию базы.
Исходные MD, модули и диалоги сохраняются.

Подготовка повторяет состав 043: три расходные накладные, у второй три
приходных ордера и два счёта-фактуры с похожими данными. Цель — точная ссылка
проведённого среднего ордера (слот 17). Поиск End/Up проходит ордер,
счёт-фактуру и нужный ордер; перед Enter ссылка читается повторно.
После отправки Enter адаптер ожидает новое видимое MDI-окно своего сеанса,
а затем читает контекст и проверяет ссылку/вид/основание. Предел ожидания —
10 секунд; команда Enter не повторяется.

`journal_children` с `edit = true` передаёт открытую форму обычным шагам
сценария. Нужны явные смешанные `kinds`, `limit`, исходный `expected`,
конечный `expected_after` и `fixture_verify`. `cancel`/`empty` с этим режимом
несовместимы. После передачи допускаются шаги формы документа; обязателен
`reopen`. Одна передача на сценарий. Прежний режим без `edit` сохраняет
поведение 041–043: просмотр и закрытие без записи.

Генератор дополняет шаблон `scenario.toml` следующими действиями:

```toml
# После journal_period и find_document open=false:
{ journal_children = true, source = "РасходнаяНакладная", link = "ДокументОснование", reference = 17, limit = 100, kinds = "ПриходныйОрдер,СчетФактура", journal = "Журнал.Общий.ФормаСписка.ФормаСписка", edit = true, expected = "<исходное состояние>", expected_after = "<конечное состояние>" },
{ value = "Сумма", text = "50" },
{ input = "Сумма", text = "75" },
{ value = "Сумма", text = "75" },
{ input = "Комментарий", text = "Harness77 подчиненный 044 изменён" },
{ value = "Комментарий", text = "Harness77 подчиненный 044 изменён" },
{ click = "Записать" },
{ click = "ОК", closes = true },
{ reopen = true },
{ check = "Комментарий", text = "Harness77 подчиненный 044 изменён" },
{ value = "Комментарий", text = "Harness77 подчиненный 044 изменён" },
{ value = "Сумма", text = "75" },
```

У исходной формы `ПриЗаписиПерепроводить(1)`: кнопка «Записать» уже
перепроводит существующий ордер; «ОК» выполняет штатное проведение и закрывает
форму без отдельного вопроса. Никакой программной записи после подготовки нет.

После шагов адаптер вновь читает точную ссылку/вид/основание и все проверяемые
сохранённые данные, закрывает текущую форму через WM_CLOSE, перечитывает курсор
списка, закрывает список и подтверждает исходный журнал/ссылку основания.
Свидетельства этого возврата — `editing_return` шага `journal_children`.
Контекст контроллера восстанавливается на исходный журнал перед его завершением.

В `cancel` после ввода отправляется `close_form`, затем «Нет» на
«Сохранить Документ? (Документ будет перепроведен)». Повторное открытие должно
показать исходные сумму 50 и комментарий. Независимое чтение подтверждает
проводку на 50. В успехе одна проводка Дт 50.1 Кт 62.1 на 75 с прежними
аналитиками; соседние документы, основания и состав связей сохраняются.

```powershell
python -X utf8 examples/journal-children-edit/prepare.py --stand .local/s42a/stand.toml --output .local/journal044
python -X utf8 -m harness77 suite --suite .local/journal044/suite.toml --stand .local/journal044/stand.toml --output-root .artifacts/suites/journal044-main
python -X utf8 -m harness77 suite --suite .local/journal044/suite-failure.toml --stand .local/journal044/stand.toml --output-root .artifacts/suites/journal044-failure
```

Основной набор: успех, повтор на новой копии, отмена. Отрицательный набор:
намеренно неверное ожидание проводки и успешный следующий сценарий.
`no-copy/project.toml` проверяет отказ без копии до запуска 1С.

`scripts/verify_journal_children_edit77.py` перечитывает сырые ответы/протоколы,
JSON/JUnit, команды и окна, исходный MD и данные. Он проверяет и вложенные
вызовы `editing_return`. `verify_journal_children_edit_controls77.py` проверяет
искажения на успешном прогоне и отмене, включая отдельную временную копию
UTF-16 ответа. Подробнее — [задание](../../docs/tasks/044-journal-children-edit.md)
и [техническая проверка](../../docs/tasks/044-journal-children-edit-acceptance.md).
