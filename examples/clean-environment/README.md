# Прикладной сценарий из чистого окружения (088)

Начиная с 092 доступна [штатная поставка исполнителя в wheel](../installed-native/README.md).
Этот пример сохраняет вариант с явным launcher и отдельно экспортируемым runtime.

С задачи [091](../../docs/tasks/091-cdb-startup.md) подготовка также передаёт
восстановление списка модулей CDB перед установкой точки COM и startup.json
с отдельными этапами до Initialize. Прежний wheel 089 остаётся пригоден:
изменён явно экспортируемый нативный исполнитель.

С задачи [090](../../docs/tasks/090-cell-input-readiness.md) подготовка копирует
исправленный исполнитель ввода ячеек: он ждёт внутренний редактор `1CEDIT`
и проверяет фокус перед вводом. Для обновления ранее экспортированного
комплекта создайте новый через `prepare.py`; прежние комплекты не меняются.

Комплект проверяет штатную форму «Готовая продукция»: две строки, изменение
количества на 3, итог 70, запись и проведение через UI, закрытие и повторное
открытие той же ссылки. Независимое чтение требует две проводки Дт 43 Кт 40
на 3/30 и 2/40. Выполняются успех, повтор, намеренно неверное ожидание 999
и успех после него. Ожидаются коды наборов 0 и 1, один JUnit failure.

Это чистая установка Python-пакета на **подготовленном Windows-стенде**,
с закреплённой базой и 1С 7.70.027, x86 CDB, 1С++ и FormEx. Установка платформы
и создание базы с нуля в проверку не входят. Путь временной копии уже должен
быть зарегистрирован в списке баз. Перед запуском завершите сеансы стенда;
копия и её `.lock` должны отсутствовать. Существующий idle-файл `.lock.guard`
сохраняется; созданный этим прогоном удаляется после подтверждённой очистки.

Подготовка из checkout (Python 3.11+, pip и закреплённый setuptools из
`requirements-build.txt`; сборка и установка ниже не используют сеть):

```powershell
python -m pip wheel --no-index --no-deps --no-build-isolation --wheel-dir .artifacts/s88-wheel .
python -B examples/clean-environment/prepare.py --stand .local/stage21-native/stand.toml --template .local/bases/base-for-test/ExtForms/rp14q1.GRP/FIO.ERT --wheel .artifacts/s88-wheel/harness77-0.4.0-py3-none-any.whl --output C:/MyProjects/harness77/.artifacts/s88-kit
```

Подготовка не запускает 1С. Новый каталог содержит wheel, шаблон ERT,
текст модуля, два профиля и набора, отдельный нативный исполнитель с двумя
DLL, независимые проверяющие скрипты и `kit.json` с SHA-256 каждого файла.
Исходники Python-пакета, вложенные репозитории и база в комплект не входят.
Абсолютные внешние зависимости перечислены в `kit.json`: платформа, CDB,
исходная база и зарегистрированный путь копии. DLL копируются из профиля;
при запуске исполнитель проверяет их закреплённые хеши.

Самостоятельный запуск комплекта без checkout из нового окружения:

```powershell
$kit = 'C:/MyProjects/harness77/.artifacts/s88-kit'
$env:PYTHONPATH = $null
$env:PYTHONHOME = $null
$env:PYTHONNOUSERSITE = '1'
python -m venv --without-pip "$kit/venv"
python -m pip --python "$kit/venv/Scripts/python.exe" install --no-index --no-deps "$kit/harness77-0.4.0-py3-none-any.whl"
& "$kit/venv/Scripts/python.exe" -B "$kit/run.py" --output C:/MyProjects/harness77/.artifacts/s88-result
```

`pip` нужен только исходному Python для офлайн-установки wheel в venv.
В venv остаётся единственная дистрибуция `harness77`. Пакет и каждый дочерний
launcher должны импортировать её из этого окружения. Рабочий каталог команд
создаётся отдельно. `research` не требуется: исполнитель передаётся явно
как часть комплекта; здесь выбран явный launcher вместо штатного runtime wheel.

Каталоги комплекта и результатов должны быть новыми, ASCII, без пробелов
(ограничение командных файлов CDB). Для повторного запуска используйте новый
`--output`. Профили используют относительные пути внутри комплекта.

Итог — `verified.json`, `suite.json`, JUnit, дочерние `run.json`, протоколы
шагов и `launcher-environment.json`. Проверка сверяет данные и сырые ответы,
хеши отчётов, очистку своей копии, опись файлов исходной базы (размеры/mtime),
список баз, временные COM-регистрации и процессы 1С до/после.
При ошибке свидетельства сохраняются; непроверенную копию не удаляют вручную.
