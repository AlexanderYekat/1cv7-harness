# Пример 028: выбор ссылочного значения

Сценарий проверяет неизменённую форму документа «Готовая продукция» закреплённого
стенда `base-for-test`, 1С 7.70.027 и зарегистрированного `copy_path` задачи 021.
Все данные создаются на свежей копии базы и удаляются вместе с ней.

`fixture_setup` создаёт два товара и записанный документ с исходным товаром.
Шаг `{ choose = "Товар", cancel = true }` открывает форму выбора по F4 и отменяет
её клавишей Escape; исходная ссылка сохраняется. Затем
`{ choose = "Товар", text = "Harness77 выбор 028" }` выбирает второй товар.
Контроллер находит единственный элемент с полным наименованием, переводит
курсор списка на него, watcher нажимает Enter. До выбора сверяются HWND формы
и ссылка текущего элемента списка, после — ссылка, вернувшаяся в строку документа.

Формула колонки берёт себестоимость нового товара (0), обнуляя стоимость и сумму.
Дальше сценарий вводит стоимость 10 и количество 3, проверяет сумму 30, записывает
и закрывает документ. `fixture_verify` читает его заново и проверяет равенство
ссылок. Ожидаемый результат — `1|Harness77 выбор 028|3|30`.

Из корня checkout, с установленным harness77 и локальными файлами стенда:

```powershell
python examples/reference-choice/prepare.py --stand .local/stage21-native/stand.toml --output .local/stage28-example
python -m harness77 run --project .local/stage28-example/project.toml --stand .local/stage28-example/stand.toml --output-root .artifacts/runs
```

Ожидаются `status = passed`, код 0. В `form/form-window.json` и операции `result`
сохранены шаги, редактор, окно и список выбора, вызовы контроллера,
`choice_closed`, `choice_value` и `choice_verified`. При провале поиска
`choice_cleanup.closed` подтверждает отмену выбора.

У `choose` ровно один вариант: непустое `text` либо `cancel = true`. Колонка
называется идентификатором или заголовком. При поиске сравнивается полное
наименование без крайних пробелов и без учёта регистра; группы исключаются,
одноимённые элементы вызывают ошибку. Колонка должна ссылаться на конкретный
справочник. Шапка, ERT, подбор и произвольные вложенные формы не поддержаны.
Диалог формулы после выбора отвечает обычным шагом `dialog`.
Если `add_row` сам открывает выбор, `choose` должен следовать сразу за ним:
он использует уже открытый список, проверяя колонку и контекст. Иначе такое
окно проваливает шаг и отменяется.

Отрицательный пример: замените имя в `choose` на «Harness77 отсутствует 028».
Ожидается провал с `found 0`, окно выбора отменено, дальнейшие шаги не выполняются.
