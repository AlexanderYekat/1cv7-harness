# Откат частичных проводок (задача 032)

Пример для закреплённого стенда 7.70.027: «Готовая продукция», Дт 43 Кт 40.
Требуются checkout, Python с установленным `harness77`, launcher форм и
зарегистрированный `copy_path` стенда. Каждый сценарий работает на новой
проверенной копии; исходная база не изменяется.

```powershell
python examples/posting-rollback/prepare.py --stand .local/stage21-native/stand.toml --output .local/s32
python -m harness77 suite --suite .local/s32/suite.toml --stand .local/s32/stand.toml
python -m harness77 suite --suite .local/s32/suite-failure.toml --stand .local/s32/stand.toml
```

Каталог подготовки должен быть новым. Срок открытия 240 с, расчёта 120 с,
общий 600 с. Автоматических повторов нет. Локальные профили и результаты
не добавляются в Git.

Генератор меняет только модуль проведения документа в копии: после заполнения
первой проводки вызывает `Операция.Записать()`, новым объектом читает эту операцию
и сообщает `HARNESS77-032-PARTIAL:…:1:3:30` (при перепроведении — `…:1:5:50`).
Далее вызывает деление на ноль (`runtime`) или `СтатусВозврата(0)` (`refusal`).
Условие ошибки задаётся комментарием подготовленного документа. Проверяющий код
не вызывает откат и не удаляет проводки.

`fixture_operations` выполняет четыре действия над одной ссылкой:

1. `post-first` — ожидаемый отказ первого проведения; `verify-first` читает
   признак 0 и отсутствие проводок.
2. `post-recover` — успешное проведение: две проводки 3/30 и 2/40.
3. `post-repost` — после отдельной записи строки 5/50 ожидается ошибка:
   сохранены признак 1 и прежние проводки 3/30 и 2/40. Поля строки остаются 5/50,
   поскольку записаны до проведения.
4. `post-final` — успешное перепроведение: две проводки 5/50 и 2/40 без дублей.

После каждого действия новый объект независимо читает все сохранённые проводки,
счета, ссылку товара, количества/суммы, признак проведения и поля первой строки.
`suite` проверяет runtime, refusal и повтор runtime на новой копии (код 0).
`suite-failure` ожидаемо заканчивается кодом 1: намеренно неверное ожидание 999
проваливает только `verify-repost`; следующий сценарий успешно проходит.

Независимая сверка обоих наборов:

```powershell
python scripts/verify_rollback77.py --suite .artifacts/suites/<main-id> --suite .artifacts/suites/<negative-id> --output .artifacts/stage32-verification.json
```

Verifier требует точный маркер чтения одной частичной проводки до ошибки/отказа,
сверяет ответы контроллера с отчётом, возвращённое значение и сохранённый признак,
все состояния проводок, JSON/JUnit и очистку. Неверное ожидание теста не меняет
его собственные ожидания о фактически сохранённых проводках. Отсутствие маркера
нельзя заменить одним лишь failed проведения. Опциональные `--regression` и
`--no-copy` проверяют набор 031 и отчёт отказа запуска без копии.

[Ожидания до запуска](../../docs/tasks/032-posting-rollback.md).
Охват ограничен этим документом и стендом; аварийная остановка процесса,
другие конфигурации и регистры отдельно не проверяются.
