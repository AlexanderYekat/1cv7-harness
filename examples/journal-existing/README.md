# Пример 035: найти и открыть существующий документ из журнала

Закреплённые DBF-стенд `base-for-test`, 1С 7.70.027, установленный 1С++ и
зарегистрированный `copy_path`. Нужен checkout: launcher находится в
`research/forms`. Каждый run работает на новой копии; модули и диалоги исходные.

Подготовка создаёт товар и три проведённые «Готовые продукции» с похожими
комментариями и датой 16 июля 2026 года внутри сохранённого интервала журнала.
Каждая содержит строки 1 × 10 и 2 × 20, две проводки Дт 43 Кт 40, итог 50.
Подготовленная ссылка — средний документ. До UI новый объект независимо читает
все три документа и их проводки; сырой ответ `fixture-initial` сохраняет результат.

`fixture_mode = "journal_existing"` открывает журнал «Материалы» без передачи
целевой ссылки. `{ find_document = true, limit = 100 }` нажимает End, затем Up:
после каждого перехода читает текущую ссылку и проверяет HWND журнала.
Сосед пропускается; только точное совпадение ссылки разрешает Enter.
Новый сохранённый контекст и HWND документа независимо сверяются с его формой MD.
Программного позиционирования курсора или открытия документа в этом шаге нет.

Количество первой строки меняется на 3, сумма — 30, итог — 70; комментарий —
«Harness77 журнал 035 изменён». «Записать» перепроводит уже проведённый документ
без вопроса, как предписано неизменённым `ПриЗаписиПерепроводить(1)` формы.
После «ОК» `reopen` требует уничтожения старых HWND и открывает ту же ссылку;
поля проверяются заново. Независимое чтение подтверждает новые строки,
ровно две проводки 3/30 и 2/40, прежние данные/проводки обоих соседей и
неизменное число документов этого вида.

Отмена: те же правки → `{ close_form = true }` (штатное закрытие рамки,
WM_CLOSE) → вопрос «Сохранить Документ? (Документ будет перепроведен)» → «Нет».
Форма закрывается; независимое чтение всех трёх документов даёт исходные данные.

## Запуск

```powershell
python -X utf8 examples/journal-existing/prepare.py --stand .local/s34d/stand.toml --output .local/journal035
python -m harness77 suite --suite .local/journal035/suite.toml --stand .local/journal035/stand.toml --output-root .artifacts/suites/journal035-main
python -m harness77 suite --suite .local/journal035/suite-failure.toml --stand .local/journal035/stand.toml --output-root .artifacts/suites/journal035-negative
python -m harness77 suite --suite .local/journal035/suite-limit-failure.toml --stand .local/journal035/stand.toml --output-root .artifacts/suites/journal035-limit
```

Основной набор: успех, повтор, отмена. Отрицательные наборы: неверное ожидание
сохранённого количества либо недостаточный предел поиска (`limit = 1`), затем
успешный сценарий. Каждый возвращает код 1 и ровно один JUnit failure.
При недостаточном пределе Enter не нажимается, документы остаются исходными.
`no-copy/project.toml` получает blocked/2 до запуска 1С.

Независимая сверка завершённых каталогов наборов (с UUID):

```powershell
python scripts/verify_journal_existing77.py --suite MAIN_UUID_DIR --suite NEGATIVE_UUID_DIR --suite LIMIT_UUID_DIR --blocked-run NO_COPY_RUN_DIR --output .artifacts/journal035-check.json
```

Проверяются сырые протоколы/ответы каждого перехода и открытия, их связь с
записью шага, HWND, начальное/конечное состояние трёх документов, UI-перепроведение,
JSON/JUnit, хеши и очистка. Дополнительные `--test-log`, `--excluded-run` и
`--regression-report` связывают журналы тестов, исследовательские отказы и регрессии.
Охват — один журнал, вид документа и сохранённый период данного DBF-стенда/1С++.
Другие периоды, журналы и SQL не проверены.
