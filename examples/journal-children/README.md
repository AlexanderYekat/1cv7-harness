# Подчинённые документы через интерфейс — задача 041

Сценарий на закреплённом DBF-стенде 1С 7.70.027/1С++: найти расходную
накладную в «Товарах», вызвать штатное «Подчиненные документы», открыть
точный приходный кассовый ордер и вернуться в исходный журнал без записи.
Нужны checkout и проверенная копия базы; wheel эти исследовательские шаги
не включает. Метаданные, модули и диалоги конфигурации исходные.

```toml
[platform.parameters]
form_object = "Документ.ПриходныйОрдер"
fixture_mode = "journal_existing"
journal_form = "Журнал.Товары.ФормаСписка.ФормаСписка"
# fixture_setup возвращает ссылку основания; slot 16 хранит ожидаемый ордер.
# fixture_verify независимо читает все документы и проводки.
steps = [
    { journal_period = true, start = "2026-07-31", end = "2026-08-01" },
    { find_document = true, limit = 100, open = false },
    { journal_children = true, source = "РасходнаяНакладная", link = "ДокументОснование", reference = 16, journal = "Журнал.Общий.ФормаСписка.ФормаСписка", expected = "<исходное состояние>", caption_control = "ндСфетФактураУжеСформирована", caption_text = "Не требуется" },
]
```

Полный исполняемый профиль создаёт `prepare.py` из `scenario.toml`. Подготовка
создаёт три похожих основания, отдельный ордер у первого и второго, ни одного
у третьего. Первый ордер проведён: одна проводка Дт 50.1 Кт 62.1, сумма 50,
количество 0; второй не проведён. Ссылки и сохранённые даты/номера фиксируются
до UI. Программные запись и проведение используются только для предпосылок.

`journal_children` перепроверяет активное основание, HWND и исходное состояние;
читает живое меню и вызывает `0x806C` только при доступной команде. Новый
«Общий журнал» проверяется по исходным метаданным, новому HWND своего PID/TID
и заголовку с основанием. End выбирает строку, Up подтверждает единственную
строку (либо пустоту); до Enter контроллер сравнивает
именно ссылки и `ДокументОснование`. В свидетельствах есть также внутренние
идентификаторы ссылок. Похожая подпись не заменяет точное совпадение.

После Enter проверяются сохранённая ссылка, новый HWND, связь и исходная
форма ордера. Закрытие выполняется через WM_CLOSE, возможный штатный вопрос
о сохранении получает только «Нет». Затем закрывается список подчинённых
и заново проверяется активный исходный журнал. Состав документов, поля,
строки, признаки, проводки/аналитики и счётчики не меняются.

`cancel = true` закрывает список без Enter. `empty = true` требует пустой
текущей ссылки и также не отправляет Enter. Эти режимы задаются отдельно.
Охват — по одному подчинённому ордеру у основания; поиск среди нескольких
подчинённых документов, другие пары, журналы и SQL не заявляются.

```powershell
python -X utf8 examples/journal-children/prepare.py --stand .local/s40j/stand.toml --output .local/journal041
python -X utf8 -m harness77 suite --suite .local/journal041/suite.toml --stand .local/journal041/stand.toml --output-root .artifacts/suites/journal041-main
python -X utf8 -m harness77 suite --suite .local/journal041/suite-failure.toml --stand .local/journal041/stand.toml --output-root .artifacts/suites/journal041-failure
python -X utf8 -m harness77 suite --suite .local/journal041/suite-reference.toml --stand .local/journal041/stand.toml --output-root .artifacts/suites/journal041-reference
python -X utf8 -m harness77 suite --suite .local/journal041/suite-limit.toml --stand .local/journal041/stand.toml --output-root .artifacts/suites/journal041-limit
```

Основной набор: успех, повтор, другое основание с проведённым ордером, пустой
список и отмена. Три отрицательных набора дают по одному failure JSON/JUnit
и успешное продолжение: неверное ожидание проводки, ссылка чужого ордера,
неполный поиск основания. Без копии запуск блокируется до 1С.

`scripts/verify_journal_children77.py` перечитывает сырые ответы/протоколы,
окна, команды, внутренние ссылки, данные, JSON/JUnit, хеши и очистку.
`verify_journal_children_controls77.py` проверяет намеренные искажения.
Факт выполнения нативных прогонов и итог приёмки фиксируются отдельно
в [отчёте 041](../../docs/tasks/041-journal-children-acceptance.md).
