# Пример 025: сценарий шагов на неизменённой форме

Запускаемый пример для закреплённого стенда `base-for-test`, платформы 7.70.027
и зарегистрированного `copy_path` задачи 021. Нужны checkout, установленный harness77
и локальные файлы стенда. На другой конфигурации нужно адаптировать имена объектов,
элементов и текст предупреждения. Своего языка в примере нет: весь тест — обычный
TOML в [scenario.toml](scenario.toml).

## Что проверяет тест

Форма элемента справочника «Банки» базы стенда, без изменений модуля и диалога.
При записи она проверяет БИК и сообщает «Возможно, БИК указан неверно.».

1. `fixture_setup` записывает в свежей копии базы банк «Harness77 банк 025».
2. Форма этой записи открывается. Шаг `check` проверяет показанное наименование.
3. В поле «Код» (БИК) вводится `12345`, затем нажимается «Записать». Шаг `message`
   ожидает предупреждение формы.
4. Вводятся верный БИК и новое наименование. «ОК» записывает элемент и закрывает форму:
   у шага указано `closes = true`. Шаг `no_message` проверяет, что предупреждения нет.
5. После закрытия `fixture_verify` читает запись заново, тест `data-verify` сравнивает
   результат с `Harness77 изменено 025|047777777`.
6. `run` сохраняет отчёт и удаляет копию.

## Шаги

| Шаг | Что делает |
| --- | --- |
| `{ click = "<элемент>" }` | нажимает кнопку или флажок; `closes = true` — нажатие закрывает форму |
| `{ input = "<элемент>", text = "…" }` | переходит в поле, заменяет его текст и выходит из поля |
| `{ check = "<элемент>", text = "…" }` | текст окна элемента; вместо `text` — `checked`, `enabled`, `visible` |
| `{ value = "<реквизит>", text = "…" }` | `Строка()` реквизита в контексте открытой формы |
| `{ message = "…" }`, `{ no_message = "…" }` | есть или нет такая строка среди сообщений 1С после последнего действия |

Элемент — идентификатор или подпись (без `&`) из описания формы; регистр не важен.
Неизвестный, неоднозначный элемент или элемент неподходящего класса — отказ до открытия
формы. Первый неуспешный шаг останавливает сценарий, тест `result` проваливается.
В отчёте указываются номер шага и причина. Ошибка исполнения 1С во время шага —
тоже провал, с текстом и строкой модуля. Протокол harness77 в модуле формы не нужен.

## Подготовка и запуск

Из корня checkout, указав новый выходной каталог:

```powershell
python examples/form-steps/prepare.py --stand .local/stage21-native/stand.toml --output .local/stage25-example
python -m harness77 run --project .local/stage25-example/project.toml --stand .local/stage25-example/stand.toml --output-root .artifacts/runs
```

Первая команда только готовит профили: дописывает к `scenario.toml` машинную часть
и пустой каталог `[configuration]`. 1С запускает вторая. Ожидается `status = passed`,
код 0. В `run.json` — три теста. В `platform-result.json` у операции `result` — список
`steps`: действие, сообщения 1С, прочитанное значение и состояние окна каждого шага.
В `form/` — описание формы, разрешённые шаги (`steps.json`) и осмотр окон.

Для отрицательного примера замените текст в шаге `message` на другой: ожидается
`failed`, код 1, причина — «step 4 (message …): no such message among […]».
