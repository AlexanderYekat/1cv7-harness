# Пример 027: табличная часть в сценарии шагов

Запускаемый пример для закреплённого стенда `base-for-test`, платформы 7.70.027
и зарегистрированного `copy_path` задачи 021. Нужны checkout, установленный harness77
и локальные файлы стенда. Весь тест — обычный TOML в [scenario.toml](scenario.toml);
шаги — те же, что в [примере 025](../form-steps/README.md) и [примере 026](../modal-dialogs/README.md),
и новые шаги табличной части.

## Что проверяет тест

Форма документа «Готовая продукция» базы стенда, без изменений модуля и диалога. У колонок
«Количество», «Стоимость» и «Сумма» формула `Пересчет()`: при изменении количества она
пересчитывает сумму как количество × стоимость.

1. `fixture_setup` записывает в свежей копии базы товар «Harness77 продукция 027» и документ
   с одной строкой: количество 1, стоимость 10, сумма 10.
2. Форма этого документа открывается. Курсор встаёт на первую строку, `value` читает количество.
3. `cell` вводит «3» в «Количество»: ячейка переходит в режим редактирования, текст заменяется,
   Enter заканчивает ввод, и формула колонки пересчитывает сумму — 30. Это проверяют `value`
   и `total`.
4. «Записать» записывает документ, «Закрыть» закрывает форму без вопроса о сохранении.
5. После закрытия `fixture_verify` читает документ заново, тест `data-verify` сравнивает
   результат с `1|3|30`: одна строка, количество 3, сумма 30.

## Шаги табличной части

| Шаг | Что делает |
|---|---|
| `{ add_row = true }` | новая строка, как клавиша Insert; строк должно стать на одну больше |
| `{ row = 2 }` | курсор на строку 2: клавиши Down и Up от текущей строки, как с клавиатуры |
| `{ cell = "<колонка>", text = "…" }` | ввод в колонку текущей строки: ячейка в режиме редактирования, текст, Enter; исполняется формула колонки |
| `{ delete_row = true }` | удалить текущую строку, как клавиша Delete; строк должно стать на одну меньше |
| `{ rows = 2 }` | число строк |
| `{ total = "<колонка>", text = "…" }` | итог колонки (`Строка(Итог(…))`) |
| `{ value = "<реквизит>", row = 2, text = "…" }` | реквизит строки 2; курсор не двигается |
| `{ key = "Down" }` | клавиша в табличной части или списке: Insert, Delete, Enter, Escape, Tab, Up, Down, Left, Right, Home, End, PageUp, PageDown, F2–F9 |

- Колонка называется идентификатором или заголовком из раздела `Browser` формы. Текст вводится
  только в колонку строкового, числового или датового реквизита; ссылку выбирают в отдельной
  форме, и такой шаг — отказ до запуска.
- Пока 1С принимает ввод новой строки, после Enter она открывает редактор следующей колонки.
  `add_row` и `delete_row` сначала заканчивают такой ввод клавишей Enter, как пользователь
  с клавиатуры. Escape отменил бы всю новую строку.
- `add_row`, `cell`, `delete_row` и `key` — действия: за ними могут идти шаги `dialog`, если
  формула или 1С открывает окно (например, вопрос «Объект будет помечен на удаление !» в списке).
- В форме списка (справочника или журнала) доступны `key` и `value` — реквизит текущего элемента.
  Остальные шаги табличной части в списке — отказ до запуска.
- Пока идут шаги такой формы, главное окно 1С показано без активации на своём рабочем столе
  harness77: текущей строкой документа 1С делает строку курсора при обновлении на простое,
  а оно приходит только видимому окну. Рабочий стол пользователя это не затрагивает.

## Подготовка и запуск

Из корня checkout, указав новый выходной каталог:

```powershell
python examples/table-part/prepare.py --stand .local/stage21-native/stand.toml --output .local/stage27-example
python -m harness77 run --project .local/stage27-example/project.toml --stand .local/stage27-example/stand.toml --output-root .artifacts/runs
```

Первая команда только готовит профили. 1С запускает вторая. Ожидается `status = passed`,
код 0. В `platform-result.json` у операции `result` — список `steps`: у шагов табличной части
есть состояние до действия (`before`: число строк, номер строки, текущая колонка) и после него
(`round_trip`), у `cell` — редактор ячейки, текст до и после ввода.

Для отрицательного примера замените ожидаемую сумму в шаге `value` на «20»: ожидается `failed`,
код 1, причина — «step 4 (value 'Сумма'): is '30', expected '20'».
