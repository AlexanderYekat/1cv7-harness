# Пример 024: создать запись, открыть форму и проверить запись изменения

Это запускаемый пример для закреплённого стенда `base-for-test`, платформы 7.70.027
и зарегистрированного `copy_path` задачи 021. Нужны checkout, установленный harness77
и локальные файлы стенда. На другой конфигурации имена объектов, реквизитов и формы
нужно адаптировать. Языка Gherkin в примере нет.

## Что делает тест

1. `run` собирает изменённую форму «Банки» и создаёт временную копию базы.
2. [setup.1s](setup.1s) записывает «Harness77 банк 024» и возвращает ссылку на запись.
3. Launcher открывает именно эту запись; модуль формы сообщает начальное имя.
4. В дополнительное поле `НовоеИмя77` вводится «Harness77 изменено 024».
5. Тестовая кнопка присваивает это значение `Наименование` и вызывает `Записать()`.
6. Форма закрывается. [verify.1s](verify.1s) через новый объект выборки читает запись
   по той же ссылке. Тест `data-verify` сравнивает результат с ожидаемым именем.
7. `run` сохраняет отчёт и удаляет копию. Следующий запуск начинает с новой копии.

Дополнительное поле и кнопка нужны именно этому примеру. Обработчик кнопки:

```bsl
Наименование = НовоеИмя77;
Записать();
```

К нему добавлен протокол launcher: один вызов обработчика и прочитанные значения.
Штатные элементы и прикладной код формы сохраняются.

## Подготовка и запуск

Из корня checkout, указав новый выходной каталог:

```powershell
python examples/test-data/prepare.py --stand .local/stage21-native/stand.toml --output .local/stage24-example
python -m harness77 run --project .local/stage24-example/project.toml --stand .local/stage24-example/stand.toml --output-root .artifacts/runs
```

Первая команда только готовит исходники и профили; 1С запускает вторая.
Повтор второй команды должен дать тот же результат с новым `run_id`.

В созданном `project.toml` код файлов включён строками `fixture_setup` и
`fixture_verify` раздела `[platform.parameters]`. `fixture_mode = "existing"`
подразумевается. Ожидание проверки записанного значения:

```toml
[[platform.tests]]
name = "data-verify"
command = "verify"
expect = "passed"
expect_value = "Harness77 изменено 024"
```

Ожидается `status = passed`, код 0. В `run.json` видны проверки открытия, результата
обработчика и чтения данных; в `platform-result.json` — операции, в `form/` — поля
до и после действий, описание формы и диагностические снимки. Проверка начального
имени выполняется и при повторном запуске. Для отрицательного примера замените
только `expect_value` теста `data-verify` на другое имя: ожидается `failed`, код 1.

`fixture_setup` также может вернуть группу или документ. Для нового элемента
подчинённого справочника задайте `fixture_mode = "owner"` и верните записанного
владельца. Для существующего подчинённого элемента оставьте `existing` и верните
ссылку на сам элемент. Подготовка работает только с `[configuration]` на копии.
