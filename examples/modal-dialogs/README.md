# Пример 026: модальные окна в сценарии шагов

Запускаемый пример для закреплённого стенда `base-for-test`, платформы 7.70.027
и зарегистрированного `copy_path` задачи 021. Нужны checkout, установленный harness77
и локальные файлы стенда. Весь тест — обычный TOML в [scenario.toml](scenario.toml);
шаги — те же, что в [примере 025](../form-steps/README.md), и новый шаг `dialog`.

## Что проверяет тест

Форма элемента справочника «Банки» базы стенда, без изменений модуля и диалога.
Если изменённую форму закрывают кнопкой «Закрыть», 1С спрашивает «Сохранить изменения?»
с кнопками «Да», «Нет», «Отмена».

1. `fixture_setup` записывает в свежей копии базы банк «Harness77 банк 026».
2. Форма этой записи открывается, в «Наименование» вводится новое имя.
3. «Закрыть» — 1С задаёт вопрос. Шаг `dialog` проверяет текст и отвечает «Отмена»:
   форма остаётся открытой, `check` видит введённое имя.
4. Вводится БИК, снова «Закрыть». На вопрос — «Да»: элемент записан, форма закрыта
   (`closes = true` стоит у шага `dialog`, после ответа на который форма закрывается).
5. После закрытия `fixture_verify` читает запись заново, тест `data-verify` сравнивает
   результат с `Harness77 изменено 026|047777777`.

## Шаг `dialog`

`{ dialog = "<текст окна>", button = "<кнопка>", text = "<ввод>", closes = true }`

- Идёт сразу после действия (`click`, `input`), которое открывает окно, или после другого
  `dialog`, если окна открываются одно за другим. Действие и его окна — одна цепочка:
  сообщения, ошибки исполнения и закрытие формы оцениваются на её последнем шаге.
- `dialog` — текст сообщения (`Предупреждение`, `Вопрос`, вопрос самой 1С) или заголовок
  окна ввода (`ВвестиСтроку`, `ВвестиЧисло`, `ВвестиДату`). Пробелы и переводы строк
  сравниваются как один пробел.
- `button` — подпись кнопки без `&`, регистр не важен, «OK» латиницей и «ОК» кириллицей
  равны. Если кнопка в окне одна, ключ можно не писать.
- `text` — текст для поля окна ввода.

Окно, на которое не отвечает ни один шаг, проваливает шаг действия: в причине — текст окна
и его кнопки. Не тот текст или нет такой кнопки — тоже провал. Окно провалившегося шага
закрывается кнопкой «Отмена», иначе «Нет», иначе единственной кнопкой, и сеанс завершается
обычно. `dialog` не на своём месте — отказ до запуска 1С.

## Подготовка и запуск

Из корня checkout, указав новый выходной каталог:

```powershell
python examples/modal-dialogs/prepare.py --stand .local/stage21-native/stand.toml --output .local/stage26-example
python -m harness77 run --project .local/stage26-example/project.toml --stand .local/stage26-example/stand.toml --output-root .artifacts/runs
```

Первая команда только готовит профили. 1С запускает вторая. Ожидается `status = passed`,
код 0. В `platform-result.json` у операции `result` — список `steps`: у шага действия —
окно, которое оно открыло (`modal`), у шага `dialog` — окно, ответ и вызовы 1С.

Для отрицательного примера замените текст первого шага `dialog`: ожидается `failed`, код 1,
причина — «step 3 (dialog …): the window shows 'Сохранить изменения?' with buttons
['Да', 'Нет', 'Отмена']»; окно закрыто «Отменой».
