# Пример 037: снять проведение из журнала

Закреплённые DBF-стенд `base-for-test`, 1С 7.70.027 и установленный 1С++.
Нужен checkout, launcher находится в `research/forms`. Каждый run использует
новую проверенную копию; модули и диалоги конфигурации исходные.

Подготовка создаёт три проведённые «Готовые продукции»: сосед 31 июля,
цель и второй сосед 1 августа 2026 года. По две строки 1 × 10 и 2 × 20,
итог 50, проводки Дт 43 Кт 40. До UI новый объект читает состояние всех трёх.

`journal_period` через штатный диалог расширяет исходный интервал до 1 августа.
`{ find_document = true, limit = 100, open = false }` перемещает курсор End/Up,
после каждого перехода сравнивая ссылку с подготовленной целью. При совпадении
остаётся в журнале: Enter и открытие формы документа отсутствуют.
Следом разрешены только шаги `journal_unpost`.

`{ journal_unpost = true, expected = "<состояние трёх документов>" }` заново
проверяет текущую ссылку и HWND. Читает штатное меню и обновляет доступность
команды `0x806E` «Сделать документ не проведенным». Проверенной MDI-рамке
отправляет WM_COMMAND. На точный вопрос «Подтвердите отмену проведения
документа !» отвечает «Да» (кнопка 6) либо, с `cancel = true`, «Нет» (кнопка 7).
Другие вопросы отклоняются и закрываются безопасным ответом.

До и после каждой команды отдельные вызовы контроллера заново читают цель,
признак проведения и данные/проводки всех трёх документов. Успех: цель не проведена,
проводок 0, поля и строки прежние; соседи, их проводки и число документов прежние.
При «Нет» весь исходный результат сохранён. Второй шаг с `enabled = false`
подтверждает штатную недоступность повторной команды и читает прежнее состояние
без отправки команды. Программного снятия проведения или открытия цели нет.

```powershell
python -X utf8 examples/journal-unpost/prepare.py --stand .local/s36a/stand.toml --output .local/journal037
python -m harness77 suite --suite .local/journal037/suite.toml --stand .local/journal037/stand.toml --output-root .artifacts/suites/journal037-main
python -m harness77 suite --suite .local/journal037/suite-failure.toml --stand .local/journal037/stand.toml --output-root .artifacts/suites/journal037-negative
python -m harness77 suite --suite .local/journal037/suite-limit-failure.toml --stand .local/journal037/stand.toml --output-root .artifacts/suites/journal037-limit
```

Основной набор: успех, повтор, отказ через «Нет». Отрицательные: неверное ожидание
сохранённого признака/проводок и недостаточный предел поиска, затем успешный
сценарий. В каждом — один failure JSON/JUnit, код 1. При пределе 1 ни Enter,
ни команда отмены не отправляются; документы исходные. `no-copy/project.toml`
блокируется до 1С.

`scripts/verify_journal_unpost77.py` принимает три `--suite UUID_DIR`,
`--blocked-run UUID_DIR`, `--output NEW_JSON`; дополнительные `--excluded-run`,
`--test-log`, `--regression-report` связывают остальные свидетельства.
Сверяются сырые ответы и протоколы всех вызовов, клавиши, ссылки/HWND,
вопрос/кнопка и PID/TID своего сервера, доступность меню, начальные/конечные
данные/проводки, JSON/JUnit, хеши и очистка. Другие журналы, документы и SQL
не проверены; нативно подтверждены указанные даты 2026 года.
