# Пример 033: полный цикл через форму документа

Для закреплённых `base-for-test`, 1С 7.70.027 и зарегистрированного `copy_path`
задачи 021. Нужны checkout, установленный harness77 и локальные файлы стенда.
Каждый сценарий использует новую проверенную копию. Модуль документа, модуль
формы и её диалог остаются исходными.

Подготовка создаёт товар и непроведённый документ «Готовая продукция» с двумя
строками. Сценарий меняет количество первой строки на 3, проверяет сумму 30
и итог 70, вводит комментарий. Нажимает «Записать», «ОК», отвечает «Да»
на «Провести документ?».

Новый шаг `{ reopen = true }` закрывает форму через установленный 1С++
`System.CloseForm(контекст, 0)` без записи изменений. Watcher требует уничтожения
HWND диалога и рамки, затем контроллер открывает ту же сохранённую ссылку и
заново находит окна формы. Подготовка данных не повторяется. Повторно открытая форма
проверяется по комментарию, двум строкам, количествам, стоимости, суммам и итогу;
затем завершается обычной командой `result` и проверенным завершением сеанса.
Шаг разрешён после предшествующих шагов, для существующего
документа с `fixture_setup` и `fixture_verify` на проверенной копии.

Независимая `fixture_verify` новым объектом читает документ и все бухгалтерские
проводки по исходной ссылке. Сверяются комментарий, число/поля/ссылки строк,
признак проведения и ровно две проводки Дт 43 Кт 40, 3/30 и 2/40.
`fixture_post` и `fixture_operations` не используются: проведение выполняет UI.

```powershell
python examples/document-form-cycle/prepare.py --stand .local/stage21-native/stand.toml --output .local/s33-example
python -m harness77 suite --suite .local/s33-example/suite.toml --stand .local/s33-example/stand.toml --output-root .artifacts/suites
```

`suite.toml` — успех и повтор, код 0. `suite-failure.toml` — неверное ожидание
сохранённого количества 999 и успех после него, код 1, один JUnit failure.
`suite-reopen-failure.toml` — неверное ожидание комментария в повторно открытой
форме и успех после него, также код 1 и один failure. `no-copy/project.toml`
проверяет блокировку профиля без `[configuration]` до запуска 1С.

В `platform-result.json` операция `result` содержит шаги, а `verify.value` —
сохранённые данные. Шаг `reopen` содержит ответ `reopen-return:1`, `reopen-same:1`,
новый осмотр окон и поля формы. Ответы контроллера и протоколы шагов сохранены
в `native/`. Независимая проверка наборов:

```powershell
python scripts/verify_document_form77.py --suite .artifacts/suites/SUITE --output .artifacts/stage33-acceptance.json
```

Можно передать несколько `--suite`, журналы проверок `--test-log` и
`--blocked-run` для прогона без копии. Выходной JSON должен быть новым файлом.

В этом сценарии табличная часть заполняется перед комментарием. В первых пробах
обратный порядок оставлял редактор ячейки открытым; сценарий честно проваливался
до записи. После подтверждения проведения окно в автоматизированном сеансе
остаётся открытым; отдельная кнопка «Закрыть» и Escape в этой последовательности
также не закрыли окно; стандартный `Форма.Закрыть(0)` не уничтожил HWND.
Поэтому закрытие перед reopen выполняет 1С++ System.CloseForm,
с обязательной независимой проверкой уничтожения окон. Эта возможность требует
компонент 1С++ закреплённого стенда. Свидетельства этих
проб сохраняются. Другие документы, SQL и создание документа из журнала не проверены.
