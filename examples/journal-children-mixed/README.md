# Выбор в списке подчинённых со смешанными видами (043)

Нужен checkout, закреплённый DBF-стенд 1С 7.70.027/1С++ и зарегистрированный
`copy_path`. Каждый запуск использует новую проверенную копию базы.
Исходные MD, модули и диалоги сохраняются.

Подготовка создаёт три расходные накладные. У первой один приходный ордер,
у второй три ордера и два счёта-фактуры, у третьей нет подчинённых.
Дата, сумма 50 и комментарий у подчинённых одинаковые; платформа выдаёт номера.
Счета-фактуры создаются между ордерами; обход End/Up ожидается как ордер,
счёт-фактура, ордер, счёт-фактура, ордер. Два ордера проведены с проводкой
Дт 50.1 Кт 62.1; счета-фактуры не проведены. Поле `Товар` составного типа
при подготовке счёта-фактуры получает тип `Справочник.Номенклатура`.

```toml
form_object = "Документ.СчетФактура"
# ...
steps = [
    { journal_period = true, start = "2026-07-31", end = "2026-08-01" },
    { find_document = true, limit = 100, open = false },
    { journal_children = true, source = "РасходнаяНакладная", link = "ДокументОснование", reference = 23, limit = 100, kinds = "ПриходныйОрдер,СчетФактура", journal = "Журнал.Общий.ФормаСписка.ФормаСписка", expected = "<исходное состояние>", caption_control = "кнПечать", caption_text = "Печать", browser_visible = false },
]
```

`kinds` — строка из 2–10 имён через запятую. Имена уникальны без учёта регистра,
содержат точное имя вида из `form_object` и исключают вид основания.
`limit` обязателен. До запуска проверяется существование всех видов и
реквизита `link` у каждого: документный тип должен принимать вид основания.
Разные имена реквизитов связи в одном списке не поддерживаются.

Каждая строка читается через свежий объект фактического вида, с проверкой
принадлежности основанию, точной ссылки, окна и общего сохранённого состояния.
Вид ожидаемой ссылки обязан совпадать с `form_object`; другой допустимый вид
может встречаться при обходе, но не открываться вместо цели. Неизвестный вид,
отсутствие цели и лимит дают отказ без Enter. Перед Enter/отменой выполняется
отдельное чтение, затем проверяются открытая ссылка/вид, связь и возврат.

На исходной форме счёта-фактуры таблица скрыта на вкладке «Шапка», а подпись
`кнПечать` меняется с «Печать...» на «Печать». Это явные ожидания профиля:
`browser_visible = false` и `caption_control`/`caption_text`. В режиме `kinds`
последняя пара может называть кнопку; геометрия и идентичность сохраняются
в проверках. Без `browser_visible` требуется видимая таблица.
Ожидания режима 041–042 без `kinds` сохраняются.

```powershell
python -X utf8 examples/journal-children-mixed/prepare.py --stand .local/s42a/stand.toml --output .local/journal043
python -X utf8 -m harness77 suite --suite .local/journal043/suite.toml --stand .local/journal043/stand.toml --output-root .artifacts/suites/journal043-main
python -X utf8 -m harness77 suite --suite .local/journal043/suite-failure.toml --stand .local/journal043/stand.toml --output-root .artifacts/suites/journal043-failure
python -X utf8 -m harness77 suite --suite .local/journal043/suite-reference.toml --stand .local/journal043/stand.toml --output-root .artifacts/suites/journal043-reference
python -X utf8 -m harness77 suite --suite .local/journal043/suite-limit.toml --stand .local/journal043/stand.toml --output-root .artifacts/suites/journal043-limit
python -X utf8 -m harness77 suite --suite .local/journal043/suite-kind.toml --stand .local/journal043/stand.toml --output-root .artifacts/suites/journal043-kind
```

Основной набор: пять позиций, повтор обоих видов на новых копиях и две отмены.
Четыре отрицательных набора содержат намеренный failure и успешное продолжение:
неверная проводка в ожидании, ссылка ордера другого основания, лимит 1,
ожидаемая ссылка счёта-фактуры при `form_object` приходного ордера.
`no-copy/project.toml` проверяет отказ без копии до запуска 1С.

Слоты подготовки: основания 1–3, ордера 15–18, счета-фактуры 23–24.
Независимое чтение до/после и на каждом шаге контролирует счётчики всех
документов и отдельных видов, поля и строки, даты/номера, признаки,
проводки/аналитики и точный состав подчинения.
`scripts/verify_journal_children_mixed77.py` перечитывает сырые UTF-16 ответы,
протоколы, JSON/JUnit, команды, окна, исходные MD и сохранённые данные.
Вид каждой сериализованной ссылки сверяется с номером вида в метаданных.
`verify_journal_children_mixed_controls77.py` проверяет искажения свидетельств
отдельно на открытии ордера и счёта-фактуры.

Результаты и ограничения — в [отчёте 043](../../docs/tasks/043-journal-children-mixed-acceptance.md).
