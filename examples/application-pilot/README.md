# Пилот регрессионной проверки прикладного модуля (095)

Проверяется настоящий модуль документа «Готовая продукция» квалифицированной
базы. Это контролируемая регрессия, а не найденная ошибка исходной базы:
в копии меняется одна строка `Операция.Сумма = Сумма;` на
`Операция.Сумма = Стоимость;`. Исправление возвращает полную сумму строки.
Исходная база и правила бухгалтерского учёта не меняются.

Один неизменный тест проходит четыре фазы: baseline → regression → fixed →
repeat-fixed. Он создаёт две строки, через штатную форму меняет количество
первой на 3, проверяет суммы 30/40 и итог 70, записывает/проводит через UI,
повторно открывает документ и независимо читает проводки Дт 43 Кт 40.
Ожидаются количества 3/2 и суммы 30/40. При ошибке документы остаются
правильными, но проводки содержат цены 10/20; должен провалиться ровно тест
`persisted-document-and-entries`. Ожидания, подготовка и UI-шаги между
фазами не меняются; меняется только прикладной модуль конфигурации.

Используется принятый wheel **0.4.0**, без новой версии harness. Stock runtime
forms, stand-init, project-init, md-extract, md-build, doctor и run берутся из
нового установленного venv. Настройка проекта под приложение — обычная
адаптация созданного каркаса: тестовый ERT-модуль, сценарий и каталог модулей.
В kit нет копии runtime, launcher.py или готового прикладного модуля базы.
Сам модуль извлекается установленным md-extract с явно выбранного стенда.

Подготовка из проверенных входов 092/094, без запуска 1С:

```powershell
python -B examples/application-pilot/prepare.py --application .artifacts/s92-kit-final --stand-inputs .artifacts/s94-kit --output .artifacts/s95-kit
```

Нативная проверка без checkout:

```powershell
$kit = 'C:/MyProjects/harness77/.artifacts/s95-kit'
$env:PYTHONPATH = $null
$env:PYTHONHOME = $null
$env:PYTHONNOUSERSITE = '1'
python -m venv --without-pip "$kit/venv"
python -m pip --python "$kit/venv/Scripts/python.exe" install --no-index --no-deps "$kit/harness77-0.4.0-py3-none-any.whl"
& "$kit/venv/Scripts/python.exe" -B "$kit/run.py" --output C:/MyProjects/harness77/.artifacts/s95-final
```

inputs.json задаёт реальные пути платформы/CDB/базы и зарегистрированной
копии, пользователя с ранее разрешённым пустым паролем и исключения копии.
Профили и проекты создаются командами, MD извлекается только для чтения.
Каждый run использует свежую проверенную копию. Output должен быть ASCII
без пробелов и разделителей CDB. Для повтора выберите новые kit/output.
Существовавшие до начала внешние сеансы входят в baseline и должны
сохраниться; их проверяет контроллер по удерживаемым дескрипторам. Изменение
инвентаря во время запуска останавливает проверку, чужие процессы не завершаются.

Сохраняются исходник выбранного модуля, обе версии, диффы ошибки/исправления,
хеш общего теста, плановые сборки MD и их независимая сверка по потокам,
дочерние отчёты, протоколы/окна/шаги и полная сверка сохранности стенда.
Исправление эквивалентно исходному корректному модулю; новой бизнес-функции
пилот не добавляет. Его результат — регрессионный тест и доказанный цикл
изменение кода → воспроизводимый отказ → исправление → успешный повтор.
