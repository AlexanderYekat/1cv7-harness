# Пример полного цикла harness77

Профиль проекта и два профиля стенда для команды `harness77 run`: статический
анализ → сборка ERT → проверка платформой → тесты → общий отчёт. Каждый запуск
получает новый `run_id` и отдельный каталог результатов `<output-root>/<run_id>`.

## Файлы

- `project.toml` — проект: шаблон, исходник модуля, тесты и сроки раздела 8.5.
- `module.1s` — модуль внешней обработки; реализует контракт безголовой проверки
  (см. комментарий в файле): `ПриОткрытии` сообщает маркеры и значение.
- `form.ert` — синтетический шаблон формы для демонстрации сборки
  (SHA-256 `b16526e5fc3c2f3c54084637f8c33d56d1ec1d0a8ff16ead7eed9c297ab45804`;
  собран генератором тестов, не прикладная форма). Для нативного прогона берите
  реальный шаблон-отчёт, например `ExtForms/rp14q1.GRP/FIO.ERT`.
- `scenario.json` — сценарий симуляционного стенда: долгий расчёт (600 с модельного
  времени) с периодами без сообщений и большой результат с проверкой SHA-256.
- `stand-simulation.toml` — переносимый стенд без 1С: симуляция проводит ту же
  логику полного цикла детерминированно и мгновенно. `platform_checked` всегда false.
- `stand-native.toml.example` — нативный стенд: подставьте пути/хеши и запускайте
  на реальной машине с 1С 7.7.

## Запуск без 1С (симуляция)

```powershell
harness77 run --project examples/full-cycle/project.toml ^
              --stand examples/full-cycle/stand-simulation.toml ^
              --output-root .artifacts/runs
```

Ожидается `status=passed`, код `0`, `platform_checked=false`. Отчёт запуска —
`.artifacts/runs/<run_id>/run.json`; большой результат и его хеш — в
`.artifacts/runs/<run_id>/results/`.

## Нативный запуск (реальная 1С 7.7)

Скопируйте `stand-native.toml.example` в локальный файл, выверите пути и хеши,
возьмите реальный шаблон-отчёт и запустите `harness77 run` с этим стендом.
Успешный нативный прогон даёт `platform_checked=true`. Долгий прикладной отчёт
на десятки минут задаётся увеличенными сроками проекта и реальными данными.
