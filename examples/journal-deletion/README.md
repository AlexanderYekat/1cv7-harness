# Пример 038: пометка на удаление и снятие пометки из журнала

Закреплённый DBF-стенд `base-for-test`, 1С 7.70.027 и установленный 1С++.
Нужен checkout: launcher находится в `research/forms`. Каждый run использует
новую проверенную копию; модули и диалоги конфигурации исходные.

Подготовка создаёт три проведённых документа «Готовая продукция»: сосед
31 июля, цель и второй сосед 1 августа 2026 года. По две строки 1 × 10,
2 × 20, итог 50, две проводки Дт 43 Кт 40. Сохранены ссылки, даты, номера
и исходное число документов. До UI новый объект читает данные, признаки
проведения/пометки и проводки всех трёх. Вариант `unposted` оставляет цель
непроведённой с самого начала; оба соседа проведены.

`journal_period` через штатный диалог включает обе даты.
`{ find_document = true, limit = 100, open = false }` ищет точную ссылку
клавишами End/Up; Enter и открытие формы документа отсутствуют.

```toml
{ journal_deletion = true, deleted = true, expected = "<состояние после пометки>" }
{ journal_deletion = true, deleted = false, expected = "<состояние после снятия>" }
```

Каждый шаг заново сверяет ссылку/HWND, читает сохранённые признаки и данные
всех трёх документов, затем обновляет доступность штатного меню. Команда
`0x8011` «Удалить» установлена по ресурсам 135/253 `1crcrus.dll` и найдена
в нативном меню. WM_COMMAND отправляется проверенной MDI-рамке журнала.
Повтор уже установленного значения `deleted` отклоняется до команды:
штатное действие переключает пометку.

Точные вопросы: «Объект будет помечен на удаление !» и
«Подтвердите отмену удаления объекта !». Ответ «Да» (ID 6) подтверждает,
`cancel = true` отвечает «Нет» (ID 7). Неожиданный вопрос отклоняется
и закрывается безопасным ответом.

На закреплённом стенде пометка проведённой цели снимает проведение и удаляет
обе проводки. Снятие пометки оставляет цель непроведённой, проводок нет.
В обоих действиях сохраняются ссылка, дата, номер, комментарий, строки,
соседи с их проводками и число документов. Отказ в любом подтверждении
сохраняет состояние непосредственно перед командой. Программной пометки,
снятия пометки или физического удаления нет.

```powershell
python -X utf8 examples/journal-deletion/prepare.py --stand .local/s37a/stand.toml --output .local/journal038
python -m harness77 suite --suite .local/journal038/suite.toml --stand .local/journal038/stand.toml --output-root .artifacts/suites/journal038-main
python -m harness77 suite --suite .local/journal038/suite-failure.toml --stand .local/journal038/stand.toml --output-root .artifacts/suites/journal038-negative
python -m harness77 suite --suite .local/journal038/suite-limit-failure.toml --stand .local/journal038/stand.toml --output-root .artifacts/suites/journal038-limit
```

Основной набор: полный цикл, повтор на свежей копии, непроведённая цель,
отказ пометки и отказ снятия. Отрицательные наборы дают ровно один failure
JSON/JUnit и успешное продолжение: неверное финальное ожидание и недостаточный
предел поиска. При пределе 1 не отправляются Enter и команда пометки.
`no-copy/project.toml` блокируется до запуска 1С.

`scripts/verify_journal_deletion77.py` принимает три `--suite UUID_DIR`,
`--blocked-run UUID_DIR`, `--output NEW_JSON`; дополнительные `--excluded-run`,
`--test-log`, `--regression-report` связывают остальные свидетельства.
Перечитываются сырые ответы/протоколы каждого вызова, клавиши, ссылки/HWND,
меню, вопросы/кнопки и PID/TID своего сервера, начальные и конечные данные,
признаки/проводки, JSON/JUnit, хеши и очистка.

Другие документы, журналы, SQL и варианты платформы не проверены.
Физическое удаление не входит в пример.
