# Проверка задачи 026: модальные окна в шагах

Дата: 25 октября 2026 года. [Задание](026-modal-dialogs.md).
Исходная ревизия — `ae36c1e`, ветка `master`.
Статус: **принято** владельцем 26 октября 2026 года; разрешены коммит и отправка на GitHub.

## Результат

Сценарий шагов отвечает на модальные окна, которые открывает обработчик: `Предупреждение`,
`Вопрос`, `ВвестиСтроку`, `ВвестиЧисло`, `ВвестиДату`, а также вопрос самой 1С «Сохранить
изменения?» при закрытии изменённой формы. Новый шаг:
`{ dialog = "<текст окна>", button = "<кнопка>", text = "<ввод>", closes = true }`. Он идёт
сразу после действия, которое открывает окно, или после другого `dialog`. Действие и его окна —
одна цепочка: сообщения, ошибки исполнения и закрытие формы оцениваются на её последнем шаге.

Окно, на которое не отвечает ни один шаг, проваливает шаг с текстом окна и его кнопками.
Не тот текст или нет такой кнопки — тоже провал. Окно провалившегося шага закрывается
безопасной кнопкой («Отмена», иначе «Нет», иначе единственная), и сеанс завершается обычно,
а не по тайм-ауту. Неверный порядок шагов — отказ до запуска 1С. Сценарии без окон работают
как в 025. Новых команд CLI и инструментов MCP нет, продукт (`src/`) не менялся.

## Как это устроено

- Последнее сообщение действия (`BM_CLICK` кнопки или выход из поля) отправляется из
  отдельного потока. Пока оно не вернулось, наблюдатель ищет новое видимое окно верхнего
  уровня потока 1С, у которого владелец выключен, или новое окно `#32770`. Из окна читаются
  заголовок, тексты, кнопки и поля с родителем, ID и стилем.
- Ответ: ввод в поле окна, как в поле формы 025 (фокус, выделение, символы, фокус на кнопку),
  затем `WM_COMMAND`/`BN_CLICKED` от кнопки, отправленный окну (`PostMessage`), — так в задаче
  002 закрывалось предупреждение. Процесс перепроверяется перед каждым сообщением.
- После возврата действия 1С вызывается, и затем окно ищется ещё раз. То, что действие
  поставило в очередь (`#Закрыть`), 1С выполняет раньше этого вызова. Если оно открывает окно,
  вызов обслуживается уже в цикле окна, поэтому окно открыто, когда вызов возвращается.
  Каждый вызов цепочки получает номер `шаг + 1000·k` и свой протокол.
- Подпись кнопки сравнивается без `&` и регистра. Латинские и кириллические буквы одного
  начертания равны: у `Предупреждение` кнопка «OK» латиницей, в сценарии пишут «ОК».

## Нативные случаи

Стенд — 7.70.027, `base-for-test`, профиль задачи 021. Каждый случай — один `harness77 run`
на своей копии базы. Форма элемента «Банки» получала кнопку «Окно 77» или поле с формулой
и процедуру в конце модуля; банк записывал `fixture_setup`. Ожидания записывались в задание
до каждой серии. Итоговая серия 1 выполнена на окончательном коде (хеши исходников — в сводке).

- Ответы: `m-warning` (предупреждение, сообщения до и после окна — в одном шаге), `m-question`
  («Нет» — «ответ Нет»), `m-chain` (вопрос «Да+Нет+Отмена», «Да», затем предупреждение),
  `m-string`, `m-number`, `m-date` (ввод в окне доходит до переменной: «abc77», «12.5»,
  «01.01.26»), `m-cancel` («Отмена» окна ввода — «строка отказ»), `m-field` (окно из формулы
  поля при выходе из него, реквизит «500»).
- Вопрос 1С при закрытии изменённой формы: `m-save` («Да» — элемент записан, форма закрыта,
  `verify` читает «Harness77 изменено 026|047777777»), `m-keep` («Отмена» — форма открыта,
  поле показывает новое имя).
- `m-ert`: FIO.ERT с `modal_module77.1s`. «Очистить» спрашивает «Очистить поля?»: «Нет» —
  фамилия прежняя, «Да» — поле пусто; ввод, «ОК» закрывает форму, «ФИО: Петров».
- Провал шага, сценарий остановлен на нём, окно закрыто, сеанс завершён обычно: `m-unexpected`
  (предупреждение без шага `dialog` — закрыто «OK»), `m-extra` (после «Да» открылось
  предупреждение, шага для него нет), `m-wrong-text` («the window shows 'Harness77 вопрос?'
  with buttons ['Да', 'Нет']» — закрыто «Нет»), `m-no-button` («no button 'Отмена' among
  ['Да', 'Нет']»), `m-close` (другой текст вместо «Сохранить изменения?» — закрыто «Отменой»,
  форму закрыл контроллер), `m-no-dialog` (окно ожидалось, но не открылось).
- Отказ до запуска 1С, `blocked`: `m-first` (`dialog` первым шагом), `m-closes-early`
  (`closes` у действия, за которым идёт `dialog`).

Все 19 итоговых случаев совпали с ожиданиями с первого прогона серии 1. [Пример](../../examples/modal-dialogs/README.md)
на неизменённой форме подготовлен своей командой и запущен дважды:
`37b14e89-bd94-453b-8144-f0b67999f8ea`, `4386fcd7-0e6b-4b79-9889-974b3ca93795`, оба `passed`.
Его отрицательный вариант (другой текст первого `dialog`, `f32fb8ec-6a22-4a0e-8e04-a9d215e81c7f`) —
`failed`, код 1, причина «step 3 (dialog 'Другой вопрос?'): the window shows 'Сохранить изменения?'
with buttons ['Да', 'Нет', 'Отмена']», окно закрыто. Регрессия на окончательном коде: пример 025
(`3b41835b`), пример 024 (`337cf4cf`), `f-elements` 022 (`actions`, `4c68dfca`) — прежние результаты.
После каждой серии база стенда и список баз 1С прежние; копии удалены, свои сеансы завершены.

## Как шла проверка

- Серия 0: все случаи `blocked`. Новый метод наблюдателя назывался `start` и перекрыл
  `Thread.start`. Метод переименован, переносимый тест проверяет, что наблюдатель не перекрывает
  методы своего потока.
- Серия 0b: 7 из 10. Ключ `action` шага `dialog` (номер шага действия) совпал с ключом записи,
  где хранится исход действия. Оценка упала, окно осталось открытым, два сеанса завершились
  по тайм-ауту завершения (`blocked`, копии удалены, процессов 1С не осталось). Ключ
  переименован в `chain`; любая ошибка шага теперь становится провалом шага, и окно закрывается.
  `m-date` прошёл, но был не доказателен: окно пустой даты сразу показывает сегодняшнюю дату.
  Дата заменена.
- Серия 0c: «Закрыть» (`#Закрыть`) вернулся без окна, вопрос 1С появился позже. Шаг его не увидел,
  сеанс завершился по тайм-ауту. Добавлен вызов 1С после возврата действия с повторным поиском окна.
- Серия 0d: пять из пяти; текст вопроса 1С — «Сохранить изменения?».

## Что установлено

- `Предупреждение`, `Вопрос` и вопрос 1С при закрытии формы — окна `#32770` с заголовком
  «1С:Предприятие»: значок (`Static` 20), текст (`Static` 65535), кнопки со стандартными ID:
  «OK» латиницей — 2, «&Да» — 6, «&Нет» — 7, «Отмена» — 2. `Вопрос` в режиме строки возвращает
  строку («Нет»).
- Окна `ВвестиСтроку`, `ВвестиЧисло`, `ВвестиДату` — `#32770` с подсказкой в заголовке, полем
  `1CEDIT` или `BMASKED` (ID 4146) с вложенным `1CEDITSPR`, кнопками «OK» (1), «Отмена» (2),
  «Помощь» (57670) и рамкой (`Button` 65535, `BS_GROUPBOX`). Окно числа показывает « 12.50».
- Владелец модального окна выключен. Окно появляется через 0,054–0,066 с после `BM_CLICK`,
  действие возвращается через 0–0,034 с после ответа.
- `#Закрыть` изменённой формы возвращается сразу; вопрос появляется при обработке очереди,
  и вызов 1С, отправленный после возврата, обслуживается в цикле этого окна. После «Да» форма
  записывает элемент (`ПриЗаписи` выполняется) и закрывается.

## Ограничения

`ОткрытьФормуМодально`, выбор значения ссылочного типа (`ВвестиЗначение` со справочником),
модальное окно в `ПриОткрытии` (до возврата `ОткрытьФорму`) и окна без кнопок не поддержаны
и нативно не проверялись. Окно ищется среди окон верхнего уровня потока 1С: новое видимое окно,
у которого владелец выключен, или `#32770`. Если окно другого вида закрыть нельзя, сеанс
завершается прежними сроками. Окно, которое действие откроет позже вызова 1С после возврата
(например, по таймеру), цепочкой не ловится. Ответ — сообщение окну, а не клавиатура системы.
Табличная часть, списки и формы, открытые из формы, по-прежнему не проверяются шагами.
