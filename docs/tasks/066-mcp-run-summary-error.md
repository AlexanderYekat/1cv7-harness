# Задача 066. Падение run и провал проверки в MCP

Задача принята владельцем 10 ноября 2026 года.

В пробе 065 упавший CLI вернул код 1 с пустым stdout. MCP принял его
как результат проверки. Теперь для кодов 0 и 1 инструмент `run`
проверяет структуру итоговой сводки, соответствие статуса коду выхода
и совпадение `run_id`, если он задан в запросе. При ошибке MCP
выставляет `isError=true`, сохраняет фактический код и потоки CLI
и добавляет пояснение в `content`.

## Результаты

- В нативной пробе на 1С 7.7.027 первый CLI аварийно завершился до
  `Initialize`. MCP вернул `exit_code=1`, `stdout=null`,
  `isError=true` и пояснение об отсутствующей или некорректной сводке.
- Второй запрос продолжил ждать на общем `copy_path`. Файлы копии,
  замок и процессы первого сеанса сохранились. После штатного
  завершения первого launcher тот же второй запрос создал свежую
  копию и вернул 42.
- Отдельный нативный тест ожидал 43 и получил 42. MCP вернул
  `exit_code=1`, `status=failed`, `stages.tests=failed` и
  `isError=false`. Проверка платформы и очистка подтверждены.

Временная копия, замки и запись пути удалены. Опись исходной базы
и список баз совпали со снимками до пробы. Прошли 70 тестов и
15 подтестов, включая пустую, неполную, неверную и чужую сводки.

Сводка — `.artifacts/stage66-native/verified.json`. Локальная проба
запускается командой `python -B .local/s66-verify.py <новый-суффикс>`.
