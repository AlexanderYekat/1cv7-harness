# Этап 5.1, задача 010: визуальные тесты форм

Дата: 19 октября 2026 года. Статус: **принято** —
[приёмка](010-visual-form-tests-acceptance.md). Предшествующие задачи —
[008](008-form-description-acceptance.md) (описание формы и первая кнопка)
и [009](009-protocol-root-cascade-acceptance.md). Направление —
[раздел 5.1 дорожной карты](../roadmap.md#51-собирать-и-изменять-формы-ert-по-текстовому-описанию),
пункт «Визуальные тесты форм». 19 октября владелец выбрал эту задачу следующей
и поручил выполнить её («давай выполни попробуй, если получится»).

## Зачем

Задача 008 проверяет форму как набор окон: окна элементов есть, их положение
совпадает с описанием, кнопка нажимается. Как форма выглядит, автоматически
не проверяется: в OLE-сеансе harness главное окно 1С скрыто, окна формы невидимы,
и снимок `PrintWindow` однотонный (305 и 251 байт, F2b `7d0455e0`). Видимость
кнопки подтверждена один раз вручную (F2m).

Визуальный тест должен открыть форму, снять её изображение и сравнить его
с заранее утверждённым эталоном: неизменённая форма проходит, сдвинутая или
пропавшая кнопка даёт отказ, отсутствие снимка, эталона или совместимой среды
блокирует сравнение явно.

## Вход: что нужно установить сначала

Получится ли вообще снять изображение формы в своём сеансе — неизвестно.
Поэтому первым идёт нативная проба V0, и только по её исходу строится сравнение.

## Проба V0 (ожидания записаны до прогона)

Профиль — F2b задачи 008 (FIO.ERT, кнопка «Проверка» 4161 в клиентской области,
`click_id = 4161`) с `[platform.parameters] visual_probe = true`. После осмотра
окон и до нажатия наблюдатель:

1. снимает окно формы (MDI-окно с заголовком) и внутренний диалог `#32770`
   четырьмя способами: `PrintWindow` с флагом 0 и с `PW_RENDERFULLCONTENT` (2),
   из своего потока и из потока, подключённого к private desktop сеанса
   (`SetThreadDesktop`; входной desktop не переключается);
2. показывает главное окно своей 1С: `ShowWindowAsync(SW_SHOWNOACTIVATE)` —
   только окно сервера своего процесса на своём desktop, идентичность
   перепроверяется, без активации и без ввода;
3. повторяет снимки через 0,5 с и ещё раз через 1 с (повторяемость);
4. скрывает главное окно обратно (`SW_HIDE`), затем нажатие идёт как в F2b.

| Что | Ожидание |
|---|---|
| снимки до показа | все 8 однотонны (одно значение цвета), как в F2b |
| показ | главное окно видимо (`IsWindowVisible`), окна формы и диалога тоже; без активации |
| снимки после показа | хотя бы один способ даёт неоднотонное изображение формы размером с её окно; предположение — флаг 0 работает, `PW_RENDERFULLCONTENT` вне входного desktop может дать пустой снимок |
| повтор через 1 с | у работающего способа изображение то же байт в байт (SHA-256 PNG) |
| скрытие и далее | главное окно снова невидимо; нажатие `clicked:1` ровно один раз; своя 1С завершена штатно, чужие сеансы сохранены |

Если ни один способ не даст изображения формы, сравнение снимков в этой задаче
не строится: исход записывается, варианты (видимый desktop, другой способ показа)
согласуются с владельцем.

## Исход V0 (`53b93f39`)

Предположение о показе подтверждено, о способе снимка — уточнено:

- До показа все 8 снимков однотонны (те же SHA-256, что в F2b). Окна формы
  и диалога имеют собственный `WS_VISIBLE`; невидимы они только потому, что скрыто
  главное окно 1С (у него `WS_VISIBLE` нет).
- `ShowWindowAsync(SW_SHOWNOACTIVATE)` сделал главное окно видимым за 0,09 с,
  вместе с ним — MDI-окно формы и диалог; `SW_HIDE` вернул исходный стиль за 0,06 с.
- После показа `PW_RENDERFULLCONTENT` даёт изображение формы из любого потока;
  флаг 0 — только из потока, подключённого к desktop сеанса (из своего потока
  снимок однотонный). Снимок окна формы 349×222 содержит заголовок «Фамилия, Имя,
  Отче…», три поля, кнопки «ОК», «Очистить», «Закрыть» и новую «Проверка»
  в правом верхнем углу. Рамка окна — без DWM (private desktop не входной).
- Повтор через 1 с отличается ровно в 13 пикселях: 1×13 в поле «Фамилия» —
  мигающий курсор ввода. Остальные пиксели совпадают.
- Нажатие `clicked:1`, сеанс завершён штатно, чужие сеансы сохранены; `run` — `passed`.

Отсюда способ снимка для сравнения: показать главное окно своей 1С без активации,
снимать `PW_RENDERFULLCONTENT`, прямоугольник курсора брать у потока 1С
(`GetGUIThreadInfo`) и маскировать, снимать серией до двух совпадающих подряд
(вне курсора) и затем скрыть окно обратно.

## Что делается

### Сравнение (продукт, переносимо)

- `src/harness77/visual77.py`: чтение и запись PNG без новых зависимостей,
  сравнение пикселей вне масок с допусками, изображение различий (снимок светло-серым,
  различия красным, маски синим), проверка среды, хранилище эталонов.
- Профиль проекта получает раздел `[visual]`: каталог эталонов и проверки
  `[[visual.checks]]` — `name`, `state` (`open` — сразу после открытия, `clicked` —
  после нажатия), `window` (`form` — окно с заголовком, `dialog` — внутренняя
  часть), `channel_tolerance` и `max_diff_pixels` (по умолчанию 0 — точное
  совпадение), `mask_caret` (по умолчанию да), `masks` — прямоугольники
  с обязательной причиной. Маски и допуски задаются в профиле до прогона.
- `run` с `[visual]` получает обязательный этап `visual` после `tests`.
  Снимки запрашиваются у стенда (`--captures-json`); каждая проверка сравнивает
  снимок своего состояния и окна с эталоном. В каталоге запуска
  `visual/<проверка>/`: `baseline.png`, `actual.png`, `diff.png`, `result.json`
  с `run_id`, хешами и итогом.
- **Блокировка, а не провал:** нет снимка, снимок неустойчив, нет эталона,
  эталон изменён (SHA-256 не совпадает с записью), среда снимка отличается от среды
  эталона или не записана. Среда — версия платформы, хеш конфигурации, сборка
  Windows, DPI системы и окна, тема, системные шрифты и сглаживание, локаль,
  способ снимка.
- **Эталон появляется только явно:** `harness77 visual approve --project …
  --run … --by …` копирует снимки прошедшего платформу запуска в каталог эталонов
  с записью (кто, когда, `run_id`, хеши ERT и описания, среда, курсор).
  Существующий эталон заменяется только с `--replace`; `run` эталоны не пишет
  ни при каком исходе.
- `harness77 visual compare A.png B.png --output DIR` — то же сравнение двух
  файлов вне запуска.

### Снимки (исследовательский адаптер)

`research/forms/form_launcher77.py` принимает запрос снимков: показывает главное
окно своей 1С, снимает состояние `open`, нажимает кнопку (`click_id`), снимает
`clicked`, скрывает окно. Каждый снимок — с прямоугольником курсора, фокусом,
числом попыток и средой. Модуль проб `research/forms/visual_module77.1s`:
обработчик «Проверка» пишет «Нажато: <n>» в поле «Фамилия», так что состояние
после нажатия видно. Вызов обработчика по-прежнему проверяет тест `click-4161`
(маркер `clicked:1`) — отдельно от внешнего вида.

## Решения

Владелец поручил выполнить задачу («давай выполни попробуй»), отдельных решений
не задавал. Приняты варианты, повторяющие решения задачи 008: формат — JSON и PNG
без новых зависимостей; сравнение и эталоны — продукт (`src/harness77`), снимки —
исследовательский адаптер (`research/forms/`); исполнитель запускает 1С сам на
`base-for-test`; шаблон — FIO.ERT. Эталоны утвердил исполнитель после просмотра
снимков; владелец может посмотреть их и при несогласии утвердить заново
с `--replace`.

**Не входит:** другие шаблоны и стенды (проверен один, 96 DPI), формы с данными
базы, состояния кроме `open`/`clicked`, допуски для сглаживания шрифтов (нулевые
допуски на этом стенде достаточны), MCP.
