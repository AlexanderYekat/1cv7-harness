# Задача 092. Штатная поставка нативного исполнителя

Реализована и проверена 12 ноября 2026 года.
Продолжение [091](091-cdb-startup.md).

Задача принята владельцем 12 ноября 2026 года.

## Использование и границы

Wheel **harness77 0.2.0** содержит квалифицированные адаптеры и их ресурсы.
Выбор внутри `[stand]`:

```toml
runtime = "forms" # либо "headless"
```

`forms` исполняет сценарии форм, `headless` — прежний check/execute.
Параметры runtime и launcher взаимоисключающие. Явный launcher сохраняет
разрешение пути относительно TOML, аргументы, сроки и механизм отмены.
Для simulation/import параметр runtime отклоняется.

Штатный режим квалифицирован на Windows, 1С 7.70.027 и CDB x86,
с прежними закреплёнными MD/DD, 1С++, FormEx и helper/identity DLL.
Требуются `[configuration] modules` и зарегистрированный copy_path.
Пустой modules допустим: неизменённая MD исполняется на свежей копии.
Прямое открытие источника штатным runtime не квалифицировано и отклоняется;
явные launchers сохраняют собственный контракт.
Платформа, CDB, DLL и база задаются профилем, DLL/база в wheel не входят.

## Реализация

`native_catalog77.json` задаёт 33 файла: 12 Python-модулей forms,
15 модулей platform77, шесть VBS/1С-ресурсов. Build-команда копирует только
этот список в harness77/_native и создаёт manifest.json с версией схемы,
runtime/платформы и SHA-256 каждого файла. Эти источники включены в sdist,
из которого также собирается wheel. Probes, тесты, DLL, базы и локальные
данные в payload не попадают. Ручных копий runtime в src нет.

Использовано расширение стандартного build_py с объявлением входов и
выходов: [контракт setuptools](https://setuptools.pypa.io/en/stable/userguide/extension.html).
Новые runtime-зависимости и загрузки из сети не добавлены.

`inspect_runtime` проверяет адаптер, схему/версию, квалифицированную
платформу, совпадение списка с каталогом, пропуски/лишние файлы и SHA-256.
Кеш __pycache__, создаваемый установщиком, не входит в исходный payload.
Манифест обнаруживает неполную, смешанную или повреждённую установку;
он не является криптографической подписью поставщика.

Doctor читает эти сведения без импорта Windows-контроллера. Его JSON
stand.runtime содержит адаптер, версию, число проверенных файлов и хеш
манифеста; отказ даёт blocked/2. NativeBackend проверяет payload до Popen,
дочерний `harness77.native_runtime77` — перед загрузкой контроллера.
Интерпретатор берётся из окружения CLI. В launcher-environment.json
сохраняются пути установленного пакета, интерпретатор и сведения runtime.

Все 33 файла исполнителя скопированы побайтно, включая исправления
090–091. Владение процессами до Initialize, nonce/desktop, permit,
сроки и очистка не ослаблены. Установка и doctor не активируют COM и
не запускают 1С. Для штатного runtime нужна обычная установка wheel;
исследовательские launchers и editable-проверки исходников имеют отдельный путь.

## Воспроизведение

[Пример и команды установки](../../examples/installed-native/README.md).
Пример содержит wheel, внешние DLL, входы, профили и проверяющие скрипты.
В нём нет native/ и launcher.py: runtime берётся только из site-packages
нового venv, CWD находится отдельно, PYTHONPATH/PYTHONHOME очищены.

```powershell
python -B scripts/verify_package77.py --output .artifacts/s92-package --command-timeout-s 600
.artifacts/s92-kit-final/venv/Scripts/python.exe -B .artifacts/s92-kit-final/run.py --output .artifacts/s92-final
.artifacts/s92-kit-final/venv/Scripts/python.exe -B scripts/verify_runtime77.py --kit .artifacts/s92-kit-final --output .artifacts/s92-controls
```

Для повторного запуска выбирается новый output. Проверка поставки строит
sdist из изолированного набора исходников, проверяет его состав, собирает
wheel из sdist, перечитывает payload/хеши и устанавливает офлайн в venv
без pip. Установлена только дистрибуция harness77; CLI и тесты запускаются
из чужого каталога без соседних репозиториев.

Отрицательные пробы повреждают только вторую одноразовую установку.
Каждое изменение восстанавливается в finally, здоровый комплект сохраняется.
Пропущенный VBS, изменённый session77.py и другая версия манифеста должны
блокировать doctor/run до launcher, CDB и Initialize. После восстановления
проверяется явно заданный launcher.
