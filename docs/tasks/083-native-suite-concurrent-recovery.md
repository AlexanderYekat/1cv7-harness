# Задача 083. Два MCP-повтора после аварии suite

Задача принята владельцем 11 ноября 2026 года.

Режим `--retries 2` расширяет [пробу задачи 082](082-native-suite-recovery-probe.md).
Два независимых MCP-сервера получают по запросу `run` с общим `copy_path`,
пока прежние CDB, 1С и OLE-клиент ещё живы. Каждый запрос должен сообщить
об ожидании пути до снятия паузы. Проба сверяет копию, замок, открытую
таблицу и обе COM-регистрации с состоянием перед аварией.

После штатного выхода прежних процессов любой из запросов может получить
копию первым. Проба удерживает этот запуск после `Initialize` и `check`
до нового сообщения второго запроса об ожидании `copy_path`. Затем оба
запроса по очереди должны вернуть `42` с одним `Initialize` каждый.
Отчёт первого захватившего путь должен подтвердить снятие обеих старых
COM-регистраций, отчёт второго — содержать пустой список снятых
регистраций.

## Прогон на 1С 7.7.027

Команда из корня репозитория для существующего локального стенда

```powershell
python -B research/mcp/verify_suite_recovery77.py --stand .local/stage21-native/stand.toml --project .local/stage21-native/s3/cases/m-same/project.toml --output .artifacts/s83-native-repeat --retries 2
```

Первый прогон пересёк полночь. Диалог смены рабочей даты оставил прежнюю
1С открытой после освобождения OLE, и ожидание выхода истекло. После
отказа от смены даты и подтверждения штатного выхода временную копию,
замок и две COM-регистрации первого прогона очистили. Повтор запустили
в новом каталоге.

## Результат повторного прогона

- Пока прежние процессы удерживали копию, каждый запрос дважды сообщил
  об ожидании пути. Снимки копии, замка и COM совпали. После снятия
  паузы CDB, 1С и OLE-клиент вышли с кодом 0.
- Первый получивший путь запрос ждал 10,840 с. Он заменил копию,
  снял обе старые COM-регистрации и вернул `42` после одного
  `Initialize`. Пока он удерживал свежую копию, второй запрос снова
  сообщил об ожидании. Снимок новой копии за это время сохранился.
- Второй запрос получил тот же путь после 31,652 с ожидания, создал
  свою свежую копию и вернул `42` после одного `Initialize`. Список
  снятых старых COM-регистраций у него пуст.

Первый результат прерванного набора сохранился, `suite.json` и JUnit
сохранили `complete=false`. Копия, замок и защита замка удалены.
Исходная база, список баз, COM-регистрации и процессы 1С совпали
со снимками до прогона.

Локальный протокол — `.artifacts/s83-native-repeat/verified.json`.
Прошли 54 локальных теста MCP и работы с копией.
