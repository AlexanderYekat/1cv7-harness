# Проверка задачи 024: тестовые данные и существующие объекты

Дата: 23 октября 2026 года. [Задание](024-test-data.md).
Исходная ревизия — `fc1b19c`, ветка `master`.
Статус: **принято** владельцем 23 октября 2026 года; разрешены коммит и отправка на GitHub.

## Результат

Launcher форм готовит известные тесту записи один раз в свежей копии базы и открывает
записанный элемент, группу или документ по ссылке. Для нового элемента подчинённого
справочника передаёт подготовленного владельца. После закрытия формы команда `verify`
может заново прочитать запись и сравнить результат с `expect_value`.

Без `[configuration]` подготовка отвергается до старта 1С. Код подготовки не выполняется
на базе стенда; действуют прежние проверки метки копии, `run_id`, хеша MD, зарегистрированного
пути, замка и удаления копии. Новых CLI-команд и MCP-инструментов нет.

## Нативные случаи

Стенд — 7.70.027, `base-for-test`, профиль задачи 021, копия без `ExtForms`, `actofsverok`,
`temp` (854 файла). Ожидания фиксировались в задании до каждой серии.

- `element`, `group`: созданы записанные банк и группа банков; форма показывает заданное
  имя, модуль читает то же имя. `document`: создана доверенность с заданным комментарием,
  его показывают поле и обработчик тестовой кнопки.
- `child`, `owner`: открыты существующий договор и новый договор с подготовленным
  контрагентом. В обоих случаях форма прочитала нужного владельца; у существующего договора
  также проверено поле наименования.
- `example`, `example-repeat`: ввод нового имени, один вызов кнопки записи, закрытие формы,
  чтение нового имени отдельным объектом выборки. Оба раза начальное имя прежнее, итоговое —
  «Harness77 изменено 024».
- `setup-once`: после `check` и `open` в копии ровно одна запись по двум тестовым именам;
  итог `Harness77 изменено 024;count:1`.
- `wrong-kind`, `wrong-group`, `empty`, `unwritten`, `wrong-owner`, `setup-error`:
  неподходящая ссылка или ошибка подготовки — `blocked` с причиной, форма не открылась.
- `wrong-expectation`: действия формы прошли, неверное ожидаемое имя провалило только
  `data-verify`. `verify-error`: ошибка исполнения завершающей проверки при ожидании успеха
  проваливает тест. `verify-negative`: та же ошибка, явно ожидаемая тестом, считается
  пройденной отрицательной проверкой.

Отдельно профиль без `[configuration]` — `blocked` до создания каталога нативного сеанса,
`run_id = 4db93164-e37b-44c8-9d69-efebb4d9221a`.

Все 17 итоговых сценариев совпали с ожиданиями (свод перечитывает последние результаты
каждого случая, предыдущие отказы сохранены). Готовый [пример](../../examples/test-data/README.md) подготовлен своей командой и запущен
дважды: `61dbcc58-26ae-4add-90a4-8ca153829844`, `8ecc5aab-2e91-41ef-8825-3b2481756fe4`.
Оба запуска — `passed`, три проверки совпали с ожиданиями. Регрессия без подготовки данных:
`e-button` задачи 023 и `f-doc` задачи 022 — `passed`, значения прежние.

После каждой серии база стенда и список баз 1С прежние; копии удалены, свои сеансы завершены.
Перечень файлов базы сравнивается по пути, размеру и времени; MD/DD дополнительно закреплены
хешами платформенного стенда. Общий отчёт перечитывает `run.json`, проверяет его SHA-256,
фактические результаты, удаление копий и сохранность источника.

## Ограничения

Работа подтверждена на закреплённом файловом стенде и перечисленных формах. Пример рассчитан
на его справочник «Банки»; для другой конфигурации нужны её поля, обработчики и описание формы.
Подготовка и проверка — тела функций 1С в профиле TOML, не новый язык сценариев.
Сохраняется прежний протокол инструментирования формы (`Форма.Параметр`, маркер загрузки).

Исходная форма доверенности высотой 220 открылась и показала нужный комментарий, но 1С
восстановила увеличенную табличную часть: нижние элементы смещены на 33 px, проверка
геометрии отказала с невязкой 12,34 px. Итоговый сценарий проверяет изменённую форму
высотой 240 с тестовой кнопкой, как направление задачи 022. Допуск геометрии не ослаблен;
автоматическая нормализация сохранённых размеров окна здесь не реализована.

Новая группа подчинённого справочника, формы плана счетов, операций и проводок,
изменение структуры метаданных и SQL-стенд не проверялись.
