# Задача 103. Файловые steps и expected

Поручена владельцем 14 ноября 2026 года после приёмки опубликованной 0.9.0.
Статус — принята владельцем 14 ноября 2026 года.
После приёмки поручены [публикация 0.10.0 и проверка скачанного wheel](103-release-0100-acceptance.md).

[Протокол технической проверки](103-file-json-inputs-acceptance.md).

Цель — менять steps.json и expected.json рядом с fixture.1s/reader.1s и
повторять run/suite/MCP без project-init и перегенерации профиля.

Локальная поставка 0.10.0: профиль схемы 4, platform.parameters.steps_file
и platform.tests[].expect_json_file. Пути разрешаются от TOML. Каждый файл
исключает встроенное значение той же роли; expect_json_file требует
expect=passed и исключает expect_value. JSON — UTF-8 без BOM, до 1 MiB,
с прежними ограничениями глубины/узлов, без повторных ключей, NaN/Infinity
и одиночных суррогатов. Steps — непустой массив непустых объектов со
скалярными значениями; смысл операций проверяет прежняя нативная подготовка.
Ожидание — любое значение JSON с прежней проверкой json_labels.

Общий загрузчик читает файлы и перечитывает их перед execute, включая
сохранённый ProjectProfile. После чтения используются зафиксированные
значения, а не дальнейшее содержимое файлов. В run/input-files сохраняются
точные байты steps.json и test-NNNN.expected.json; JSON содержит роль,
индекс теста для ожидания, размер, источник и SHA-256. Fixture/reader
сохраняют контракт 102 и собственный fixture-inputs. Inline 101 и схема 3
102 продолжают работать; прежняя 0.9.0 должна отвергать схему 4 явно.

project-init разрешает ссылки от scenario.json, проверяет до публикации,
копирует четыре файла и сохраняет локальные ссылки. Для нескольких файлов
ожиданий создаёт expected-NNNN.json; для одного — expected.json.

Приёмка на прежней фактуре: неизменные исходник/ошибка +1/исправление/повтор
через run, CLI suite и stdio MCP; отдельно совместимые схемы 2 и 3.
Пробы steps: количество второй строки 3→4, UI читает 120/170, прежнее
expected обнаруживает пять расхождений. Пробы expected: только ожидаемый
total 140→141, одно расхождение при правильном UI. Восстановление возвращает
passed. Каждый вариант проходит все три интерфейса при том же профиле.

Отрицательные входы: отсутствующие/повреждённые файлы обеих ролей, неверная
структура steps, inline/file конфликты, схема 3 с новыми полями, кодировка,
пустой файл и каталог. Blocked до платформы, без дочернего run у suite;
тот же живой MCP затем выполняет корректные запросы. Сверить снимки,
JSON/JUnit, неизменность профилей/тестов, сохранность базы/реестра/процессов
и очистку копий. Публикация релиза в поручение не входит.
