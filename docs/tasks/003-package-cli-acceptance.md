# Приёмка этапа 3: пакет, CLI и сборка ERT

Дата: 13 октября 2026 года. Статус: **принято в описанном охвате**.
Задание — [003-package-cli.md](003-package-cli.md).

## Что реализовано

- Устанавливаемый `harness77` 0.1.0, wheel/sdist, `src`-layout, словарь внутри
  пакета, консольная команда и `python -m harness77`. Runtime-зависимостей нет;
  build backend — setuptools 80.9.0.
- Команды `lint`, `compiler-protocol`, `extract`, `build`. Первые две сохраняют
  прежние схемы, диагностические правила и коды возврата. В линтере дополнительно
  отклоняется отчёт через hardlink на вход/контекст.
- Сборка новой ERT использует прежний CFB writer с отдельной проверяющей обёрткой:
  CP1251/CRLF, строгий режим по умолчанию, явная legacy-нормализация с отчётом,
  SHA-256 входов/результата, сверка текста/остальных потоков/каталога,
  перечитывание временного файла, публикация без перезаписи существующего выхода.
- Документация установки, контрактов, разработки, проверок и происхождения кода.
  Исходные devtools/77MCP и их Git-истории не изменены.

## Свидетельства

До добавления новой сборки установленный пакет прошёл прежние 95 тестов:
92 прошли, 3 symlink пропущены из-за прав Windows. Лог:
`.local/package77-migration-tests-unrestricted.log`.

После реализации сборки — 16 новых проверок без ошибок. Полная приёмка:
[скрипт](../../scripts/verify_package77.py), локальный результат
`.artifacts/package77/acceptance-20261013/summary.json`, статус `passed`.
Он строит sdist из отдельного дерева без вложенных репозиториев, затем wheel
из sdist; устанавливает его офлайн в чистое venv и запускает тесты из чужого
каталога с кириллицей и пробелом, без PYTHONPATH и системных пакетов.

Итог: **111 тестов, 108 прошли, 3 symlink пропущены**, ошибок нет. Проверены
обе точки входа, словарь установленного пакета, единственная установленная
дистрибуция, успешный минимальный пример и импорт P1/P2 с 60/7 диагностиками.
Версии: Windows, runtime Python 3.12.14, build Python 3.13.6, setuptools 80.9.0.
Linux и другие версии Python в этой сессии не проверялись.

Дополнительное сравнение четырёх ERT оригинального корпуса КУДиР:
`.artifacts/package77/corpus-20261013/summary.json`, статус `passed`.
Диагностики и коды возврата прежнего/установленного линтера совпали целиком:
P1 — 6 ошибок, P2 — 7, OK1/OK2 — 0; предупреждений нет. Это статика, поэтому
6 ошибок линтера P1 не равны 60 сообщениям его импортированного протокола.
Для каждого случая выполнены извлечение и сборка отдельной ERT, сохранены
шесть посторонних потоков, исходный SHA-256 совпал с манифестом до и после.
Новые ERT в платформе не запускались.

Первый запуск тестов внутри sandbox получил отказы Windows на
`resolve(strict=True)`. Повторение вне sandbox подтвердило работоспособность;
неуспешный лог сохранён. Сетевой индекс пакетов был недоступен, приёмка использует
уже установленный закреплённый backend и офлайн-установку wheel. Обычная установка
из интернета в этой сессии не проверена.

## Границы и следующий шаг

Готовность относится к упаковке, существующей статике/импорту и сохранности
модульной сборки CFB v3. Не доказаны компиляция новых артефактов, работа видимых
форм, 77MCP-адаптер, сборка всей MD, полный runner и долгие отчёты.
Для публикации нужен поддерживаемый файловой системой hardlink; неподдерживаемая
операция приводит к отказу, а не небезопасной подмене алгоритма.

Существующие низкоуровневые функции записи devtools сохранены как legacy-код;
продуктовый путь — `artifacts.build`. Контракт долгих расчётов предусмотрен
в [contracts.md](../contracts.md), реализация и нативная приёмка относятся к этапу 4.

Следующий шаг: связать статику, сборку, принятый platform77-контроллер и минимальные
тесты в один запуск с новым run-id и проверкой соответствия артефакта. База
выбирается явно и используется по уже согласованной политике без обязательного
копирования. Отмена импорта не требует восстановления базы: исходные репозитории
сохранены, карта и хеши находятся в [migration.md](../migration.md).
