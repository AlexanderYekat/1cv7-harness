## Реализация

В конфигурацию проекта добавлены fixture_setup_file и fixture_verify_file
для schema_version=3. Для каждой роли встроенный текст и файл исключают
друг друга. Пути разрешаются от TOML; содержимое — UTF-8 без BOM/NUL,
непустое и представимое в Windows-1251. В runtime передаются обычные тела
функций; его протокол, UI, копирование базы и ожидания фактуры сохраняются.

Общий load_project проверяет/читает файлы. Перед execute они читаются снова,
включая случай ранее загруженного ProjectProfile. Каждый run сохраняет
исходные байты в fixture-inputs/; inputs.fixture_files и result_files
содержат роль, источник, размер, SHA-256 и подтверждение снимка.
В runtime используется текст именно этих байтов с нормализацией переводов
строк. Последующие правки относятся к следующему запуску.

project-init разрешает ссылки относительно входного scenario.json,
проверяет файлы до создания проекта, копирует их в fixture.1s/reader.1s,
обновляет локальные ссылки в JSON/TOML и выбирает схему 3. При встроенных
текстах сохраняет прежние схему 2 и байты сценария. Схемы 1–2 и входы 101
продолжают поддерживаться. [Реальный отказ опубликованной 0.8.0](../../.artifacts/s102-evidence/old-080-schema-guard.json)
подтвердил, что она отвергает схему 3 до запуска платформы.

## Нативный проект

Проект — C:/MyProjects/h77-102-files/, вне checkout; установлен выбранный
wheel через локальный connect/harness77.txt. Профиль схемы 3 ссылается
на fixture.1s и reader.1s. База, пользователь, DLL, CDB, ERT и контроллер
переданы явно. Операции идут через .harness77/launch.py; PYTHONPATH/PYTHONHOME
пусты, user site отключён.

Основная серия использует неизменные файлы и бизнес-ожидания 101:
вторая строка 3×30=90, итоги 140; ошибка +1 даёт 91/141 с четырьмя точными
JSON-расхождениями. Три интерфейса проверяют четыре файловые фазы и отдельный
вариант со встроенными телами схемы 2. Два контроля подписи сохраняются.

Отдельные пробы правят только файлы при том же неизменном профиле:
fixture меняет сохраняемый комментарий и вызывает расхождение /comment_ok;
reader возвращает {}, что вызывает missing_field; восстановление возвращает
passed. Каждая тройка повторяется через run, CLI suite и тот же живой MCP.
Снимки фиксируют каждую фактически использованную редакцию. project-init,
project.toml и scenario.json между этими пробами не переписываются.

Семь отрицательных входов через каждый интерфейс: отсутствующий файл,
inline/file конфликт, не-UTF-8, непредставимый символ, пустой файл,
схема 2 с файловыми полями и каталог вместо файла. Все дали blocked до 1С,
без дочернего run у suite, с последующим успешным запросом к тому же MCP.

## Полученные результаты и свидетельства

Основной цикл через каждый интерфейс дал passed/failed/passed/passed;
контролируемая ошибка обнаружена с прежними четырьмя JSON-расхождениями.
Дополнительный встроенный вариант 101 прошёл через все три интерфейса:
raw JSON и MD совпали с исходным вариантом принятой опубликованной 0.8.0.
В обоих основных suite получено 4 passed / 1 failed / 0 blocked / 0 skipped;
единственный failed — запланированная прикладная регрессия. Два отдельных
контроля неправильной подписи первого открытия и reopen дали ожидаемые failed.

Девять запусков с изменением файлов дали failed/failed/passed у каждого
интерфейса: правка fixture — одно расхождение /comment_ok, reader с {} —
восемь missing_field, восстановление — passed. SHA-256 того же профиля
не изменился. Исходные fixture.1s/reader.1s восстановлены. Все 46 снимков
23 файловых запусков совпали с метаданными, эффективными параметрами и
телами в фактически запущенных контроллерах ERT; три встроенных запуска
не создают fixture-inputs. Все 26 запусков открыли и переоткрыли документ
напрямую с динамической подписью «Печать», без артефактов журнала.

Источник, реестр и исходный список процессов сохранены, копии очищены,
принудительное завершение не понадобилось. Оба MCP завершились штатно.
Исходный список чужих сеансов был пуст: эта серия не подтверждает совместную
работу с активным чужим сеансом. Проверка ограничена прежним стендом
Windows / 7.70.027 / квалифицированные DLL / DBF.
