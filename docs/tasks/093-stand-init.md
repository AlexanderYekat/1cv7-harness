# Задача 093. Создание профиля стенда

Продолжение [092](092-installed-native-runtime.md). Реализована и проверена
12 ноября 2026 года.

Задача принята владельцем 12 ноября 2026 года.

## Команда

В harness77 0.3.0 добавлена команда:

```powershell
harness77 stand-init --output stand.toml --name local-7.70.027 --runtime headless `
  --exe 'C:/Program Files (x86)/1Cv77/BIN/1cv7l.exe' `
  --cdb 'C:/Program Files (x86)/Windows Kits/10/Debuggers/x86/cdb.exe' `
  --helper C:/stand/com_cleanup77.dll --identity C:/stand/proxy_identity77.dll `
  --base C:/stand/base-for-test --copy-path C:/stand/harness77-copy --user ВВВ `
  --copy-exclude ExtForms --copy-exclude actofsverok --copy-exclude temp --format json
```

Все пути выбираются явно. Относительные входы и output разрешаются от CWD;
в TOML сохраняются абсолютные пути. Режим выбирается явно: headless или forms.
Команда не принимает пароль; используется ранее разрешённый пустой пароль
для указанного пользователя, как в существующем контракте запуска.

В профиле записываются runtime, версия платформы, пути, база/путь копии,
пользователь, выбранные исключения копирования и SHA-256. В pinned входят
exe/MD/DD/1CPP/FormEx, в tool_hashes — CDB/helper/identity. Сроки задаёт проект
или последующий CLI запуска. Параметр copy-exclude повторяемый, по умолчанию
исключений нет; допустимы имена подкаталогов верхнего уровня, не файлов.

## Проверки и запись

Штатный runtime квалифицирован для Windows и 1С 7.70.027 на принятом стенде.
Stand-init проверяет его манифест, затем читает только литеральные PINNED и
IDENTITY_SHA из проверенных источников runtime через AST. Код модулей не
импортируется и не исполняется; дублируемой таблицы квалификации в команде нет.
Платформа, MD/DD и DLL должны совпасть с этой политикой. Это начальный охват
на известной базе; произвольная другая конфигурация автоматически не одобряется.
CDB проверяется как PE x86, его фактический SHA-256 фиксируется в профиле.
Для exe и DLL также проверяется PE x86. Таблицы пользователей/журнала должны
быть доступны для чтения. Источник остаётся неизменным.

Путь копии должен быть зарегистрирован в списке баз 1С, родитель — существовать.
Команда читает регистрацию и отказывает при существующей копии, ссылке или
замке; существующий idle guard сохраняется. База и копия не пересекаются,
профиль нельзя создавать внутри них. Регистрация баз и COM не меняется;
сеанс, копия и замок не создаются. Готовность всего сценария отдельно
проверяет doctor с проектом.

Output должен быть новым файлом в существующем каталоге. Существующие
файлы, каталоги и ссылки не заменяются. Используются те же примитивы,
что у команд артефактов: временный файл в целевом каталоге, fsync,
перечитывание, проверка TOML и публикация hard link без перезаписи.
Перед публикацией повторно проверяются runtime, регистрация/состояние
пути копии и SHA-256 входов. Временный файл удаляется в finally.
При отсутствии поддержки hard link команда отказывает без fallback-копирования.

Успех: created/0, путь/размер/SHA-256 профиля и сведения runtime.
Отказ: blocked/2 с причиной. JSON явно содержит platform_checked=false
и launch_performed=false. Текстовый режим сообщает созданный путь или причину.
Ошибка аргументов — обычный argparse exit 2. Команда не вызывает doctor или
run автоматически; цепочка выполняется пользователем явно:

```powershell
harness77 doctor --project project.toml --stand stand.toml --format json
harness77 run --project project.toml --stand stand.toml --output-root C:/runs/check
```

Штатный запуск по-прежнему требует configuration.modules проекта и
зарегистрированную копию; пустой каталог modules допустим.

## Проверка

13 новых тестов проверяют TOML с кириллицей/кавычками, абсолютные пути,
SHA-256, отсутствие запуска и изменений входов, существующий файл/каталог,
несовместимый PE/hash, неизвестную базу, регистрацию/занятость копии,
пересечения, отказ публикации и гонку перезаписи, изменение входов/runtime,
отказ доступа к реестру и статическое чтение политики без её исполнения.

```powershell
python -B -m unittest discover -s tests -p test_stand_init77.py -v
python -B scripts/verify_package77.py --output .artifacts/s93-package --command-timeout-s 600
```
