## Что реализовано

- **`.github/workflows/ci.yml`** — запуск при push в любую ветку, при pull request и вручную:
  - `windows` — `windows-2025`, Python 3.11, 3.13, 3.15: установка по
    [development.md](../development.md), тесты продукта, наборы исследования `platform77`,
    `forms`, `kudir`;
  - `package` — `windows-2025`, Python 3.13: `scripts/verify_package77.py`, свидетельства —
    артефакт `package77` (14 дней), и при отказе тоже;
  - `linux` — `ubuntu-24.04`, Python 3.13: тесты продукта.
  Токен только на чтение, действия закреплены SHA коммита (`checkout` v7.0.1, `setup-python`
  v7.0.0, `upload-artifact` v7.0.2), секретов нет, `pull_request`, а не `pull_request_target`,
  сроки 30–40 минут, новый push отменяет устаревший запуск той же ветки.
- **`scripts/ci_summary77.py`** — сводка задания: итог, каждый пропущенный тест с причиной,
  каждый упавший тест; журнал в кодовой странице Windows тоже читается.
- **Исследование без `1cv77-devtools`.** `ert_probe77.py`, `build_formex_fixture.py` и
  `reference77.py` берут `ert_module` и `compiler_protocol77` из `src/harness77` (тот же код).
- **Тесты.** Временные корни `test_config77`, `test_form77`, `test_mcp77` — в полном виде
  (`resolve()`); `test_session77` — управляемые часы вместо настоящих; 11 тестов контракта
  нативного launcher помечены `windows_only` (`tests/stage4_fixtures.py`). Код продукта
  (`src/harness77`) не менялся.
- **Документы.** [testing.md](../testing.md) — раздел CI: что проверяется, что нет и как
  повторить локально; дорожная карта.

## Границы

- Настоящая 1С 7.7 в CI не запускается; нативная приёмка — на стенде владельца.
- На Linux проверяются статический анализ, протокол, ERT, формы, MCP и симуляционный `run`;
  контракт нативного launcher — только на Windows.
- После приёмки, по слову владельца (`b383f29`): Dependabot раз в месяц предлагает одним
  pull request обновление закреплённых действий (первая проверка — без предложений: версии
  последние); ветки Dependabot проверяются один раз, через pull request; итоговое задание
  `ci` — единственная проверка для защиты `master`. Запуск на `b383f29` — шесть заданий зелёные.
- Защиту `master` (обязательная проверка `ci`, без force-push и удаления, администратор может
  отправлять напрямую) исполнитель включить не смог: вызов API запретил классификатор
  разрешений Claude Code. Команда для владельца — в [передаче](../handoffs/2026-10-21-ci.md).
- `research/76av/inspect_76av.py` по-прежнему берёт `ert_module` из `1cv77-devtools`:
  76.АВ не кандидат, тестов у этого скрипта нет.
