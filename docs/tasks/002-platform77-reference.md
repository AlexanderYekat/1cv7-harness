## Повторение подготовки

Из корня проекта, выбирая **новый** каталог `--output`:

```powershell
python -X utf8 -B research/platform77/reference77.py prepare --ok .artifacts/platform77/syntax-recovery-p08-streams-20261012/cycle-01/success-before --syntax .artifacts/platform77/syntax-recovery-p08-streams-20261012/cycle-01/syntax --unused-syntax .artifacts/platform77/concurrent-ert-unused-syntax-01-20261012 --unused-name .artifacts/platform77/concurrent-ert-unused-name-01-20261012 --output .artifacts/platform77/configurator-reference-next
python -X utf8 -B research/platform77/reference77.py verify .artifacts/platform77/configurator-reference-next
```

`prepare` возвращает `awaiting_reference`, `verify` —
`package_integrity: passed`, `reference_acceptance: not_assessed`.
CLI 0 здесь означает только успешную подготовку/проверку файлов.
Ни одна команда не запускает 1С, не проверяет модуль Конфигуратором и не
присваивает положительную ручную приёмку. Ошибка входных свидетельств — CLI 2.
Существующий каталог не перезаписывается.

На текущей Windows файловая песочница возвращает WinError 5 при разрешении
некоторых путей `.artifacts`. Те же команды вне песочницы прошли. Это
ограничение доступа контроллера, а не ошибка ERT или повод менять права базы.

## Выполненный контроль

В окне запуска выбраны режим «Конфигуратор» и существующая запись
`harness77 — base-for-test`; показан точный путь
`C:\MyProjects\harness77\.local\bases\base-for-test\`.
Текстовое свидетельство выбора сохранено в `base-selection.json`.
Вход под «ВВВ» завершён пользователем. Для каждой ERT выполнено:

1. «Файл → Открыть», полный путь подготовленной копии; путь проверен в заголовке.
2. Вкладка «Модуль», «Действия → Синтаксический контроль».
3. Сохранён снимок с именем файла и полным результатом в окне сообщений.
4. Для ошибки: фокус окна сообщений, Ctrl+Home, Ctrl+Shift+End, Ctrl+C;
   Ctrl+N → «Текст», вставка целого протокола, сохранение в одноимённый `.txt`.
   Ctrl+A в этом редакторе не выделяет весь текст. Исходные байты CP1251
   оставлены без исправлений; сохранён завершающий маркер платформы.

Результаты:

- `01-ok.ert`: явное «Синтаксических ошибок не обнаружено!» (`01-ok.png`).
  Исполнение функции в Конфигураторе не проводилось; значение 42 относится
  к отдельно подтверждённому автоматическому `execute`.
- `02-syntax.ert`: «Ошибка в выражении», строка 2.
- `03-unused-syntax.ert`: «Ожидается выражение», строка 6.
- `04-unused-name.ert`: «Процедура не обнаружена (Harness77UndefinedProcedure)»,
  строка 6. Открытие файла для редактирования допустимо; проверка его модуля
  обнаруживает дефект. В автоматических `check`/`execute` загрузка отвергается
  до вызова исправной функции.

У отрицательных случаев по одной диагностике, без нераспознанных строк.
Каждый `.txt` импортирован неизменённым `compiler_protocol77.py --encoding cp1251`
в отдельный `*-import.json`: статус `failed`, CLI 1. Пустой протокол успехом
не объявлялся. Копирование из окна сообщений добавляет отступ исходной строки;
колонки импорта описывают сохранённый текст и не считаются колонками модуля.
Сопоставляются статусы, номера строк и точные сообщения; пути сверяются с
выбранной копией. Байты полных протоколов двух разных каналов не обязаны совпадать.

Ранее черновик ошибочно называл сообщение P02 «Ожидается выражение».
Перечитывание исходного `check.txt` и `execute.txt` подтвердило «Ошибка в выражении»
в обоих. Исправлено описание; исходные протоколы и ожидания не менялись.

`observations.json` содержит явные наблюдения, выбранные пути и хеши снимков/
текстов; `reference-comparison.json` — повторяемое сопоставление. Подготовительный
`reference-manifest.json` намеренно сохраняет исходный `awaiting_reference`.
Его поле не переписывает историю и не служит итогом выполненной проверки.

```powershell
python -X utf8 -B research/platform77/reference77.py verify .artifacts/platform77/configurator-reference-20261012
python -X utf8 -B research/platform77/reference77.py compare .artifacts/platform77/configurator-reference-20261012
```

`compare` заново проверяет доноров и копии, требует явного положительного
наблюдения P01 и полных отрицательных протоколов, сверяет их хеши/пути.
Результат здесь — `comparison: matched`, CLI 0; содержательное несовпадение
даёт CLI 1, непригодное свидетельство — CLI 2. Изображения проверяются по хешу,
их содержание засвидетельствовано оператором, а не распознано скриптом.
Команда не заменяет проверку базы и завершения всего эксперимента.

После контроля повторный `verify` прошёл. `stand-before.json` и `stand-after.json`
подтвердили прежние EXE, MD/DD, FormEx и 1С++. Изменения ERT/конфигурации
не сохранялись. Собственный Конфигуратор закрыт Alt+F4: удерживаемый дескриптор
PID 26020 подтвердил exit code 0, принудительная остановка не применялась,
после выхода процессов 1С нет (`close-owner.json`, `close.json`). Отладчик к
этому GUI-сеансу не подключался, отсутствие исключений первого шанса здесь
не заявляется. `reference-receipt.json` закрепляет хеши всех свидетельств.

Автоматический `check` открывает ERT загрузчиком Предприятия, а штатная
проверка Конфигуратора — отдельный способ. Совпадение на этих четырёх случаях
подтвердило только заявленный охват модуля ERT и невызванных процедур.
Выражения и обработчики формы, глобальный модуль, другие модули MD и прикладные
обработки этим сравнением не проверяются.
