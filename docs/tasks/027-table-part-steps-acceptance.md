# Проверка задачи 027: табличная часть в шагах

Дата: 26 октября 2026 года. [Задание](027-table-part-steps.md).
Исходная ревизия — `48527fa`, ветка `master`.
Статус: **принято** владельцем 27 октября 2026 года; разрешены коммит и отправка на GitHub.

## Результат

Сценарий шагов работает с табличной частью формы документа так же, как пользователь с клавиатуры.
Добавляются новые шаги:

| Шаг | Что делает | Когда проходит |
|---|---|---|
| `{ add_row = true }` | Insert в окне табличной части | строк стало на одну больше |
| `{ row = <номер> }` | курсор на строку клавишами Down/Up | текущей стала нужная строка |
| `{ cell = "<колонка>", text = "…" }` | ячейка в режиме редактирования, замена текста, Enter; исполняется формула колонки | редактор открылся, принял текст и закрылся |
| `{ delete_row = true }` | Delete в окне табличной части | строк стало на одну меньше |
| `{ rows = <число> }` | число строк | совпало |
| `{ total = "<колонка>", text = "…" }` | итог колонки | совпал |
| `row = <номер>` у `value` | реквизит строки, курсор не двигается | совпал |
| `{ key = "<клавиша>" }` | клавиша в табличной части или списке | сообщение дошло |

В форме списка справочника или журнала из новых шагов доступен только `key`, а `value` читает реквизит
текущего элемента. Колонка называется идентификатором или заголовком из раздела `Browser`. Текст вводится
только в колонку строкового, числового или датового реквизита. Ссылочная или неизвестная колонка, шаг
табличной части на форме без неё, на форме списка или ERT — отказ до запуска 1С. `add_row`, `cell`,
`delete_row` и `key` — действия: за ними идут шаги `dialog` задачи 026. Новых команд CLI и инструментов
MCP нет, продукт (`src/`) не менялся.

## Как это устроено

- Перед действием и после него клиент вызывает 1С. Контроллер сообщает число строк, номер текущей
  строки и текущую колонку (`КоличествоСтрок()`, `НомерСтроки`, `Форма.ТекущаяКолонка()`). Для `cell`
  тот же вызов делает колонку текущей и открывает её редактор: метод формы `Активизировать(<колонка>, 1)`,
  который по помощнику синтаксиса можно вызывать из внешнего модуля.
- Клавиши — `WM_KEYDOWN`/`WM_KEYUP` через очередь сообщений окну табличной части (`browse`, ID 4151)
  или редактора ячейки. Это сообщения проверенному окну, а не системный ввод. Процесс перепроверяется
  перед каждым сообщением. Модальное окно, которое открыла клавиша, обслуживает следующий вызов 1С,
  и цепочка задачи 026 его находит.
- Редактор ячейки — дочернее окно табличной части с ID `4152 + B + j` (это те ID, которые задача 022
  пропускала). Текст заменяется, как в поле формы 025: выделение и символы `WM_CHAR`, затем Enter.
- Пока 1С принимает ввод новой строки, после Enter она открывает редактор следующей колонки. `add_row`,
  `delete_row` и `row` сначала заканчивают такой ввод клавишей Enter, не больше числа колонок. Escape
  для этого не годится: он отменяет всю новую строку.
- Ввод идёт в текущую строку окна табличной части. Текущей строкой документа 1С её делает при обновлении
  на простое, а MFC шлёт это обновление только видимому главному окну. Поэтому, пока идут шаги формы
  с табличной частью или списком, главное окно 1С показано без активации на своём рабочем столе
  (как для снимков задачи 010) и скрывается после шагов. `row` нажимает Down или Up по одному разу,
  после каждого нажатия вызывает 1С и проверяет `НомерСтроки`.

## Нативные случаи

Стенд — 7.70.027, `base-for-test`, профиль задачи 021. Каждый случай — один `harness77 run` на своей
копии базы. Основная форма — новый документ «Готовая продукция». Для наблюдения в его модуль
добавлены `ПриВводеСтроки` и `ПриУдаленииСтроки` с сообщением, а в начало `Пересчет` — сообщение
с текущей колонкой, предупреждение при количестве больше 100 и деление на ноль при 13. Неизменённая форма
открывала документ, записанный `fixture_setup`; список — форма списка «Банки» `Основная`. Ожидания
записывались в задание до каждой серии. Итоговая серия 2 выполнена на окончательном коде (хеши — в сводке).

- Строки и ячейки: `r-add` («ввод строки», строка 1), `r-cell` (количество 3, стоимость 10, формула —
  «Сумма» 30, итог 30), `r-rows` (две строки, курсор на первую, количество второй читается без сдвига
  курсора, итог 3), `r-delete` (удалена первая из двух, `ПриУдаленииСтроки`, осталась строка
  с количеством 2), `r-delete-new` (удаление строки, ввод которой не закончен), `r-keys` (Up и Down
  в табличной части).
- Окна и ошибки формулы: `r-dialog` (предупреждение формулы колонки, шаг `dialog` отвечает),
  `r-error` (провал шага 2 со строкой деления на ноль).
- Неизменённая форма: `r-existing` (собственный `Пересчет` формы, «Сумма» 30), `r-row-existing`
  (вторая строка: ввод «7» в неё, «Сумма» 70, итог 80), `r-save` (количество 3, «Записать», «Закрыть»;
  `fixture_verify` читает документ заново — «1|3|30»).
- Список: `r-list` (Down и Up меняют текущий элемент, `value` читает его наименование), `r-list-delete`
  (Delete — вопрос «Объект будет помечен на удаление !», ответ «Нет», элемент прежний).
- Провал шага, сценарий остановлен на нём: `r-wrong-rows`, `r-no-row` («1C refused: no row 3 of 0»),
  `r-wrong-total`, `r-unexpected` (предупреждение без шага `dialog`, окно закрыто «OK»).
- Отказ до запуска 1С, `blocked`: `r-reference` (ссылочная колонка «Товар»), `r-list-add` (`add_row`
  в списке), `r-unknown-column`, `r-ert` (шаг табличной части на форме ERT).

Все 21 случай серии 2 совпали с ожиданиями с первого прогона. [Пример](../../examples/table-part/README.md)
на неизменённой форме прошёл трижды: `3120f0a7-b80c-4418-b15d-b8e202fee601`,
`2f5e5013-3deb-4093-ac37-3252fb6675f4`, `7a53599b-a4c0-44ec-9124-6e79e517b107` — `passed`, код 0.
Его отрицательный вариант (ожидаемая сумма 20, `fb771e76-602b-4b3f-9e0e-25aa4adc0495`) — `failed`,
код 1, причина «step 4 (value 'Сумма'): is '30', expected '20'». Ещё два запуска примера
(`cb5a853f-5b5d-4784-9823-efb9fd6d8af6`, `ac70efc4-90e8-4424-904e-9ce08e24e7f1`) получили `blocked`
(`open_timeout`). 1С не дошла до регистрации своего OLE-объекта за 120 с, в замечаниях —
«CDB readiness deadline» и «foreign proxy identity». В это время на машине работали задания Codex
проекта КУДиР, первый из отказов — ещё и во время моей параллельной проверки поставки. Принудительная
очистка подтверждена, чужие процессы сохранены, копии удалены, источник не изменился. Повторы
без изменений прошли. Регрессия на окончательном коде: пример 026 (`7b96085b`), пример 025 (`1b1f03e8`),
`f-elements` 022 (`actions`, `48a61b9d`) — прежние результаты. После каждой серии база стенда и список
баз 1С прежние; копии удалены, свои сеансы завершены.

## Как шла проверка

- Серия 0 (9 прогонов): Insert, отправленный окну табличной части через очередь (и напрямую),
  добавляет строку и вызывает `ПриВводеСтроки`; `НомерСтроки` в ней ещё прежний (0). Ввод в ячейку
  через `Активизировать` + текст + Enter работает, формула исполняется; в списке Down и Up двигают
  текущий элемент. Второй `add_row` провалился: перед Insert был открыт редактор следующей колонки,
  а Escape в нём отменил всю новую строку.
- Серия 0b (9): Enter, пока открыт редактор, заканчивает ввод строки; Insert прямо в редактор, команда
  меню «Новая строка» и перевод фокуса на шапку при открытом редакторе ничего не делают;
  `Активизировать(<колонка>, 0)` на пустой таблице сам начинает новую строку. Delete и команда
  «Удалить строку» удаляют текущую строку. Решение: Enter до закрытия редактора, клавиши через очередь.
  Варианты исследования из кода убраны.
- Серия 1 (20): 17 совпали. `row = 1` (`АктивизироватьСтроку`) не сдвинул строку, Up в табличной
  части не изменил `НомерСтроки`.
- Серии 1b–1d (12): `АктивизироватьСтроку` и `ПолучитьСтрокуПоНомеру`, вызванные из контроллера, строку
  ввода не двигают. После Down при скрытом главном окне курсор окна стоял на второй строке, а «7» записалось
  в первую — в текущую строку документа.
- Серия 1e (5): с показанным главным окном Down и Up сразу меняют `НомерСтроки`, и ввод идёт в строку
  курсора. Главное окно стало показываться на время шагов, `row` — клавишами.
- Серия 2 (21): все совпали.

## Что установлено

- Окно табличной части документа и списка — `browse` с ID 4151, дочернее окно диалога формы.
  Редактор ячейки существует, пока ячейка редактируется: `1CEDIT` с вложенным `1CEDITSPR` или
  `BMASKED`, ID `4152 + B + j`; фокус — во вложенном окне. «Количество» показывает « 0.000»,
  «Стоимость» — « 0.00».
- После Insert 1С сразу открывает редактор первой колонки («Товар»), после Enter в ячейке новой строки —
  редактор следующей, Enter на последней редактируемой колонке закрывает редактор. В существующей
  строке Enter только заканчивает ввод.
- `ПриВводеСтроки` вызывается до того, как новая строка стала текущей; `ПриУдаленииСтроки` видит номер
  удаляемой строки.
- Меню «Действия» формы документа: «Новая строка» (32786), «Вставить строку» (24649), «Изменить» (32784),
  «Копировать строку» (32790), «Удалить строку» (32785), «Переместить вверх/вниз» (33790/33791).
  У формы списка справочника — «Новый» 32786 и «Удалить» 32785. Команда меню делает то же, что клавиша.
- Delete в списке справочника спрашивает «Объект будет помечен на удаление !» (`#32770`, «&Да»/«&Нет»).

## Ограничения

Проверено на одной форме документа («Готовая продукция»), её неизменённом модуле и списке «Банки»
закреплённого стенда; журналы шагом `key` нативно не проверялись. Текст вводится только в колонки
строкового, числового и датового типа: выбор ссылочного значения (F4, форма выбора), подбор и формы,
открытые из табличной части, не поддержаны. Перетаскивание строк, перемещение строк вверх и вниз,
копирование строки (F9) отдельными шагами не проверялись, хотя `key` их клавиши отправит.
Табличная часть ERT и многострочная часть операции и проводок не проверялись. `row` двигает курсор
клавишами по одной строке за вызов 1С: длинная таблица — столько же вызовов. На время шагов такой
формы главное окно 1С показано на рабочем столе harness77 (рабочий стол пользователя не затрагивается).
