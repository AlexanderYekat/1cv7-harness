# Задача 075. Сверка итоговых файлов suite в MCP

Задача принята владельцем 10 ноября 2026 года.

Для результата `suite` с кодом 0 или 1 MCP проверяет файлы после
выхода CLI. Сервер определяет каталог по корню результатов запроса
и идентификатору набора. Сводка stdout должна совпасть с полями
`suite.json`, а SHA-256 и размер `junit.xml` — со сведениями в
сводке. При расхождении или отсутствии файла MCP возвращает
`isError=true` и конкретную причину, сохраняя код и потоки CLI.

## Нативная проверка

Три запроса к одному MCP-серверу запускают на реальной 1С 7.7.027
сценарий, который ожидает 43 и получает 42. Корень результатов
передан относительно рабочего каталога сервера. Все три CLI
записывают итоговые JSON и JUnit и завершаются с кодом 1.
Для двух запросов пробный процесс после записи отчётов, перед
выходом, меняет JUnit без изменения размера либо удаляет его.

## Результаты

- С целыми `suite.json` и `junit.xml` MCP вернул код 1 и
  `isError=false`. В JUnit один `failure`.
- Изменённый JUnit сохранил размер, но его SHA-256 отличался.
  MCP сохранил код 1 и сводку, вернул `isError=true` и сообщил
  о несовпадении SHA-256.
- При удалённом JUnit MCP сохранил код 1 и сводку, вернул
  `isError=true` и сообщил «junit.xml отсутствует».

Во всех трёх случаях `suite.json` содержал завершённый набор.
Дочерние отчёты подтвердили один `Initialize` и значение 42
в каждом запуске. Копия, замки и временная регистрация удалены,
опись источника и снимки COM-регистраций и процессов совпали
с исходными. Прошли 50 автоматических тестов MCP и suite, включая
проверки отсутствующего и изменённого `suite.json` и чужого пути.

Сводка — `.artifacts/s75-native/verified.json`. Локальная проба
запускается командой `python -B .local/s75-verify.py <новый-суффикс>`.
