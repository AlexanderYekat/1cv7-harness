# Задача 087. Авария запроса за владельцем восстановленной копии

Нативная проверка выполнена 12 ноября 2026 года.

Задача принята владельцем 12 ноября 2026 года.

Проба продолжает [задачу 086](086-native-suite-recovery-close-waiter.md).
После аварии suite первый повтор восстанавливает копию и удерживается
после `Initialize` и `check`. Второй запрос ждёт тот же `copy_path`.
Проба завершает его MCP и дочерний Python CLI через сохранённые
дескрипторы, проверив образы, время создания и родительские PID.
Владелец должен сохранить копию и завершиться, а следующий запрос —
получить свежую копию на том же пути.

## Воспроизведение

На существующем локальном стенде 1С 7.7.027, из корня репозитория:

```powershell
python -B research/mcp/verify_suite_recovery77.py --stand .local/stage21-native/stand.toml --project .local/stage21-native/s3/cases/m-same/project.toml --output .artifacts/s87-native-full --retries 2 --crash-waiter
```

Каждый повтор команды требует нового каталога `--output`.

## Результат

- Владелец дождался выхода прежних процессов за 10,663 с, заменил копию
  и снял обе старые COM-регистрации.
- Второй запрос дважды сообщил об ожидании пути. Его MCP и CLI
  завершены с кодом `0x8200` каждый. У прерванного запроса нет
  итогового `run.json`, ответа MCP, нативного каталога и вызова
  `Initialize`. Отмена через MCP и создание cancel-файла не выполнялись.
- После завершения обоих процессов копия, замок, обе регистрации
  и процессы владельца совпали со снимком перед ожиданием.
  Владелец продолжил работу и вернул `42` после одного `Initialize`.
- Новый MCP-запрос получил тот же путь без ожидания, создал свежую
  копию и вернул `42` после одного `Initialize`. Старые регистрации
  повторно не снимались.

Первый результат прерванного suite, `suite.json` и JUnit сохранились.
Копия, замок и защита замка удалены. Опись исходной базы, список баз,
COM-регистрации и процессы 1С совпали со снимками до прогона.
Локальный протокол — `.artifacts/s87-native-full/verified.json`.

Предварительный прогон `.artifacts/s87-native` остановился до аварийного
завершения: проверка требовала единственного дочернего процесса MCP.
Отбор уточнён до Python CLI с последующей проверкой полного пути образа
и идентичности процесса. После отказа проба штатно отменила запросы
и восстановила стенд; в её `verified.json` все проверки `cleanup` успешны.

Регрессия MCP: `python -B -m unittest discover -s tests -p test_mcp77.py -v`
— 28 тестов, `OK`. Локальный журнал —
`.artifacts/mcp-regression-085-087.log`.

Нативная регрессия [084](084-native-suite-recovery-cancel-waiter.md)
на итоговом скрипте с `--retries 2 --cancel-waiter` также прошла:
отменённый запрос не запускал 1С и не получил ответ MCP, владелец
и следующий запрос вернули `42` после одного `Initialize` каждый,
все проверки очистки успешны. Протокол —
`.artifacts/s84-regression-085-087/verified.json`.
