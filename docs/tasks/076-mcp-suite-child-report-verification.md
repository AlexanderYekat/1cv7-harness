# Задача 076. Сверка дочерних run.json в MCP

Задача принята владельцем 10 ноября 2026 года.

Для результата `suite` с кодом 0 или 1 MCP после сверки `suite.json`
и JUnit проверяет дочерний отчёт каждого сценария. Путь строится
по `run_id` в каталоге `runs` под корнем результатов запроса.
Сервер сверяет ссылку, размер и SHA-256 с записью в `suite.json`,
затем проверяет идентификатор, статус и код в прочитанном отчёте.
При расхождении MCP возвращает `isError=true` с именем сценария
и причиной. Код выхода и потоки CLI сохраняются.

## Нативная проверка

Три запроса `suite` запускают через один MCP-сервер реальную 1С
7.7.027. Сценарий «Контроль» во всех случаях ожидает 43 и получает 42,
поэтому CLI штатно завершает каждый набор с кодом 1. Для двух запросов
пробный процесс после записи итоговых отчётов, перед выходом, подменяет
`run.json` отчётом другого нативного запуска или удаляет его.

## Результаты

- При целых отчётах MCP вернул код 1 с `isError=false`.
- При подмене отчётом другого прогона MCP сохранил код 1 и вернул
  `isError=true` с причиной «сценарий „Контроль“: SHA-256 run.json
  не совпадает с suite.json».
- При удалении дочернего отчёта MCP сохранил код 1 и вернул
  `isError=true` с причиной «сценарий „Контроль“: run.json отсутствует».

Во всех случаях `suite.json` совпал со сводкой, а JUnit сохранил
исходный SHA-256 и ссылку на дочерний отчёт. Каждый нативный запуск
вызвал `Initialize` один раз. Копия, замки и временная регистрация
удалены. Опись источника и снимки COM-регистраций и процессов
совпали с исходными.

Прошёл 51 автоматический тест MCP и suite. Тесты также проверили
чужой `run_id` при совпадающем хеше и ссылку на другой отчёт.
Сводка — `.artifacts/s76-native/verified.json`. Локальная проба
запускается командой `python -B .local/s76-verify.py <новый-суффикс>`.
