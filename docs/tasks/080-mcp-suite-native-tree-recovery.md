# Задача 080. Восстановление после падения suite при запуске 1С

Задача принята владельцем 10 ноября 2026 года.

Набор из трёх сценариев запускается через MCP на 1С 7.7.027
на временной копии базы. Первый сценарий проходит штатно.
Второй запускает CDB, 1С и OLE-клиент. Launcher подтверждает
собственный прокси и приостанавливается перед выдачей разрешения
на `Initialize`.

В этой точке проба сверяет метку копии, замок, записи владельца
обеих COM-регистраций, родство процессов и пути исполняемых файлов.
Она помещает проверенное дерево MCP в отдельный Windows Job Object
и подтверждает выход процессов по удержанным дескрипторам.
Новый MCP-сервер повторяет запуск с тем же `copy_path`.

## Результаты

- Проба завершила сервер MCP, CLI набора, launcher, CDB, 1С,
  OLE-клиент и четыре системных `conhost.exe`. У второго сценария
  подтверждён собственный OLE-прокси, вызовов `Initialize` было ноль.
- Первый сценарий вызвал `Initialize` один раз и вернул 42.
  Его `run.json`, промежуточные `suite.json` и JUnit сохранили
  SHA-256. У набора осталось `complete=false`, у второго сценария
  остался `run_id` без итогового отчёта, третий остался `skipped`.
- После завершения дерева копия, замок и обе COM-регистрации
  сохранили данные владельца. Новый запрос распознал оставленный
  замок и заменил копию на том же пути. Launcher подтвердил выход
  всех четырёх процессов из записей владельца, снял обе регистрации,
  вызвал `Initialize` один раз и вернул 42.

Временная копия, замок и файл защиты удалены. Опись источника,
список баз, COM-регистрации и процессы 1С совпали со снимками
до прогона.

Сводка — `.artifacts/s80-native/verified.json`. Локальная проба
запускается командой `python -B .local/s80-verify.py <новый-суффикс>`.
