# Техническая проверка 045: ошибка доступа при обмене шагами

Итог `.artifacts/stage45-acceptance-final.json` — passed, issues пусты.
Задача принята владельцем 8 ноября 2026 года в указанном охвате.
Основание приёмки — поручение «принимай и коммить».
[Задание](045-step-exchange.md).

## Что установлено

Обмен имеет два направления: Python публикует `form-step-request` через
`Path.replace`, VBScript читает запрос и вызывает контроллер; VBScript
публикует UTF-16 ответ через `FSO.MoveFile`, Python читает `form-step-N-done`.
Прежний код считал видимость имени достаточным условием успешного открытия.
Отказы доступа на обоих чтениях не обрабатывались как временное состояние.

Воспроизведены две неисправности:

1. В копии старого протокола с проверками Err после файловых операций,
   без 1С, на 2989-м запросе `FSO.OpenTextFile(form-step-request, 1)` вернул
   `70: Разрешение отклонено`. Первые 2988 вызовов завершились; новый запрос
   остался на диске, контроллер для него не вызывался. Свидетельства:
   `.artifacts/stage45-exchange-stress2/summary.json`, `client.vbs`,
   `ert-events.jsonl`, запрос `probe45:-113988`. Предварительные 1000 обменов
   прошли; это не считалось доказательством отсутствия гонки.
2. После исправления стороны VBScript обнаружена симметричная ошибка Python:
   `PermissionError: [Errno 13]` при чтении уже видимого
   `form-step--112513-done`. Контроллер успел выполнить 1514 вызовов;
   файл содержит правильный `value:-112513`. Артефакты —
   `.artifacts/stage45-fixed-stress5000`. Та же ошибка воспроизвелась в
   нативном продолжении 044 на `form-step-9-done` после кнопки «Записать»:
   `8581f7c2-da75-4ad8-97c6-54db55ddc0b8` в `stage45-failure044`.

Отдельная проба конкурирующих `Path.replace` и `FSO.OpenTextFile` без 1С
дала 30 ошибок открытия 70 на 3254 чтения; у публикующей стороны тоже были
отказы переименования. Файлы и учётная запись не менялись. Отчёт:
`.artifacts/stage45-rename-race/summary.json`, сырой `observations.txt`.
Эта нагрузочная проба намеренно перезаписывает один файл без подтверждения
и подтверждает механизм конкуренции, а не корректность штатного протокола.

Ошибка 70 совместима с блокировкой файла, а не только с постоянным запретом
доступа. Windows учитывает совместимость режимов уже открытых дескрипторов.
Это соответствует [описанию ошибки 70 Microsoft](https://learn.microsoft.com/en-us/office/vba/language/reference/user-interface-help/permission-denied-error-70)
и [правилам CreateFileW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew).

## Что можно сказать о первоначальном отказе 044

У трёх прежних отказов 042–044 остался следующий запрос, но отсутствуют его
ответ, временный ответ и протокол. В 044 это
`3b5f2d54-149a-4614-85ea-2dc550eb9df2`, запрос `-111900` после `-111003`.
След сужает место до чтения/закрытия/удаления запроса и совпадает с новым
воспроизведением `request-open`. Однако старый лог не записывал точную
операцию: утверждать, что именно тот исторический отказ был в OpenTextFile,
или называть конкретный блокирующий процесс/драйвер, нельзя.

Доказан дефект устойчивости файлового протокола: временный отказ открытия
видимого файла обрывал сценарий. Поломка формы или прикладного кода 1С
не требуется для воспроизведения. Постоянные запреты доступа остаются
возможной отдельной причиной и должны завершаться явным отказом.

## Исправление

Код обмена вынесен в `research/forms/step_exchange77.py`.

- VBScript ограниченно повторяет только открытие и удаление собственного
  запроса при ошибке 70. Бюджет — 1 секунда, не более 26 попыток, пауза 40 мс.
  Проверка бюджета выполняется после операции; её собственное время входит
  в измерение. Чтение, закрытие и проверка идентичности предшествуют вызову.
- Python так же ограниченно повторяет только чтение готового ответа при
  `PermissionError`. Отсутствующий или повреждённый ответ не превращается
  в успех; эти ошибки не повторяются как ошибки доступа.
- Запрос не публикуется повторно, контроллер не вызывается повторно.
  Существующий ответ или временный ответ блокирует повтор шага до вызова.
  Создание/запись/публикация ответа после контроллера не повторяются.
- Ошибка содержит операцию, путь, исходные номер/source/description,
  run_id, известный номер шага, число попыток и время. Если запрос ещё не
  прочитан, номер шага в диагностике null. Фатальная ошибка сохраняется
  в событии `blocked/step-exchange` и, по возможности, в UTF-16
  `form-step-error.json`. Python возвращает проверенную диагностику в
  `exchange_error`; чужая/повреждённая диагностика отвергается.
- Каждый повтор доступа виден: `step-exchange-retry` в событиях VBScript,
  `exchange_retries` в ответе Python. Постоянный отказ остаётся ошибкой.

`controller_may_have_executed` относится только к служебному вызову
контроллера. Предыдущее UI-действие могло уже сработать даже при false.
По этому флагу нельзя повторять нажатие кнопки, запись или проведение.
При отказе после вызова флаг true: результат может быть неизвестен клиенту,
но исполнение не повторяется. Новых автоматических повторов сценария нет.

## Воспроизведение

```powershell
python -X utf8 -B research/forms/probe_step_exchange77.py --mode controlled --output .artifacts/exchange-controls-new
python -X utf8 -B research/forms/probe_step_exchange77.py --mode stress --count 5000 --output .artifacts/exchange-stress-new
python -X utf8 -B scripts/verify_step_exchange_controls77.py --controlled .artifacts/exchange-controls-new --output .artifacts/exchange-verifier-controls-new.json
python -X utf8 -B -m unittest discover -s research/forms/tests -v
```

Первые две команды требуют Windows и 32-битный cscript/FSO. Они работают
только с собственными файлами и подставным контроллером, без 1С и базы.
Выходные каталоги должны быть новыми. Нативная приёмка ограничена прежним
DBF/1С++ стендом; это не доказательство отсутствия всех файловых отказов.

Первая серия контролируемых проб оборвалась в сборщике результатов с NameError;
она не включена в положительную матрицу, полный набор повторён после исправления
исследовательского скрипта. Промежуточный стресс стороны Python и нативный
`stage45-failure044` также сохранены отдельно; положительные проверки выше
выполнены после исправления обеих сторон чтения.
