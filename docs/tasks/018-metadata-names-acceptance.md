# Приёмка задачи 018: имена объектов метаданных в коде модуля

Дата: 21 октября 2026 года. Задание — [018-metadata-names.md](018-metadata-names.md).
HEAD перед работой — `1bda176`, ветка `master`. Принята владельцем 21 октября 2026 года.

## Итог

`harness77 lint` 0.3.0 сверяет имена объектов конфигурации в коде с `1Cv7.MD` базы:
L7712 — `Константа`, `Перечисление` (вид и значение), `ВидыСубконто`, `ПланыСчетов`;
L7713 — строка «Тип.Вид» в аргументе двенадцати функций, принимающих имя типа или
описатель объекта. Оба правила — предупреждения (`--strict` — ошибки): 7.7 загружает модуль
с любым отсутствующим именем, а ошибка возникает только при исполнении строки или не возникает
вовсе — тогда тип молча теряет вид. Линтер совпал с 1С 7.70.027 на 42 из 42 проб;
пакетные пробы показали, что `1Cv7.MD` прочитан так же, как его видит 1С.

## Что реализовано

- `metadata77`: `Metadata.objects()` — имена по классам (`Consts`, `SbCnts`, `Documents`,
  `EnumList`, `Registers`, `ReportList`, `CalcVars`, `Journalisters`, `Buh` → `Plans`, `SbKind`),
  `enum_values()` — значения перечисления; читаются по запросу, запись другого вида или
  повтор имени — `ErtError`. Сборка формы (012–013) от новых разделов не зависит: прежние
  `names`/`numbers` и сообщения не изменились.
- `lint77` 0.3.0: L7712, L7713 (`check_metadata_names`); `--metadata 1Cv7.MD` для текста
  и ERT; модули `1Cv7.MD` — со своими метаданными (без потока метаданных — без проверки);
  отчёт — `metadata` и `metadata_context_modules`; в `LIMITATIONS` — граница правил.
  Сообщение называет базу (файл, конфигурация, хеш) и то, что сделает 1С по пробам.
- `run`: стадия `static` берёт `[build] metadata` проекта, иначе `1Cv7.MD` базы стенда;
  `static.metadata` — SHA-256, конфигурация, источник; нечитаемый `1Cv7.MD` — `blocked`.
- MCP `lint`: аргумент `metadata`.
- Исследование: `research/rules77/probe_metadata77.py`; приёмка —
  `scripts/verify_metadata_names77.py`; тесты — `tests/test_lint77_metadata.py` (23).
- Документы: задание, приёмка, контракт, README, README исследования, дорожная карта, передача.

Все срабатывания называют имена, которых нет в базе: `n-survey` показал, что разбор
совпадает с перечислением 1С. На модулях самой базы это ссылки на объекты, удалённые из
её конфигурации (значения `ВидыРасчетовСПокупателями`, `Справочник.Фирмы`, `СвоиЮрЛица`,
`Константа.РаздельныйУчетТоваровОптРозница`…): часть — под проверкой `Метаданные…Выбран()`,
остальные — ветки, которые на этой базе дали бы ошибку (`c-*`). В `ExtForms` больше всего
`Фирмы` и `СвоиЮрЛица` — переносимые формы проверяют их наличие. КУДиР обращается к трём видам
субконто (`Контрагенты`, `Договоры`, `ВидыРасчетовСПокупателями`) — все есть в базе.
Локальных переменных с именами глобальных атрибутов в корпусе нет.

## Границы

- Уровень — предупреждение: защищённый код (`Метаданные.Справочник("Х").Выбран()`) правило
  не распознаёт. С `--strict` или в модулях, рассчитанных на одну базу, — ошибка.
- Не проверяются: реквизиты (`Спр.Реквизит`), имена форм после вида, тексты запросов,
  `Метаданные.<Класс>("Имя")`, строки вне аргументов перечисленных функций (`Т = "Справочник.Х"`),
  английские имена глобальных атрибутов и типов, журналы расчётов, виды и группы расчётов,
  календари (в доступных базах этих разделов нет). `НазначитьТип`, `ВвестиЗначение`,
  `УстановитьРеквизитСправочника` нативно не проверялись — сообщение говорит об аналогии.
- Проверены одна база и один стенд; раздел `Registers` прочитан статически по базе
  «Торговля+Склад 9.2», нативно — только отсутствие регистров.
