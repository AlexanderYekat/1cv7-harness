# Задача 056. Закрытие списка типов после Enter

Задача принята владельцем 9 ноября 2026 года в указанном охвате.
Основание приёмки — поручение «Принимай задачу 056 и коммить».

В контрольной записи 054 из задачи 055 F4 открыл список типов и harness
прочитал четыре пункта. Следующая проверка владельца окна остановила
сценарий. Отчёт того запуска не разделял отправку нажатия и отпускания Enter.

Нативная проба `68afbe9e-5f29-4224-8cfb-fbfc0766c5a3` на свежей копии
разделила чтение списка, выбор пункта, проверку фокуса и обе половины Enter.
`LB_SETCURSEL` и `LB_GETCURSEL` вернули индекс 0, фокус подтвердился на
списке. После одного `WM_KEYDOWN` 1С уничтожила окно списка. При проверке
перед `WM_KEYUP` прежний HWND уже не имел владельца, и шаг отказал.

Для Enter в списке типов отпускание пропускается, если нажатие уже
отправлено и исчезновение HWND подтверждено. Проверки владельца при
нажатии и у живого окна сохраняются. Далее `choose` по-прежнему сверяет
новый справочник, его активный контекст, строку и точную ссылку товара.
В отчёте `keyup_skipped=window_closed` отмечает этот переход.
Если окно исчезает между проверкой владельца и `PostMessageW`, код 1400
также требует повторной проверки отсутствия HWND. [Коды Win32](https://learn.microsoft.com/windows/win32/debug/system-error-codes--1300-1699-)

Локальный `.local/s56-native-launcher.py` подключается через
`.local/s54d/stand-056.toml`. Режим `HARNESS77_PROBE56_MODE=keyup-race`
задерживает проверку перед отпусканием, чтобы 1С успела обработать
нажатие. Режим `foreign` подставляет отдельное тестовое окно launcher
на том же изолированном рабочем столе. Трасса `native/probe56.json`
содержит оба HWND, владельцев и счётчик вызовов `PostMessageW` для пробы.

## Результаты

- В повторе `61ae140b-816a-4030-be67-52e2b4ab5a2b` 1С снова уничтожила
  список после `WM_KEYDOWN`. Трасса подтвердила один F4, одно нажатие
  Enter в списке типов и пропуск отпускания для исчезнувшего HWND.
  Штатный справочник вернул точную ссылку во вторую строку. Все 86 шагов
  отмены прошли, после повторного открытия итог составил 110.
- В пробе `65d31719-1f18-4c6a-b35c-c134c3689191` подставленный HWND
  принадлежал процессу launcher. Проверка остановилась до первого
  вызова `PostMessageW` для этого окна. Независимое чтение подтвердило
  исходные данные, тестовое окно и копия базы удалены.
- Контрольный набор 054 `2a7f64b5-d8f2-450b-b820-bc8e1720f134` прошёл
  без вмешательства пробы. Запись `5a847af7-0fcd-4152-a4f2-6a3facad39d8`
  подтвердила 190 после одного сохранения и повторного открытия той же
  фактуры. Отмена `391df5c2-ce01-402b-be79-2153736dd46c` подтвердила 110.

Сводная сверка `.artifacts/stage56-native-verified.json` прошла с
`issues=[]`. Сверены счётчики клавиш, точные ссылки и независимое чтение
данных. Копии удалены. Прошли 218 тестов форм.
