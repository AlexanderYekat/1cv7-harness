# Этап 5, задача 026: модальные окна в шагах

Дата: 25 октября 2026 года. Предшествующая задача — [025](025-form-steps.md).
Статус: **принято** владельцем 26 октября 2026 года ([отчёт проверки](026-modal-dialogs-acceptance.md)).
Владелец выбрал направление 25 октября 2026 года из четырёх предложенных
(модальные окна в шагах, табличная часть в шагах, проведение и движения, набор тестов за прогон).

## Зачем

После 025 сценарий нажимает кнопки и вводит текст на форме. Если обработчик открывает модальное
окно (`Предупреждение`, `Вопрос`, `ВвестиСтроку`), сценарий на нём останавливается. Сообщение
нажатия не возвращается, пока окно открыто, и через 10 с шаг проваливается с причиной «did not
return». Окно остаётся открытым, и дальнейшая судьба сеанса не определена. Такие окна есть
почти в каждой прикладной форме: подтверждение записи, предупреждение о неверных данных, ввод
значения перед действием.

Нужен шаг, который проверяет текст окна и отвечает на него, как пользователь. Неожиданное окно
должно давать понятный провал и закрываться, чтобы сеанс завершился обычным путём.

## Охват

1. Новый вид шага:
   `{ dialog = "<текст окна>", button = "<подпись кнопки>", text = "<ввод>", closes = true }`.
   - `dialog` — текст, который показывает окно. Для `Предупреждение` и `Вопрос` это текст
     сообщения, для окон ввода — заголовок (подсказка). Сравнивается после замены любых
     пробелов и переводов строк одним пробелом.
   - `button` — кнопка по подписи, без `&` и без учёта регистра. Латинские и кириллические
     буквы одного начертания равны: кнопка `Предупреждение` — «OK» латиницей (задача 002),
     в сценарии пишут «ОК». Если в окне одна кнопка, ключ можно не указывать.
   - `text` — текст для единственного поля ввода окна (`ВвестиСтроку`, `ВвестиЧисло`,
     `ВвестиДату`).
   - `closes = true` — после ответа форма закрывается.
2. Шаги `dialog` идут сразу после действия (`click` или `input`), которое открывает окно, или
   после другого `dialog`, если обработчик открывает окна одно за другим. Такая цепочка
   считается одним действием. Сообщения, ошибки исполнения и проверка закрытия относятся
   к последнему шагу цепочки. `closes` у действия, за которым следует `dialog`, ставится
   на последний `dialog`. Нарушение порядка — отказ до запуска.
3. Последнее сообщение действия (нажатие кнопки, выход из поля) отправляется из отдельного потока.
   Пока его нет, наблюдатель ищет новое видимое окно верхнего уровня нашего потока 1С, у которого
   владелец выключен. Это и есть модальное окно. Из него читаются заголовок, тексты, кнопки и поля.
   Ответ — `WM_COMMAND` от выбранной кнопки, как при закрытии окна в задаче 002. Повторная
   проверка процесса выполняется перед каждым сообщением, как раньше. После возврата действия
   1С вызывается, и затем окно ищется ещё раз: так находится окно, которое открыло поставленное
   в очередь действие, например вопрос при `#Закрыть` (серия 0c). Каждый вызов цепочки получает
   свой номер (`шаг + 1000·k`) и протокол; последний шаг цепочки оценивает их вместе.
4. Окно, которое открылось без шага `dialog`, проваливает шаг действия с текстом окна и его
   кнопками. Не тот текст или нет такой кнопки — тоже провал. После любого провала окно
   закрывается безопасной кнопкой: «Отмена», иначе «Нет», иначе единственная кнопка. Так делается,
   пока действие не вернётся, но не больше пяти окон. Закрытие записывается в свидетельства.
   Если окно не открылось, а ожидался `dialog`, — провал «no modal window opened».
5. Без шагов `dialog` и без модальных окон поведение 025 не меняется. Срок 10 с на возврат
   действия сохраняется. Время, пока открыто ожидаемое окно, в этот срок не входит.

`ОткрытьФормуМодально`, выбор значения ссылочного типа (`ВвестиЗначение` со справочником),
модальное окно в `ПриОткрытии` (до того, как `ОткрытьФорму` вернётся) и окна без кнопок не входят
в задачу. Такое окно должно давать явный провал, а не зависание шага.

## Приёмка

Ожидания нативных случаев записываются здесь до запусков. Каждый случай — один `harness77 run`
на копии базы. Форма — форма элемента «Банки» с добавленной кнопкой или полем. Модуль меняется
только добавленными процедурами, банк записывает `fixture_setup` (как в 025). Проверяются:
предупреждение, вопрос (каждый ответ), цепочка окон, окна ввода, окно из формулы поля, вопрос
1С при закрытии изменённой формы, ERT. Провалы: неожиданное окно, не тот текст, нет кнопки,
окно не открылось. Отказы до запуска: неверный порядок шагов. Регрессия — пример 025, пример 024,
`f-elements` 022. Переносимые тесты покрывают разбор и порядок шагов, выбор кнопки, сравнение
текста и оценку. Копии удаляются, база стенда и список баз не меняются.

Серия 0 (исследование механизма). Ожидания до прогона:

- `m-warning`: кнопка «Окно 77» — `Сообщить("до 77")`, `Предупреждение("Harness77 предупреждение")`,
  `Сообщить("после 77")`. Шаги: нажать, `dialog` без `button` (одна кнопка), `message "до 77"`,
  `message "после 77"`. Окно — `#32770` со статическим текстом и одной кнопкой (как в задаче 002).
  Сценарий проходит.
- `m-question`: `Ответ77 = Вопрос("Harness77 вопрос?", "Да+Нет")`, `Сообщить("ответ " + Ответ77)`.
  Ответ «Нет» — сообщение «ответ Нет». Сценарий проходит.
- `m-chain`: вопрос «Да+Нет+Отмена», ответ «Да» — затем `Предупреждение("Harness77 готово")`,
  затем `Сообщить("конец 77")`. Два шага `dialog`, сообщение «конец 77». Сценарий проходит.
- `m-string`: `ВвестиСтроку(Стр77, "Harness77 строка", 20)`, ввод `abc77`, «ОК» — сообщение
  «строка abc77». Окно ввода: поле и кнопки «ОК»/«Отмена». Ввод — как в поле формы 025:
  фокус, выделение, символы, затем фокус на кнопку.
- `m-number`, `m-date`: то же для `ВвестиЧисло` (`12.5`, «число 12.5») и `ВвестиДату`
  (`251026`, «дата 25.10.26»).
- `m-field`: поле `Число77` (число 10.2) с формулой, которая при значении больше 100 вызывает
  `Предупреждение("Harness77 больше 100")`. Ввод `500`, затем `dialog`, затем `value Число77`
  = «500». Окно открывается при выходе из поля.
- `m-close`: ввод в «Наименование», «Закрыть». Ожидание: 1С спрашивает, записать ли изменения.
  Текст вопроса неизвестен, поэтому в шаге стоит заведомо другой текст. Случай должен провалиться
  с причиной «the window shows …», окно закрыто «Отменой» или «Нет», сеанс завершён обычно.
  Текст из свидетельств войдёт в серию 1.
- `m-unexpected`: нажатие «Окно 77» без шага `dialog` — провал «an unexpected modal window
  'Harness77 предупреждение'», окно закрыто, `result` закрывает форму контроллером.
- `m-no-dialog`: нажатие «Записать» (верный БИК), затем `dialog` — провал «no modal window opened».

Наблюдать: класс, заголовок, тексты и ID кнопок окон `Предупреждение`, `Вопрос` и окон ввода;
владелец окна; возвращается ли действие после ответа и сколько это занимает; доходит ли ввод
в окне до переменной модуля; работает ли вызов 1С после цепочки.

Серия 0c, итог: `m-chain` (вопрос «Да+Нет+Отмена»: «Отмена» — ID 2; ответ «Да», затем
предупреждение), `m-date` (окно « 25.10.26» → «01.01.26», сообщение «дата 01.01.26»)
и `m-no-dialog` совпали. `m-close` не совпал: «Закрыть» (`#Закрыть`) вернулся за 0,1 с без окна,
вызов 1С после шага ответил, шаг `dialog` окна не нашёл. Вопрос 1С появился позже, при закрытии,
которое `#Закрыть` ставит в очередь. Окно осталось открытым, вызов `result` ждал его, и сеанс
завершился по тайм-ауту завершения. Копия удалена, процессов 1С не осталось.

Исправление: после возврата действия 1С вызывается, и только затем проверяется, не открылось ли
окно. Поставленное в очередь 1С выполняет раньше этого вызова. Если при этом открывается окно,
вызов обслуживается уже в его цикле, поэтому окно открыто, когда вызов возвращается. Тогда цепочка
продолжается. После ответа 1С вызывается снова: под номером `шаг + 1000·k`, со своим протоколом.
Последний шаг цепочки оценивает все её вызовы вместе: сообщения, ошибки исполнения.
