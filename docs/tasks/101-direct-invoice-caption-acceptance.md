для прямого открытия существующего документа с fixture_setup/fixture_verify.

не исключаются. Код MD/диалога эта настройка не изменяет.

wheel с манифестом SHA-256. Производные копии вручную не патчились.

## Самостоятельный проект и сценарий

Проект — `C:/MyProjects/h77-101-direct/`, вне checkout. Новый wheel включён
в `.harness77/packages/` и установлен в локальное окружение. Doctor, run,
CLI suite и stdio MCP идут через `.harness77/launch.py`; маркер пустой.
PYTHONPATH/PYTHONHOME отсутствуют, user site отключён. Глобальные настройки
и регистрация MCP не изменяются.

Fixture создаёт только товар, покупателя, договор, подразделение и фактуру
с двумя строками 1×50 и 1×30; возвращает непосредственно ссылку фактуры.
Накладной-основания, списка ссылок или навигации журнала нет. Reader читает
сохранённые данные новым объектом по аргументу Объект77.

Параметры fixture_mode="existing", caption_control="кнПечать",
caption_text="Печать". Первый UI-шаг читает подпись кнопки; затем меняется
количество второй строки на 3, документ записывается и закрывается.
Reopen явно ожидает «Печать», подтверждает исчезновение прежнего окна
и равенство сохранённой ссылки; следующий check вновь читает подпись.
Ожидаются строки 50/90 и итоги 140. Документ не проводится.

В четырёх фазах один набор fixture/reader/steps/expected/ERT/контроллера.
Регрессия +1 только в пересчёте количества/цены даёт 91 и 141 с четырьмя
точными JSON-расхождениями. Исправление побайтно восстанавливает исходник.
Отдельные отрицательные контроли меняют только ожидание подписи первого
открытия либо reopen и должны провалить соответствующую проверку.
