## Чтение и отсутствие изменений

[Проект](../../.artifacts/s106-native-project/acquisition.json) использует
закреплённый wheel через локальный launcher, без PYTHONPATH/PYTHONHOME.
Стенд прежний: Windows, 1С 7.70.027, DBF, 1С++/FormEx, явные helper/identity DLL.
Каждый запуск работает с одноразовой копией базы.
Doctor: 41 passed, 1 skipped, без blocked/warning.
[Результат doctor](../../.artifacts/s106-native4/cycle/doctor.stdout.json).

В начале примера известны только идентификаторы двух COMBOBOX. Из открытой
формы прочитаны:

- СписокТиповУслуг: «Оказание услуг», «Оказание посредн. услуг в торговле».
- ВариантЗачетаАванса: «не зачитывать», «только по договору»,
  «без указания договора».

Оба исходных выбранных индекса равны 0. Порядок пунктов сохраняется.
`discovery.json` содержит эти наблюдения; тексты для последующего select
генерируются из него, а не задаются заранее.

Шесть случаев прошли через каждый из трёх транспортов — 18 запусков:
обычное чтение; скрытый список с пунктами `['', 'Дубль', 'Дубль']`;
пустой список; 1001 пункт; успешное чтение после отказа; контрольный select.
Только переполнение ожидаемо даёт failed: `COMBOBOX item count exceeds 1000`.
У него нет полного snapshot; reader подтверждает прежние сохранённые данные.
Оба suite продолжают работу после отказа, JSON/JUnit согласованы.
MCP отвечает на ping во время и после suite и завершается с кодом 0.
[Серия и снимки стенда](../../.artifacts/s106-native4/verified.json).
Независимый аудитор перечитал все 18 отчётов, 30 snapshots и 72 снимка входов:
хеши совпали, результаты трёх транспортов одинаковы.
[Повторная сверка чтения](../../.artifacts/s106-native4/read-verification.json).

У выбранного пустого пункта индекс 0 и текст `""`; у пустого списка
индекс и текст равны null. Фокус до/после каждого чтения совпадает.
В обоих обработчиках выбора установлен счётчик с сообщением о каждом вызове:
при чтении сообщений нет, контрольный select публикует ровно вызов № 1.
Reader подтверждает ТипУслуги=1 при чтении и 2 после контрольного select
и записи; остальные строки, ссылки и итоги прежние.

## Основной цикл и совместимость

Основной цикл baseline/regression/fixed/repeat-fixed завершён через run,
CLI suite и MCP: в каждом транспорте passed/failed/passed/passed.
Тексты для двух select взяты из discovery. Текущий пункт — проверенный no-op;
смена пункта вызывает обработчик. После записи и reopen читается новый
snapshot, контекст и независимый reader.

Контролируемая ошибка в прикладном обработчике сохраняет ТипУслуги=1 вместо 2.
После reopen snapshot показывает индекс 0, шаг 12 `value` обнаруживает
значение 1, reader даёт ровно одно различие `/service_type` (expected=2,
actual=1). Исправление восстанавливает исходный модуль побайтно. Оба suite
продолжают работу после регрессии; MCP сохраняет связь и штатно закрывается.
[Основной цикл](../../.artifacts/s106-native4/cycle/verified.json).

Повторный verifier перечитал 12 отчётов и сверил 48 снимков четырёх входов
с байтами проекта. Все 48 snapshots COMBOBOX имеют верную привязку к шагу,
SHA-256 и ссылки в run.json. Диагностика между транспортами совпала,
JUnit согласован с JSON. 24 состояния геометрии открытия/reopen прошли
с максимальной невязкой 1,01 px при допуске 2 px; 216 отрицательных подмен отклонены.
[Повторная сверка цикла](../../.artifacts/s106-native4/cycle/independent.json).

Неизменённые принятые примеры 104 и 105 дополнительно прошли на том же

## Найденные особенности проверочного стенда

Сохранены и не включены в успешную квалификацию подготовительные попытки:

- [Первая подготовка](../../.artifacts/s106-native): сравнение MD-потока
  остановилось до запуска 1С из-за LF/CRLF; ожидаемые байты приведены к
  формату md-build.
- [Первая нативная попытка](../../.artifacts/s106-native2): снимок списка
  успешен, но `value` не читает экспортную переменную модуля формы через
  контекст документа. Счётчик наблюдается через сообщения каждого вызова,
  с положительным контролем select. Runtime менять не потребовалось.
- [Следующая попытка](../../.artifacts/s106-native3): 1С отображает пустое
  представление числового значения 1 как «1»; для действительно пустого
  пункта требуется строковое значение `""`. Скрытие также изменяет
  native-доступность: `enabled` читается из окна, а не выводится из свойства
  формы `Доступность`. Итоговый нативный случай проверяет скрытое окно;
  disabled дополнительно покрыт тестом runtime.

Снимки исходного стенда перед тремя нативными попытками совпали. Принудительное
завершение в этих попытках не требовалось. Все исправления касались подготовки
и аудита примера; квалифицируемый wheel остался тем же.

Охват ограничен строковыми drop-down COMBOBOX типов 2/3, до 1000 пунктов
по 4096 символов, на указанном стенде. Это чтение native-представления,
не универсальный инспектор форм и не чтение внутренних значений списка 1С.
