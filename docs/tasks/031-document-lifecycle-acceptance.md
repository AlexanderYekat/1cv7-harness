## Реализация

`fixture_operations` задаёт порядок действий над одной ссылкой документа.
`post-<id>` вызывает `Провести(1)`, `unpost-<id>` — `СделатьНеПроведенным()`.
Каждая команда заново читает сохранённый документ; необязательный `before` —
доверенный код, явно изменяющий и записывающий этот объект до действия.
Другой объект читает сохранённый признак проведения; успех требует возврата 1
и признака 1 для проведения, 0 для отмены. Отказы/ошибки сохраняются в `posting`
и диагностике; неполные/неоднозначные ответы блокируют проверку.

Сразу после каждой операции выполняется обязательная `verify-<id>` с обычным
доверенным кодом `fixture_verify`. Пример читает все бухгалтерские проводки
через новую `Операция` по ссылке документа, проверяет количество, счета Дт 43
Кт 40, ссылки товара, количества и суммы. Также выполняется финальная `verify`.
Список не совмещается с `fixture_post`, ограничен 20 операциями; id уникальны.
Все операции и проверки должны быть объявлены тестами до запуска.
Исходная база отклоняется: необходима проверенная копия `[configuration]`.
