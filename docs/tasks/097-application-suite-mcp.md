# Задача 097. Прикладная регрессия через suite и MCP

Дата — 13 ноября 2026 года. Продолжение принятой
[096](096-structured-application-checks.md). Реализация и проверка
завершены; результат принят владельцем 13 ноября 2026 года.

## Ожидания до запуска

Использовать установленный принятый wheel 0.5.0 и тот же документ,
UI-сценарий, reader и JSON-ожидания 096. Нового бизнес-адаптера, launcher
или правил бухгалтерии в ядре не требуется.

Один манифест выполняет baseline/regression/fixed/repeat-fixed. Каждый
проект отличается только каталогом модулей конфигурации; тесты, параметры,
ERT-модуль, шаблон и ожидаемый JSON неизменны. Регрессия меняет только
`Операция.Сумма = Сумма;` на `Операция.Сумма = Стоимость;` в модуле
проведения «Готовой продукции». У каждого сценария своя свежая копия базы.

Этот манифест выполнить через CLI suite и stdio MCP tools/call suite.
Ожидаются passed/failed/passed/passed, итог failed/1 и ровно один JUnit
failure. MCP возвращает isError=false: прикладной провал — результат теста.
Два расхождения сумм 30→10 и 40→20 должны сохраниться с JSON Pointer,
подписями, типами и значениями в run.json, suite.problems и JUnit.

Второй манифест выполняет invalid-json/empty-json/recovered с неизменными
ожиданиями и двумя явно изменёнными reader. Ожидаются blocked/blocked/passed,
итог blocked/2 и два JUnit error, разные коды json_result_invalid и
json_result_missing. MCP возвращает isError=true, отвечает на ping и
принимает следующий успешный suite (passed/0, isError=false).

Независимо перечитать suite/JUnit/все run, raw протоколы, сохранённый JSON,
SHA-256 и размеры; сверить пути и run_id, точные диагностики, отсутствие
других провалов и пропусков. Сопоставить результаты CLI и MCP без случайных
идентификаторов и путей. Проверить прогресс MCP по сценариям, один Initialize
на запуск, штатную очистку, удаление копии/замка и сохранность источника,
реестра, входов, runtime и чужих процессов. Автоматических повторов нет.

Охват ограничен документом и квалифицированным стендом 096 (Windows /
7.70.027).

## Реализация и переносимая проверка

Новых операций MCP и изменений ядра нет. `suite77._problems` уже переносит
точные JSON Pointer, подписи, типы и значения в `structured.diagnostics`.
JUnit содержит ту же диагностику в JSON-тексте failure/error. Сводный ответ
MCP содержит причину и пути; полная диагностика остаётся в связанных
suite.json/run.json/JUnit. Пустой raw-файл — свидетельство отсутствующего
результата, не подтверждение успешной проверки.

Добавлены `tests/test_application_suite77.py`, самостоятельный пример
`examples/application-suite` и `scripts/verify_application_suite77.py`.
Два новых теста запускают настоящие CLI/MCP процессы на simulation-стенде:
точные два расхождения, JUnit failure/error, продолжение после failed/blocked,
ping и следующий успешный suite после isError=true.

Из нового venv без pip, из другого CWD, без PYTHONPATH/PYTHONHOME и
checkout-импортов прошли **590 тестов, 5 пропусков** (четыре ограничения
symlink и одна проверка только для не-Windows). Использован принятый wheel
0.5.0 из 096, без пересборки:
`35cf181a9b57d856da727f32da3463646ed4685e1314fd7d341728d64bc8f47e`.
Все 36 файлов ядра совпадают с checkout; нативные 33 файла не изменены.
[Журнал полного набора](../../.artifacts/s97-installed-tests/tests.log).

## Нативные результаты

Одинаковые манифесты выполнены из чистого установленного wheel через CLI
и MCP, с одним стендом и отдельной копией базы на каждый сценарий:

- [CLI regression](../../.artifacts/s97-native/cli-regression/suite/suite.json)
  и [MCP regression](../../.artifacts/s97-native/mcp-regression/suite/suite.json):
  **passed/failed/passed/passed**, итог **failed/1**, counts 3/1/0/0.
  По одному JUnit failure; последующие исправление и повтор не пропущены.
  MCP вернул **isError=false**. Неуспешен только
  `persisted-document-and-entries`, с ровно двумя расхождениями сумм.
- [CLI invalid-results](../../.artifacts/s97-native/cli-invalid-results/suite/suite.json)
  и [MCP invalid-results](../../.artifacts/s97-native/mcp-invalid-results/suite/suite.json):
  **blocked/blocked/passed**, итог **blocked/2**, counts 1/0/2/0.
  По два JUnit error, разные коды `json_result_invalid` и
  `json_result_missing`; recovered прошёл. MCP вернул **isError=true**.

Сохранённый документ, строки и количества во время регрессии верны;
только суммы проводок равны 10/20 вместо 30/40. В run, suite.problems и
JUnit совпали пути `/entries/0/amount`, `/entries/1/amount`, подписи,
строковые типы и значения. Сводный reason содержит обе ошибки.
Нормализованные результаты двух одинаковых манифестов CLI и MCP совпадают.

Диагностика регрессии:
[CLI run](../../.artifacts/s97-native/cli-regression/runs/a3a72208-4b65-4bf7-bd62-e56655b0a319/run.json),
[MCP run](../../.artifacts/s97-native/mcp-regression/runs/33af7fbd-1ea9-489f-951b-5c09c4c215fb/run.json).

Тот же MCP-процесс после isError=true выполнил
[успешный новый suite](../../.artifacts/s97-native/mcp-success/suite/suite.json):
**passed/0, isError=false**. Во всех трёх MCP-запросах зафиксированы
прогресс со всеми границами сценариев, строго возрастающий счётчик,
правильный progressToken и успешные ping во время и после выполнения.
[Полный stdio-трафик](../../.artifacts/s97-native/mcp-traffic.json).
Сервер PID 19780 завершился с кодом 0.

Всего **15 нативных запусков, 5 наборов**, без пропусков и автоматических
повторов. В каждом запуске один Initialize, успешный старт и нативные
операции, forced_cleanup=false, подтверждённая очистка, удаление копии,
освобождение замка. JSON-ошибки не подменяют исход нативной операции:
операция verify выполнена, оценка её результата заблокирована.

Сверены **3598 потоков** каждой из семи плановых MD. Только регрессионная
MD отличается одним потоком модуля проведения; baseline/fixed/repeat-fixed
и отрицательные случаи сохраняют исходную MD. Хеш каждого run совпадает
со своей плановой MD. Все 36 файлов ядра и 33 нативных файла остаются из
принятого wheel 0.5.0. Источник, MD/DD/DLL, реестр, guard, входы и runtime
сохранены. Чужой PID 18812 во всех запусках имеет прежние parent=7676,
образ и creation_filetime=134390187986538342; чужие сеансы не завершались.

Независимый verifier повторно перечитал все пять наборов и 15 запусков.
**33 подмены отклонены** на отдельных копиях: пути, подписи, типы,
значения, коды, счётчики, ссылки/размеры/байты JSON, run_id, подробности
JUnit, отсутствие raw-событий/UI и незавершённый suite. Для шести контролей
согласованно менялись run/suite/JUnit с пересчитанными хешами. Отрицательные
JSON-запуски дополнительно сверены по всем raw UI-протоколам прежним verifier
033: допускается только его заранее известное расхождение статуса
blocked вместо ожидаемого им failed. Исходные свидетельства после контролей
перечитаны и сохранены без изменений.
