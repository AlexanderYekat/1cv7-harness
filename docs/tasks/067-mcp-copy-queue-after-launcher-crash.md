# Задача 067. Очередь MCP после падения run и launcher

Два запроса `run` через один MCP-сервер использовали один временный
`copy_path` на 1С 7.7.027. Первый launcher подтвердил свой OLE-прокси
и остановился перед публикацией `initialize-permit`. Когда второй
запрос начал ждать, проба завершила первый CLI, затем его launcher.
Для остановки использовались дескрипторы тестовых процессов. Перед
остановкой launcher проба сверила UUID, PID, время создания, путь
исполняемого файла и дерево процессов.

## Результаты

- После выхода обоих процессов CDB, 1С и клиент первого запуска
  оставались живы. Таблицы копии были доступны, а Windows по-прежнему
  запрещала удаление `.lock`. Второй запрос снова сообщил «ждёт
  освобождения пути копии». Опись 856 файлов, SHA-256 `1Cv7.MD`,
  метка, замок и обе COM-регистрации совпали со снимком до падения.
  Первый `Initialize` не вызывался, второй launcher ещё не стартовал.
- После выхода тестовых дочерних процессов тот же второй запрос
  продолжился автоматически. Отчёт зафиксировал 10,334 с ожидания
  замка. MCP сообщил «готовит копию», затем «запускает 1С». Новая
  копия получила свой `run_id` и не содержала контрольного файла
  первой копии. Launcher подтвердил выход всех процессов из обеих
  записей владельца, снял оставленные COM-регистрации, один раз
  вызвал `Initialize`, вернул 42 и штатно закрыл 1С.

Временная копия, замки и запись пути удалены. Опись исходной базы
совпала со снимком до прогона. Список баз и COM-ключи восстановлены.
Сценарий прошёл с действующим механизмом защиты копии.
