# Этап 5, задача 023: формы справочников и журналов 1Cv7.MD на копии базы

Дата: 22 октября 2026 года. Предшествующая задача — [022](022-md-forms.md).
Приёмка — [023-catalog-journal-forms-acceptance.md](023-catalog-journal-forms-acceptance.md). Статус: **принято** владельцем 23 октября.

## Зачем

После 022 агент меняет модуль и описание любой формы конфигурации, но в 1С проверяются только формы
документов и обработок: launcher форм не открывает форму элемента, группы и списка справочника и
форму журнала. Ошибка компиляции модуля такой формы привязывается к изменённому объекту по имени, без
файла и строки: как 1С называет эти модули в сообщениях, не проверялось (открытое передач 021 и 022).
22 октября владелец выбрал это направление из четырёх (формы справочников и журналов, данные тестов на
копии, колонки табличной части, реквизиты в метаданных).

## Что известно до начала (статический обзор)

- `md-extract` и `md-build` уже раскладывают и собирают эти формы (задачи 021, 022): в базе стенда
  55 форм элемента, 24 формы группы, 83 формы списка справочников и 28 форм журналов, в «Торговле+Складе
  9.2» — 55, 20, 73 и 18. Форма элемента и группы — форма объекта: поле с именем реквизита справочника —
  поле этого реквизита.
- У каждой формы списка есть раздел `Browser` — список (`Multicolumn`, окно `browse` с ID 4151) и колонки
  (`Fixed`, первая — пиктограмма). Первое число раздела у форм списка чаще 0, у части — 1–5. Правило ID
  окон задачи 022 (окна с последней записи, список — после первых `B` окон, колонки занимают `C` номеров)
  на формах списка не проверялось.
- Синтакс-помощник 7.70.027 (`1cv7Lang.als`): новый элемент — `ОткрытьФорму("Элемент.<Вид>", Конт,
  ГруппаРодитель, ФлагГруппы, ЭлементВладелец)`, флаг группы 1 — новая группа; форма списка —
  `"Справочник.<Вид>.<Форма>"`; форма журнала — `"Журнал.<Имя>.<Форма>"`; `Форма.Закрыть(0)` закрывает
  форму без вопросов, в том числе изменённый элемент справочника.
- Использование реквизита справочника — поля 11 и 12 его записи `Params`: «для элемента» и «для группы».
  На формах элемента базы стенда 271 поле реквизитов — все «для элемента»; на формах групп 1 поле — «для
  группы»; в «Торговле+Складе» на формах групп 14 полей, из них одно (`Партии.Свойство`) — реквизит только
  для элемента. Ни у одного из 379 + 379 реквизитов справочников двух конфигураций нет записи «ни для
  элемента, ни для группы».
- Подчинённый справочник (поле 4 записи — номер владельца): 9 из 58 в базе стенда, 16 из 60 в
  «Торговле+Складе». Его новый элемент открывается с владельцем — `ЭлементВладелец`.

## Охват

1. **Launcher форм** (`research/forms/form_launcher77.py`): `form_object` называет форму как файл её модуля
   в раскладке `md-extract` —
   `Справочник.<Вид>.ФормаЭлемента` → `ОткрытьФорму("Элемент.<Вид>", Контекст)`,
   `Справочник.<Вид>.ФормаГруппы` → `ОткрытьФорму("Элемент.<Вид>", Контекст, , 1)`,
   `Справочник.<Вид>.ФормаСписка.<Форма>` → `ОткрытьФорму("Справочник.<Вид>.<Форма>", Контекст)`,
   `Журнал.<Имя>.ФормаСписка.<Форма>` → `ОткрытьФорму("Журнал.<Имя>.<Форма>", Контекст)`;
   прежние `Документ.<Имя>`, `Обработка.<Имя>`, `Отчет.<Имя>` — без изменений. Ожидаемая форма — диалог
   этой формы в `1Cv7.MD` копии; у формы списка — место списка среди окон (`browser`), как у табличной
   части. Новый элемент и группа подчинённого справочника — явный отказ (нужен владелец).
2. **Имена модулей в ошибках компиляции** (`md77.platform_module`): модули форм элемента, группы и списка
   справочника, формы журнала и формы отчёта — к своим файлам раскладки; `run` даёт
   `configuration_compilation_failed: <файл>:<строка>`. Имена устанавливает серия 0.
3. **Использование реквизита** (`metadata77.Attribute.use`, `form77.FormContext`): новое поле с именем
   реквизита справочника на форме элемента — только реквизита «для элемента», на форме группы — «для
   группы»; иначе отказ `md-build` с использованием реквизита в сообщении. Существующие поля не меняются.
   Запись без известного использования — без отказа.
4. **MCP и CLI** — без новых инструментов: `run` и `md-build` прежние.

**Не входит:** открытие существующего элемента, группы или документа (нужны данные базы); новый
элемент подчинённого справочника; формы плана счетов, операций и проводок; изменение колонок
(`Browser`), новые формы и объекты.

Отказ по использованию реквизита нативно не проверяется: такая форма не собирается `md-build`, а
`run` строит конфигурацию только им. Основание — корпус (выше).

### Серия 0: имена модулей и вызовы `ОткрытьФорму`

В модуле формы — синтаксическая ошибка в новой процедуре (как `f-calc-error` задачи 022). 1С компилирует
модуль формы при её открытии, поэтому ошибка в журнале копии означает, что вызов открыл именно эту форму.

| Случай | `form_object` | Ожидание |
|---|---|---|
| `e-name` | `Справочник.Банки.ФормаЭлемента` | `run` — `failed`, `configuration_compilation_failed: Справочник.Банки.<?>:<строка ошибки>` |
| `g-name` | `Справочник.Банки.ФормаГруппы` | то же, имя модуля формы группы — `?` |
| `l-name` | `Справочник.Банки.ФормаСписка.Основная` | то же, имя модуля формы списка — `?` |
| `j-name` | `Журнал.Доверенности.ФормаСписка.ФормаСписка` | `configuration_compilation_failed: Журнал.Доверенности.<?>:<строка>` |
| `r-name` | `Отчет.КурсыВалют` | `configuration_compilation_failed: Отчет.КурсыВалют.<?>:<строка>` |

После серии: копии удалены, перечень файлов базы стенда и список баз 1С не изменились.
