# 114. Обновление fixture и reader из TOML

Задача принята владельцем 19 ноября 2026 года.

В локальном 0.18.0 `fixture-refresh` обновляет управляемую пару файлов в
существующем проекте, созданном через `project-init --fixture-kind` в 0.17.0
или новее. Сохранённый `fixture-recipe.toml` нужен для сравнения. Для правки
сделайте его отдельную копию и передайте её команде.

```powershell
Copy-Item -LiteralPath ./project/fixture-recipe.toml -Destination ./next.toml
# После редактирования next.toml:
harness77 fixture-refresh --project ./project/project.toml --recipe ./next.toml --format json
harness77 run --project ./project/project.toml --stand ./stand.toml
```

Перед записью команда заново генерирует `.1s` по сохранённому рецепту и
сверяет их с существующими файлами побайтно. Любая сохранённая ручная правка,
включая комментарий и переводы строк, даёт `blocked` с именами конфликтующих
файлов в `conflicts`. В этом случае текущий fixture, reader и снимок рецепта
сохраняются. При успехе меняются только нужные файлы из этой тройки. Шаги,
ожидания, `project.toml` и обработка предыдущей схемы профиля сохраняются.
Отчёт содержит `updated`, `unchanged` либо `blocked` и хэши результатов
при успехе.

Файлы подготавливаются под временной блокировкой каталога. Сбой записи
вызывает откат уже заменённых файлов. Если восстановление заблокировано,
резервные копии остаются в `.harness77-fixture-refresh.lock`. В 0.18.0 `run`
откажется читать незавершённую или смешанную пару. При таком отказе нужно
проверить резервные файлы, восстановить согласованную тройку и только после
этого убрать блокировку.

## Критерий проверки

На проекте услуг, созданном скачанным 0.17.0, вручную изменить каждый `.1s`
по очереди и получить отказ с его именем. После восстановления исходных
файлов применить TOML с другим именем услуги и `service_type = 2`. При
неизменных ожиданиях reader должен получить `/service_type = 2` и показать
одно расхождение. Возврат прежнего TOML должен вернуть `passed`.

## Результат

19 ноября 2026 года кандидат 0.18.0 установлен из wheel в отдельный
каталог `C:/MyProjects/h77-114-refresh`. Проведены 655 пакетных тестов с 5
пропусками. Новые тесты проверили повтор без правок, отказ при изменении
каждого `.1s`, откат после ошибки замены, сохранение резервных копий при
заблокированном откате и отказ чтения смешанной пары.
[Проверка пакета](../../.artifacts/s114-package/summary.json).

В нативном проекте из скачанного 0.17.0 добавленный вручную комментарий
в каждом из двух `.1s` дал отдельный `blocked` с точным именем файла. Во
время отказов сохранены байты всех входов. При обновлении без конфликта
изменились только fixture, reader и снимок рецепта. Серия `run` дала
`passed → failed → passed`, во всех фазах прошли 19 UI-шагов. Reader поймал
одно расхождение `/service_type` (`1 → 2`). Возврат исходного TOML восстановил
все файлы проекта побайтно, повтор с тем же рецептом дал `unchanged`.
Ожидания и шаги совпали во всех запусках. База, реестр и чужие процессы
сохранены. [Нативный отчёт](../../.artifacts/s114-native-verification.json).

После проверки убраны временные сборки и окружения, суммарно около 52 МБ.
Wheel, журналы, проекты и нативные отчёты сохранены. Копия базы и блокировки
запуска и обновления отсутствуют. [Запись очистки](../../.artifacts/s114-cleanup.json).
