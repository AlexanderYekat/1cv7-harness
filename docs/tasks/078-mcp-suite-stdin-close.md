# Задача 078. Закрытие stdin MCP во время ожидания стенда

Задача принята владельцем 10 ноября 2026 года.

Проба запускает два независимых MCP-сервера в одном сеансе Windows
на 1С 7.7.027. Первый выполняет набор из трёх сценариев, второй
запускает отдельный `run` на другой временной копии базы. Отдельный
запуск встаёт в очередь, пока первый сценарий держит стенд, и
захватывает мьютекс после его штатного выхода.

После сообщения «сценарий 2/3 … ждёт освобождения стенда» проба
закрывает stdin сервера набора и продолжает читать stdout до его
выхода. MCP получает EOF, передаёт отмену через файл и дожидается
завершения CLI. Состояние владельца проверяется через второй сервер.

## Результаты

- После EOF сервер набора успел отправить итоговый ответ
  `exit_code=2`, `complete=true`, `cancelled=true` и штатно вышел
  с кодом 0 через 6,919 с. В итоговом JUnit первый сценарий успешен,
  второй содержит `error` с причиной `cancelled`, третий — `skipped`.
  Хеш результата первого сценария сохранился.
- Второй сценарий завершился после 0,556 с ожидания мьютекса до
  старта CDB, 1С и OLE-клиента. Launcher подтвердил очистку,
  временная копия удалена, замок освобождён.
- Отдельный MCP-сервер ответил на `ping` после выхода сервера
  набора. Снимки четырёх процессов владельца, COM-регистраций,
  метки, замка, описи 855 файлов и хеша `1Cv7.MD` совпали до и
  после EOF. Владелец продолжил работу, один раз вызвал
  `Initialize` и вернул 42.

Оба сервера вышли с кодом 0. Временные копии и замки удалены.
Опись исходной базы, список баз, COM-регистрации и процессы 1С
совпали со снимками до прогона.

Сводка — `.artifacts/s78-native/verified.json`. Локальная проба
запускается командой `python -B .local/s78-verify.py <новый-суффикс>`.
