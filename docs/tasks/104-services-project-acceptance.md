## Исправление геометрии

Полный прямоугольник измеряется CB_GETDROPPEDCONTROLRECT, а исходный
свёрнутый rect сохраняется. В настоящей форме обнаружена также смена
шрифта: высота поля выбора меняется 18→15 px, сохраняя высоту списка;
полная высота 86 становится 83, а 60 — 57.
Нормализация восстанавливает высоту ресурса по измеренной разнице
`default_item_height - current_item_height`, без фиксированной прибавки.
Текущая высота читается CB_GETITEMHEIGHT, исходная измеряется скрытым
контролом собственного процесса с тем же DPI. Пробник уничтожается;
окна 1С не меняются. Неудача измерения или различие DPI дают явный отказ.
CBS_SIMPLE и остальные элементы сохраняют прежнюю геометрию.

[Нативная проверка API и смены шрифта](../../.artifacts/s104-combo-api-final.json)
подтвердила 86/60 до и после нормализации. Ниже сохранена история
первоначальных отказов и промежуточных проверок.

Сопоставление record ID с window ID по `window_ids`, а не по равенству ID,
локализует большие невязки в двух COMBOBOX:

- `ВариантЗачетаАванса`: record 4164 → window 4198, описание

`fit_units` сравнивает полную описанную высоту с измеренным прямоугольником
окна. Требуется отдельно проверить семантику высоты COMBOBOX и поддержать

## Границы и завершение

Критерии 104 технически выполнены на прежнем Windows/7.70.027/DBF-стенде,
с проверенными 1С++/FormEx и helper/identity. Новые платформы и конфигурации
этой серией не квалифицированы. Бюджеты финальной серии: open 600 с,
calculation 300 с, cancel 15 с, shutdown 60 с, total 1500 с;
допуск геометрии 2 px и четыре прикладных файла не ослаблялись.
В промежуточном контроллере исправлено ошибочное ожидание junit.xml
для одиночного run (он сохраняет JSON; JUnit принадлежит suite).
Baseline этого промежуточного прогона был passed; он не подменяет
12 запусков новой полной финальной серии. Все прежние результаты сохранены.
После приёмки по поручению владельца 0.11.0 опубликована и проверена полным циклом
из релизного wheel. Скачанные файлы совпали с проверенными по SHA-256.
