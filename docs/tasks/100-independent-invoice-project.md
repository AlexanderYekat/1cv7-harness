# Задача 100. Самостоятельный прикладной проект счёта-фактуры

Дата — 13 ноября 2026 года. Реализация разрешена владельцем после приёмки 099.
Статус — реализована, проверена и принята владельцем 13 ноября 2026 года.

## Цель

Подтвердить прикладную работу на втором документе, без цепочки входных
комплектов 095–099. Создать отдельный проект вне checkout, подключить
опубликованный wheel 0.7.0 через connect/harness77.txt и использовать
проектную команду для doctor, run, CLI suite и stdio MCP suite.

## Прикладной сценарий и закреплённые ожидания

Документ — `СчетФактура` квалифицированной DBF-конфигурации стенда.
Новая fixture создаёт товар, покупателя, договор, подразделение, расходную
накладную и подчинённый документ с двумя строками 1×50 и 1×30.
UI находит накладную по точной ссылке, открывает подчинённую фактуру,
меняет количество второй строки на 3, нажимает штатную кнопку записи,
закрывает и повторно открывает ту же ссылку.
Первая строка остаётся 50, вторая становится 90, сумма/всего документа — 140.
Документ не проводится. После закрытия формы reader создаёт новый объект и читает сохранённые
строки по точной ссылке, ссылки товаров, признак проведения, комментарий
и итоги. Ожидания в expected.json задаются до нативных запусков.

Контролируемая регрессия — `+ 1` в штатной ветке пересчёта количества/цены
модуля формы: 91 вместо 90, 141 вместо 140. Это специально внесённая ошибка,
а не обнаруженный дефект исходной конфигурации. Исправление восстанавливает
исходные байты модуля. Baseline, regression, fixed и repeat-fixed проходят
с одинаковыми fixture, reader, steps, expected, ERT и platform.tests.

## Входы и границы

Явно передаются Python установленного пакета для первоначального создания,
ERT, модуль контроллера, helper/identity DLL, executable 1С, CDB, существующая
база, пользователь и зарегистрированный путь временной копии. Компоненты
можно взять из их существующего расположения: формат прежних kit.json
не читается, старые прикладные тесты не используются.

Локальное окружение скачивает конкретный опубликованный GitHub wheel
с закреплённым SHA-256, без обращения к исходникам harness77. В проекте
хранятся исходники, тесты, локальное правило/маркер и настройки; venv, кеш
и результаты исключаются из переносимого архива. Исходная база остаётся
внешним входом и не изменяется. Сборка MD должна менять только целевой
модуль; диалог формы, остальные потоки и метаданные сохраняются.

Квалификация ограничена Windows / 7.70.027 / проверенными компонентами
и данной DBF-базой. Новая платформа, иная конфигурация, создание форм,
публикация пакета и глобальные настройки не входят.

## Проверка готовности

1. Четыре прямых run и по четыре сценария через CLI suite/MCP suite:
   passed, failed, passed, passed. После регрессии suite продолжает работу.
2. UI обнаруживает сохранённую сумму 91; JSON содержит четыре точных
   расхождения `/amount`, `/total`, `/rows/1/amount`, `/rows/1/total`.
   Остальные поля и первая строка не меняются.
3. Raw JSON, SHA-256, MD, run.json, suite.json и JUnit перечитываются
   независимо. Проекции диагностик CLI/MCP/JUnit согласованы; MCP отвечает
   на ping во время suite и после него.
4. Сохранены исходная база, реестр и чужие сеансы; свои копия и lock очищены.
   Тестовые входы и профили сохраняют хеши во всех фазах.
5. Есть воспроизводимый отдельный проект, команды, отчёты и честный перечень
   реально понадобившихся изменений инструмента.
