# Задача 077. Сверка содержимого JUnit с suite.json

Задача принята владельцем 10 ноября 2026 года.

После проверки SHA-256, размера и дочерних отчётов MCP разбирает
`junit.xml` для результата `suite` с кодом 0 или 1. Сервер сверяет
счётчики, порядок и имена testcase, исходы и причины провала,
а также ссылки `system-out` с `suite.json`. При расхождении
MCP сохраняет фактический код и потоки CLI и возвращает
`isError=true` с конкретной причиной.

## Нативная проверка

Три набора через один MCP-сервер на 1С 7.7.027 штатно завершились
с кодом 1. В каждом сценарий «Контроль» ожидал 43 и получил 42.
После работы CLI проба скопировала в один JUnit `system-out` из
другого нативного запуска, а из другого JUnit удалила `failure`.
Перед выходом проба пересчитала SHA-256 и размер JUnit и записала их
в `suite.json` и сводку stdout.

## Результаты

- При согласованных отчётах MCP вернул код 1 с `isError=false`.
- При чужой ссылке MCP сохранил код 1 и вернул `isError=true`
  с причиной «сценарий „Контроль“: ссылка system-out в junit.xml
  не совпадает с suite.json».
- После удаления `failure` MCP сохранил код 1 и вернул
  `isError=true` с причиной «сценарий „Контроль“: исход testcase
  в junit.xml не совпадает с suite.json».

Во всех трёх случаях записанный SHA-256 JUnit совпал с фактическим,
а дочерние отчёты прошли сверку. Каждый нативный запуск вызвал
`Initialize` один раз. Очистка копии, замков и временной регистрации
подтверждена. Прошли 52 автоматических теста MCP и suite. Тесты также
проверили чужое имя testcase и неверные счётчики.

Сводка — `.artifacts/s77-native/verified.json`. Локальная проба
запускается командой `python -B .local/s77-verify.py <новый-суффикс>`.
