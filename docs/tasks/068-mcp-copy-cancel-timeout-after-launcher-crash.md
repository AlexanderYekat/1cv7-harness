# Задача 068. Отмена и тайм-аут в очереди MCP после падения run и launcher

Четыре запроса `run` через один MCP-сервер использовали один временный
`copy_path` на 1С 7.7.027. Первый launcher остановили перед публикацией
`initialize-permit`. После аварийного завершения первого CLI и launcher
по проверенным дескрипторам CDB, 1С и клиент продолжали работать. Первый
`Initialize` не вызывался. Ожидающий запрос снова сообщил «ждёт
освобождения пути копии». В это время в очередь вошли ещё два запроса.

## Результаты

- Запрос, отменённый через `notifications/cancelled`, завершился с кодом 2.
  Отчёт CLI зафиксировал `blocked`, причину `cancelled` и 0,339 с ожидания
  замка. MCP не отправил ответ на отменённый запрос. Выход CLI подтверждён
  по дескриптору процесса до остановки оставшихся процессов первого запуска.
- При `open=3` MCP вернул код 2, `blocked` и `open_timeout` после 3,012 с
  ожидания замка. Для обоих запросов отчёт подтвердил, что замок не захвачен,
  а подготовка копии и нативный запуск не начались. Пока CDB и 1С были
  живы, опись 856 файлов, хеш `1Cv7.MD`, метка, замок и COM-регистрации
  первой копии совпали со снимком до падения.
- Оставшийся запрос продолжился автоматически после выхода старых
  процессов. Он дождался замка за 29,189 с, создал свежую копию со своим
  `run_id` без контрольного файла первой копии, вызвал `Initialize` один
  раз и вернул 42.

Удаление копии, замков и временных регистраций подтверждено. Опись
исходной базы и список баз совпали со снимками до прогона. Сценарий
прошёл с действующим кодом CLI и MCP.
