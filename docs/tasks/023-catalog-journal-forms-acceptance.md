# Приёмка задачи 023: формы справочников и журналов 1Cv7.MD на копии базы

Дата: 22 октября 2026 года. Задание — [023-catalog-journal-forms.md](023-catalog-journal-forms.md). HEAD перед
работой — `038d842`, ветка `master`. Статус: **принято** владельцем 23 октября.

## Итог

Агент проверяет в настоящей 1С формы справочников и журналов конфигурации так же, как с задачи 022 — формы
документов и обработок. Launcher форм открывает новую форму элемента и группы справочника, форму списка
справочника и форму журнала по имени файла её модуля (`form_object`). Он находит форму по ID её окон и
сверяет раскладку и подписи, нажимает кнопки и читает поля. Ошибка компиляции модуля любой из этих форм и
формы отчёта даёт провал прогона с файлом раскладки и строкой: имена, которые 1С пишет в журнал, установлены
пробами. На форме элемента справочника новое поле реквизита допустимо только для реквизита «для элемента»,
на форме группы — «для группы»; иначе `md-build` отказывает.

Нативно (4 серии и регрессия, 44 прогона, ожидания записаны до каждой серии): на итоговом коде все 20 случаев серии 3
совпали с ожиданием, включая регрессию форм задач 011 и 022. Два наблюдения серий 1–2 привели к явному отказу
launcher: 1С не открывает форму элемента справочника, который редактируется в списке. База стенда и список
баз после каждой серии прежние, копии удалены.

## Что сделано

- Launcher форм (`research/forms/form_launcher77.py`): `form_object` —
  `Справочник.<Вид>.ФормаЭлемента` (`ОткрытьФорму("Элемент.<Вид>", Контекст)`), `…ФормаГруппы`
  (`ОткрытьФорму("Элемент.<Вид>", Контекст, , 1)`), `Справочник.<Вид>.ФормаСписка.<Форма>`,
  `Журнал.<Имя>.ФормаСписка.<Форма>`; регистр букв не важен. Отказ до запуска 1С: новый элемент или группа
  подчинённого справочника, форма элемента справочника, который редактируется в списке.
- `form_window77`: окно дерева групп формы списка (`SysTreeView32`) — ID 4679 на своём месте в очереди окон;
  масштаб подбирается по положениям и размерам элементов вместе.
- `src/harness77/md77.py` — `platform_module`: имена модулей форм элемента, группы и списка справочника, формы
  журнала и формы отчёта в сообщениях 1С → файлы раскладки.
- `src/harness77/metadata77.py` — `Attribute.use` (поля 11 и 12 записи реквизита справочника),
  `Metadata.catalog` (владелец и способ редактирования справочника).
- `src/harness77/form77.py` — `FormContext` формы элемента или группы знает реквизиты другой формы;
  новое поле такого реквизита — отказ с его использованием в сообщении.
- `research/forms/probe_md_catalogs77.py` (серии проб; `probe_md_forms77.py` — форма без `ПриОткрытии`,
  строка ошибки, ожидание `blocked`), `scripts/verify_catalog_forms77.py`; тесты: `tests/test_md77_forms.py`
  (+4), `research/forms/tests` (+5).
- Документы: [контракты](../contracts.md) (`md-build`, `run`), [README](../../README.md),
  [README исследования форм](../../research/forms/README.md).

Установлено в 1С 7.7:

- Вызовы синтакс-помощника открывают формы конфигурации и передают модулю `Форма.Параметр`: новый элемент —
  `ОткрытьФорму("Элемент.<Вид>", Контекст)`, новая группа — с флагом группы 1, список и журнал — по имени формы.
- Имена модулей в журнале копии: `Справочник.<Вид>.Форма.Модуль` (элемент), `Справочник.<Вид>.Форма
  группы.Модуль`, `Справочник.<Вид>.ФормаСписка.<Форма>.Модуль`, `Журнал.<Имя>.Форма.<Форма>.Модуль`,
  `Отчет.<Имя>.Форма.Модуль`. Строка — строка модуля, как его собрал `md-build`.
- Окна формы списка нумеруются по правилу табличной части задачи 022 (`Browser`, колонки `Fixed`, первая —
  пиктограмма). Окно дерева групп — ID 4679 при любом месте в очереди (первым, вторым, третьим), номер
  своего места оно не отдаёт другим.
- Поле с именем реквизита на форме элемента показывает реквизит нового элемента.
- Для справочника, который редактируется в списке (поле 11 записи — 0: `ЕдиницыИзмерений`, `СтавкиНДС`),
  `ОткрытьФорму("Элемент.<Вид>")` возвращает пустое значение и форму не открывает, без ошибки. У справочников
  с полем 11, равным 1 (`Банки`, `НалогиИОтчисления`) или 2 (`Валюты`), форма элемента открывается.

## Ограничения и открытое

- Launcher открывает только новый элемент, группу и документ; существующий объект (нужны данные базы) —
  нет. Подчинённый справочник — отказ (нужен владелец).
- Форма группы справочника, который редактируется в списке, не проверялась и не отклоняется.
- Отказ по использованию реквизита нативно не проверен: такая форма не собирается `md-build`. Поле реквизита
  «для группы» на форме группы нативно не проверено: на стенде нет формы группы, куда его можно добавить
  (единственная — короче 255 байт, правило префикса длины задачи 008).
- Поле 11 записи справочника как способ редактирования выведено из корпуса и двух нативных наблюдений.
- Формы плана счетов, операций и проводок launcher не открывает; колонки (`Browser`) не меняются.
