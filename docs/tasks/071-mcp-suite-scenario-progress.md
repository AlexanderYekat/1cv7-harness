# Задача 071. Прогресс сценариев suite через MCP

Задача принята владельцем 10 ноября 2026 года.

С `_meta.progressToken` MCP сообщает начало сценария, его номер в наборе
и идентификатор. Сценарий сохраняет этот префикс в сообщениях об ожидании
копии, её подготовке, ожидании стенда и запуске 1С. Периодические сообщения
повторяют состояние ожидания. При переходе к следующему сценарию сервер
сбрасывает фазу. События записываются по порядку, поэтому между опросами
могут смениться сразу несколько фаз или сценариев.

## Нативная проверка

Проба отправила два запроса `suite` одному MCP-серверу на стенде 1С
7.7.027. Для управляемых задержек она удерживала штатные замок
`copy_path` и мьютекс COM-регистрации. Запросы имели отдельные
`progressToken`.

- В успешном наборе MCP показал «Первый сценарий» (1/2), ожидание
  `copy_path`, подготовку копии, ожидание стенда и запуск 1С в этом
  порядке. Отчёт зафиксировал 10,207 с ожидания копии и 10,391 с ожидания
  мьютекса. Оба ожидания дали периодические уведомления.
- Затем MCP показал «Второй сценарий» (2/2) и его запуск 1С. Все
  сообщения после перехода относились ко второму сценарию. Оба сценария
  прошли, каждый с одним `Initialize` и значением 42. Итоговый JUnit
  содержит два успешных testcase со ссылками и хешами дочерних отчётов.
- Второй запрос отменён через `notifications/cancelled` после сообщения
  об ожидании `copy_path` у сценария 1/2. После 0,570 с ожидания
  набор завершился с кодом 2. Замок остался у пробного владельца,
  launcher не стартовал. В итоговом JUnit один `error` с причиной
  `cancelled` и один `skipped`. Уведомлений о начале сценария 2/2
  для этого запроса не было.

Копия, замок и файл защиты удалены. Опись исходной базы, список баз,
COM-регистрации и процессы 1С совпали со снимками до прогона.
Сводка — `.artifacts/s71-native/verified.json`. Локальная проба
запускается командой `python -B .local/s71-verify.py <новый-суффикс>`.

## Проверка Windows CI

В [CI для 8ba65e0](https://github.com/AlexanderYekat/1cv7-harness/actions/runs/42769131299)
три Windows-задачи упали в одном тесте сохранения открытой копии.
Тест сравнивал короткий путь из `TEMP` с полным путём исполнителя и
пропускал имитацию занятой таблицы. Ошибка воспроизведена локально
на исходном тесте с путём 8.3. После нормализации пути в оснастке
все 26 целевых тестов прошли с тем же `TEMP`. Полный локальный
прогон на Windows с Python 3.13 выполнил 511 тестов, три пропущены.
