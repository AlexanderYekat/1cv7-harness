# Задача 107. Создание COMBOBOX в форме ERT

Поручение владельца — 16 ноября 2026 года. Продолжение принятого этапа

## Контракт

В описание существующего ERT-шаблона можно добавить элемент `COMBOBOX`:

```json
{"class":"COMBOBOX","identifier":"Список77","formula":"Выбор77()",
 "x":10,"y":130,"width":180,"height":75}
```

Обязательны уникальный идентификатор и геометрия. Имя связывает реквизит
формы с модулем: `Список77.ДобавитьЗначение(10, "Первый")` заполняет список,
`Список77.ТекущаяСтрока(1)` задаёт начальный выбор. Отдельная `Перем` с этим
именем запрещена, поскольку перекрывает реквизит формы.

Первый охват — неопределённый тип U, native CBS_DROPDOWNLIST (тип 3).
`type` опускается либо равен `{"kind":"undefined"}` без длины и точности.
Формула необязательна; если задана, проверяется существующий вызов процедуры
модуля или функции платформы. Пункты заполняет прикладной модуль; отдельного
языка описания пунктов нет. Заголовок и слой задаются по прежним правилам.
Версия схемы описания остаётся прежней, формат существующих элементов сохранён.

Высота включает раскрываемую часть списка. Вся эта область должна помещаться
в клиентскую область и не создавать новых наложений на элементы того же слоя.
Это консервативное правило размещения прежнего сборщика.

Не входят другие типы данных, редактируемый COMBOBOX, новые свойства существующего
списка, создание COMBOBOX внутри MD и создание целой формы с нуля.

## Проверка готовности

1. Создать новую ERT, перечитать описание, подтвердить тип, имя, формулу и
   геометрию. Сохранить неизвестные поля шаблона и посторонние потоки.
2. Открыть созданную ERT в настоящей 1С 7.70.027, проверить геометрию с допуском
   2 px, прочитать список через `inspect_combo`, выбрать пункт через `select`.
3. Проверить отсутствие вызовов при чтении и повторе текущего выбора, один
   вызов при смене выбора. Пустая строка и дубликаты читаются буквально.
4. Одинаковые входы ожиданий через run, CLI suite и stdio MCP дают
   passed/failed/passed/passed при baseline/regression/fixed/repeat-fixed.
   Контролируемая ошибка увеличивает счётчик обработчика на 2 вместо 1.
5. Suite продолжает работу после регрессии; JSON/JUnit согласованы, MCP
   отвечает на ping во время и после suite. SHA-256 snapshots сверены.
6. Исходная база, реестр, чужие процессы сохранены; копия и lock очищены.
   Переносимые тесты форм и пакета сохраняются.
