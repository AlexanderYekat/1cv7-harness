# Задача 105. Выбор значения COMBOBOX

Поручение владельца — 16 ноября 2026 года: реализовать выбор значения
COMBOBOX и завершить полный цикл через run, CLI suite и MCP.
Задача принята владельцем 16 ноября 2026 года; поручены публикация 0.12.0
и повтор полного цикла на скачанном релизном wheel.
[Результаты технической проверки](105-combo-selection-acceptance.md).

## Контракт

Шаг `{"select":"СписокТиповУслуг","text":"Оказание посредн. услуг в торговле"}`
разрешает элемент по идентификатору, затем подписи, как остальные UI-шаги.
Нужен ровно один COMBOBOX. `text` обязателен, сравнение пунктов точное,
с учётом регистра и пробелов; пустая строка допустима как текст реального пункта.
Префиксы, порядковые номера и неявный выбор первого совпадения не используются.

Нативный runtime читает список и текущий индекс, выбирает пункт через
CB_SETCURSEL и передаёт родителю CBN_SELCHANGE. Последнее сообщение выполняется
через существующую цепочку Pending: следующие dialog-шаги могут ответить
на модальное окно обработчика. Повтор выбора текущего пункта — проверенный
no-op без повторного вызова формулы. После обработки и обмена с 1С повторно
проверяются индекс и текст. Состояния до/после и факт уведомления сохраняются
в form-window.json. Контекст и сохранённые данные проверяются отдельно.

Поддержаны native drop-down COMBOBOX со строковыми пунктами (типы 2 и 3).
Простой постоянно раскрытый список и owner-draw без CBS_HASSTRINGS отклоняются.
Не более 1000 пунктов, не более 4096 символов в одном пункте.
Отсутствующий/неоднозначный текст, неправильный класс, скрытое/заблокированное
окно, чужой процесс/поток, неответившее сообщение и неподтверждённый выбор
дают явный отказ. Проверка владения выполняется перед каждым сообщением.

Основание уведомления: [Microsoft CBN_SELCHANGE](https://learn.microsoft.com/en-us/windows/win32/controls/cbn-selchange)
и [CB_SETCURSEL](https://learn.microsoft.com/en-us/windows/win32/controls/cb-setcursel).
Установка индекса сама по себе не посылает уведомление родителю.

## Приёмочный сценарий

[Отдельный пример](../../examples/combo-selection/README.md) использует
штатную форму «Оказание услуг» и четыре файловых входа схемы 4.
Fixture создаёт ТипУслуги=1 и две строки 1×50, 1×30.
UI проверяет исходный пункт, выбирает его повторно, меняет тип на
«Оказание посредн. услуг в торговле», записывает и переоткрывает документ.
Контекст формы и независимый reader должны дать ТипУслуги=2; строки и итог 80
остаются прежними.

Контролируемая ошибка заменяет только присваивание в обработчике
`ТипУслуги = СписокТиповУслуг.ТекущаяСтрока()` на `ТипУслуги = 1`.
UI меняет пункт, но после записи/reopen обнаруживает 1 вместо 2; reader
даёт ровно одно различие `/service_type`. Исправление возвращает исходный
модуль побайтно. Это внесённая ошибка, не дефект исходной конфигурации.

Готовность: baseline/regression/fixed/repeat-fixed дают
passed/failed/passed/passed через каждый из run, CLI suite и stdio MCP.
Сверяются raw JSON, JUnit, снимки четырёх входов, MD-потоки, сохранность
исходной базы, реестра и процессов, очистка копии и lock. Suite продолжает
работу после ожидаемого провала, MCP отвечает на ping во время и после suite.
Публикация релиза и приёмка владельцем — отдельные действия.
