# Приёмка задачи 022: формы 1Cv7.MD по описанию на копии базы

Дата: 22 октября 2026 года. Задание — [022-md-forms.md](022-md-forms.md). HEAD перед работой —
`076e7e3`, ветка `master`. Статус: **принято** владельцем 22 октября.

## Итог

Агент может изменить форму самой конфигурации — документа, справочника, отчёта, обработки — тем же
описанием, что и форму ERT (задачи 008, 011–013), и проверить её в настоящей 1С на копии базы.
`md-extract` кладёт рядом с модулем каждой формы описание её диалога (416 форм базы стенда, 334 —
«Торговли+Склада 9.2»), `md-build` пересобирает только изменённые диалоги. Поле с именем реквизита
объекта — поле этого реквизита: его тип обязан совпасть с типом реквизита. Launcher форм открывает
форму конфигурации по имени (`form_object`) и сверяет её с диалогом собранного `1Cv7.MD`.

Нативно на копии базы 1С показала собранные формы обработки и документа там и такими, как их
описали. Новая кнопка вызывает процедуру модуля формы. Новые поля передают значения модулю: строка,
число, флажок, ссылка вида `Справочник.Валюты`. Новое поле `РасчетныйСчет` формы документа
показывает реквизит документа. Визуальная проверка формы конфигурации различает неизменную и
сдвинутую кнопку. Ошибка компиляции модуля формы обработки — провал прогона с файлом и строкой.
Все 10 случаев на итоговом коде совпали с ожиданием (`f-doc-close` — наблюдение). База стенда и
список баз после каждой серии прежние, копии удалены.

## Что сделано

- `src/harness77/md77.py` — описания форм в раскладке (`<модуль>.json`, `read_forms`), индекс
  `modules.json` версии 2 (`forms`; версия 1 читается), форма без описания без потерь —
  `forms_not_described`; `md-build` пересобирает диалоги изменённых описаний в контексте
  конфигурации (`changed_forms`, `unchanged_forms`, `verification.changed_dialogs`); имя модуля
  формы обработки в сообщениях 1С — `Обработка.<Имя>.Форма.Модуль`.
- `src/harness77/form77.py` — `FormContext` формы конфигурации: экспорт глобального модуля для
  формул, поля реквизитов объекта (тип реквизита), отказы по реквизитам табличной части, встроенным
  реквизитам и смене привязки; табличная часть (`Multicolumn` раздела `Browser`) — препятствие
  размещения; новые записи сдвигают её место в обходе (`table_part_position`).
- `src/harness77/metadata77.py` — у реквизита длина, точность, номер вида и часть объекта.
- `run`: модуль изменённой формы проверяется как изменённый модуль (L7711 по новому диалогу);
  `visual approve` записывает хеш собранной конфигурации прогона.
- Launcher форм (`research/forms`): `form_object`, ожидаемый диалог и место табличной части из
  `1Cv7.MD` открытой базы, окружение снимка — конфигурация базы стенда; ID окон формы с табличной
  частью; поля без рамки в 1 px при подборе масштаба; ввод в ANSI-окно поля байтом Windows-1251;
  надпись с формулой не сверяется с подписью; при ненайденной форме — ID дочерних окон кандидатов.
  Launcher этапа 4 — точка `select_base` для адаптера.
- `lint` 0.6.0 (решение владельца после представления): L7711 — ошибка, когда известен и глобальный
  модуль конфигурации (модули самого `1Cv7.MD`, `--globals 1Cv7.MD`, `run`); без него —
  предупреждение, как раньше. `run` берёт глобальный модуль базы, на которой исполняется модуль:
  `[build] metadata` проекта, иначе `1Cv7.MD` базы стенда, с `[configuration]` — собранной
  (`static.global_module`; нечитаемый — `global_module_error`, не отказ). Статика настоящих профилей
  стенда (контрольный, КУДиР, пробы 011 и 022) с ним — без L7711.
- MCP: описания `md-extract`, `md-build` дополнены формами.
- `research/forms/probe_md_forms77.py`, `scripts/verify_md_forms77.py`; тесты
  `tests/test_md77_forms.py` (12), дополнения `test_visual77`, `research/forms/tests`.

Установлено в 1С 7.7:

- `ОткрытьФорму("Обработка.<Имя>"|"Документ.<Имя>", Контекст)` открывает форму конфигурации и
  передаёт её модулю `Форма.Параметр`, как форме ERT; новая форма документа открывается
  после `ВводНового`.
- Окна формы с табличной частью: 1С создаёт их с последней записи, табличную часть (`browse`,
  ID 4151) — после первых `B` окон (первое число раздела `Browser`), а её колонки занимают `C`
  номеров ID: у «Доверенности» `B` = 26, `C` = 4, окна 4152–4177 и 4182–4196. С `B` = 28
  (две новые записи) окна пошли по тому же правилу. По корпусу элементы выше табличной части
  среди последних `B` записей у 89% (база стенда) и 76% («Торговля+Склад») элементов.
- Поле с именем реквизита документа показывает реквизит документа.
- Окно поля `1CEDIT`/`BMASKED` на 1 px больше записи с каждой стороны (14 полей двух задач).
- Начальный фокус — у последней записи; поле без фокуса не принимает текст, набранный
  сообщениями `WM_CHAR`, — формула другого элемента обновляет форму, и текст пропадает.
- 1С не компилирует модуль формы, читающий неопределённое имя («Переменная не определена»).
  Так и форма обработки `ВыборИзКлассификатораАдресов` самой базы стенда: строка 734,
  `глВладелецСпискаУлиц` (запуск `46d8f10e`, ожидание записано до прогона) — её `lint` 0.6.0 называет
  ошибкой L7711. Других L7711 в модулях базы стенда нет, у «Торговли+Склада» — ни одного.

| «Торговля+Склад 9.2» (только чтение) | 385 | 334, все описаны | байт в байт | изменены ровно 333; 1 — отказ по виду префикса длины | описания совпали | да |

Отказ по виду префикса — правило задачи 008: заголовок длиннее на 3 знака перевёл бы короткий
диалог (меньше 255 байт) из однобайтового префикса длины в `0xFF + uint16`, а такой случай в 1С 7.7
не проверен. Сборка `1Cv7.MD` с 413 изменёнными диалогами — 4 с.

## Ограничения и открытое

- Раздел `Browser` (колонки табличной части и списков) не описывается и не меняется, кроме места
  табличной части в обходе; новые формы и объекты, удаление элементов, поля встроенных реквизитов
  не поддерживаются.
- Launcher открывает формы документов, отчётов и обработок; формы справочников и журналов
  (элемент, группа, список) нативно не открывались. Имена их модулей в сообщениях 1С не проверены:
  ошибка привязывается к изменённому объекту по имени, без файла.
- Новые записи в обходе формы идут первыми (как в ERT с задачи 008).
- Тип в записи поля реквизита — копия; у 6 полей двух конфигураций она устарела после изменения
  метаданных. Какой тип берёт 1С для такого поля, не проверялось: существующим полям тип не меняется.
- Ввод сообщениями `WM_CHAR` доходит только до поля с фокусом; фокус launcher не переводит.
- Внешние обработки `ExtForms` базы стенда, проверенные с её глобальным модулем, дают 26 ошибок L7711
  в трёх обработках, написанных для других конфигураций (`ТорговоеОборудованиеФЗ54`,
  `ПоискКонтрагентаПоАдресу`, `TwoActOnOwnPage`): на этой базе они не компилируются.
- Эталон `md-open` утверждён исполнителем по поручению владельца после просмотра снимка, как в
  задаче 010.
