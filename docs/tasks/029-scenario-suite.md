# Задача 029: набор сценариев и JUnit XML

Дата: 7 ноября 2026 года. Предшествующая задача — [028](028-reference-choice.md).
Статус: **реализовано и проверено**
([отчёт](029-scenario-suite-acceptance.md)). Направление выбрано владельцем в чате.

## Результат и границы

`harness77 suite --suite suite.toml --stand stand.toml` последовательно запускает
существующие профили проектов через тот же исполнитель, что `run`. Каждый сценарий
имеет своё имя, новый `run_id`, сборку, сеанс, копию базы при `[configuration]` и
полный `run.json`. Общий сеанс 1С, общие данные между сценариями, параллельный запуск
и автоматические повторы не входят в первый охват.

Манифест версии 1 содержит `[suite] id` и непустой список `[[scenarios]]` с `id`
и `project`. Имена сценариев уникальны; пути разрешаются от каталога манифеста.
Стенд один на набор, сроки разрешаются для каждого проекта как у `run`.

Корень результатов содержит `<suite_id>/suite.json`, `<suite_id>/junit.xml`
и общие `runs/<run_id>/`. Дочерние пути не удлиняются от имени набора:
глубокая вложенность воспроизвела `open_timeout` на закреплённой 1С 7.7.
Общий JSON связывает сценарий с прочитанным с диска `run.json` и SHA-256.
Один сценарий — один JUnit testcase: `passed` без дочернего исхода, `failed` →
`failure`, `blocked` → `error`, незапущенный → `skipped`. Ожидаемый отрицательный
исход учитывается по итоговому статусу `run`, а не по сырому ответу операции.
JUnit сохраняет кириллицу, экранирует разметку и заменяет недопустимые XML-символы.

Коды: 0 — все прошли; 1 — есть провал без блокировки; 2 — есть блокировка,
отмена или незапущенные сценарии. Итоги сохраняются до первого запуска и после
каждого сценария. Промежуточный отчёт помечен `complete = false`, кодом 2.
После обычного провала или ошибки входа одного проекта набор продолжается.
Отмена передаётся текущему `run`, остальные получают `skipped`. Если после запуска
не подтверждены завершение сеанса, удаление копии, отпускание блокировки или
сохранность источника, дальнейшие сценарии не запускаются. `keep_copy = true`
для наборов отклоняется до запуска: следующему сценарию нужна свежая копия.

## Проверка (ожидания до выполнения)

- Переносимо: несколько настоящих циклов через simulation, смешанные исходы,
  ожидаемый отрицательный тест, относительные пути, дубликаты и пустой набор,
  отсутствующий профиль/результат, чужой run_id, отмена, очистка и остановка,
  корректность XML/счётчиков/ссылок, CLI и MCP.
- Нативно: пример с формами задач 025–028 на закреплённом стенде, отдельная копия
  на сценарий; совпадение JSON, JUnit и дочерних отчётов. Дополнительный набор
  содержит намеренный провал и успешный следующий сценарий.
- Регрессии продукта, форм и контроллера; сборка/установка пакета без сети.

Результаты и фактические ограничения фиксируются в отдельном отчёте приёмки.
