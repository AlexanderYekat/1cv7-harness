# Задача 058. Отмена ожидающего запуска через MCP

Задача принята владельцем 9 ноября 2026 года.

Проверка 057 вызывала нативный launcher напрямую. В 058 один настоящий
сервер `harness77 mcp` принял два параллельных запроса `run` на разных
копиях базы 1С 7.7.027. Тестовый адаптер удерживал первый клиент после
`check` и отмечал каждый вызов `Initialize`. Профили запусков, запросы
MCP и нативные отчёты сохранены в `.artifacts/stage58-native`.

Второй запрос отменён через `notifications/cancelled` после того, как он
дошёл до ожидания мьютекса. MCP создал свой файл отмены, CLI передал
отмену launcher. В `run.json` второго запуска зафиксированы `blocked`,
`cancelled=true` и код 2. Launcher ждал 1,066 с и не получил мьютекс.
CDB, 1С и клиент не стартовали, временные COM-ключи не создавались,
вызовов `Initialize` было ноль. MCP-ответ для отменённого запроса
подавлен согласно контракту.

PID и COM-ключи первого сеанса сохранились. После сигнала тестового
адаптера он выполнил `execute`, вернул 42 и штатно закрылся. MCP вернул
успешный ответ для первого запроса.

Третий `run` повторно использовал копию отменённого запуска. Он дождался
освобождения мьютекса сторонним сеансом, выполнил один `Initialize`,
вернул 42 и штатно закрылся. MCP завершился с кодом 0. Тестовые копии,
замки и временные записи удалены, исходная база совпала с описью до пробы.

Сводка — `.artifacts/stage58-native/verified.json`. Локальная проба
запускается командой `python -B .local/s58-verify.py <новый-суффикс>`.
45 тестов MCP, CLI и нативного backend прошли.
