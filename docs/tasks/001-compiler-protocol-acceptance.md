## Исправления после ревью

На прежней ревизии воспроизведены два падения D07 при настоящем 8.3 TEMP:
подмена проверки родителя не срабатывала, а сообщение об остатке содержало
разрешённый длинный путь вместо короткого. Каталог тестов теперь разрешается
через `.resolve()`. В новой ревизии полный набор повторно выполнен с TEMP,
TMP и TMPDIR в формате 8.3: **45 тестов, 42 прошли, 3 прежних пропуска,
0 ошибок, 0 падений**. Скрипт проверяет, что дочерний Python действительно
использует короткий путь.

Также воспроизведён `failed` с несериализуемым номером из 4301 цифры.
ТЗ версии 1.1 задаёт максимум 640 значащих цифр после удаления ведущих нулей.
Преобразование по частям удалено; настройки защиты Python не меняются.
Границы 640/641, числа из 4301 и 400000 цифр, длинные ведущие нули проверены
в API и CLI. Превышение даёт полный `blocked` JSON, исходный текст сохраняется.
При лимитах Python 640, 4300 и 0 API остаётся JSON-совместимым.

Исправлены двойная точка в сообщении и описание происхождения кодировки
в manifest; байты P1/P2 и их эталоны не изменились. Сокращения CLI `--out`,
`--enc`, `--for` теперь отклоняются. Добавлен реальный тест directory junction:
запись поверх входа, в том числе через другой регистр, запрещена; публикация
в отдельный файл через junction работает. Тест не заменяет проверки symlink.

Скрипт приёмки E02/E03 перенесён в отслеживаемый корневым Git каталог `scripts`.
Оригинальный корпус нужен только при явном `--original-corpus`; основной
переносимый запуск требует Python, Git и отдельный checkout devtools.

После коммита создан отдельный временный каталог `<TEMP>` и выполнено:

```powershell

git -C <TEMP>\devtools checkout --detach 10cff1685276483b6fe0881ae7a30ae9b07e8759
```

Получено `true`; пользовательские настройки Git не менялись. SHA-256 файлов
после checkout совпали с manifest. Оба набора повторно запущены из `<TEMP>`,
то есть **снаружи** checkout, с абсолютным путём к каталогу тестов:

```powershell

python -B -m unittest discover -s <TEMP>\devtools\tests -p test_lint77.py -v
```

Результат повторён: 45 тестов парсера / 3 пропуска / 0 ошибок / 0 падений;
31 тест линтера / 0 пропусков / 0 ошибок / 0 падений. Корпуса `research` рядом

Воспроизводимый скрипт доступен в Git:
[scripts/verify_compiler_protocol77.py](../../scripts/verify_compiler_protocol77.py).


Для другой структуры каталогов передать `--repo PATH`. Скрипт проверяет
зафиксированную ревизию, а не незакоммиченные изменения. Дополнительные проверки

## Пропуски и границы приёмки

Три теста символических ссылок пропущены из-за `WinError 1314`: текущая учётная
запись Windows не имеет привилегии создания symlink. Это проверки:

- ссылки выхода на вход;
- ссылки входа и публикации в разрешённую цель ссылки выхода;
- отказа при циклической ссылке.

Эти сценарии **не объявляются проверенными** на текущей машине. Техническое ТЗ
разрешает явно отмечать недоступность symlink; обязательные реальные проверки
hard link и регистра Windows, а также дополнительная проверка junction прошли.
Код разрешения символических ссылок
присутствует; отдельная среда с правом их создания нужна для снятия ограничения.

Дифф devtools ограничен 11 файлами результата: парсер, инструкция, дополнение
README, `.gitattributes`, тест и шесть файлов fixtures. `lint77.py`, его тесты,
`ert_module.py`, синхронизация и 77MCP не изменены. Исторический
`docs/baseline.json` и оригинальные протоколы не редактировались.

Следующее задание — **шаг 2: эксперимент с настоящей 1С 7.7**. Этот результат
импортирует протокол ошибок; он не подтверждает автоматическое управление
платформой, успешную компиляцию, связь с текущей ERT или исполнение тестов 1С.
