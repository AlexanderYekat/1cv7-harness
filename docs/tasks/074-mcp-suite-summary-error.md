# Задача 074. Падение suite и провал теста в MCP

Задача принята владельцем 10 ноября 2026 года.

Для кодов 0 и 1 MCP проверяет итоговую сводку `suite` из stdout.
Она должна подтверждать завершение набора, содержать согласованные
статус, код и счётчики сценариев, совпадать с запрошенным `suite_id`
и содержать сведения об итоговом JUnit. При ошибке MCP выставляет
`isError=true`, сохраняет фактический код и потоки CLI и добавляет
пояснение в `content`.

## Нативная проверка

Два набора из двух сценариев запускаются через один MCP-сервер на
1С 7.7.027. В первом проба аварийно завершает только тестовый CLI
с кодом 1 сразу после публикации результата первого сценария.
Во втором первый сценарий ожидает 43, а реальная 1С возвращает 42.
Второй сценарий этого набора ожидает и получает 42.

## Результаты

- После падения MCP вернул фактический код 1, `stdout=null`,
  `isError=true` и пояснение о сводке. В промежуточных JSON и JUnit
  сохранён успех первого сценария. У набора `complete=false`, второй
  сценарий остался без `run_id`. Тот же MCP-сервер ответил на `ping`
  и принял следующий запрос.
- При штатном провале MCP вернул код 1, `status=failed`,
  `complete=true` и `isError=false`. Первый сценарий получил 42
  вместо 43, второй прошёл с результатом 42. В итоговом JUnit один
  `failure` и один успешный testcase. Ссылки и SHA-256 дочерних отчётов
  совпали, хеш JUnit соответствует сводке.

Все три нативных запуска вызвали `Initialize` по одному разу.
Промежуточные отчёты первого набора сохранились при втором запуске.
Копия, замок и временная регистрация удалены. Опись источника и
снимки COM-регистраций и процессов совпали с исходными. Прошли 49
автоматических тестов MCP и suite.

Сводка — `.artifacts/s74-native/verified.json`. Локальная проба
запускается командой `python -B .local/s74-verify.py <новый-суффикс>`.
