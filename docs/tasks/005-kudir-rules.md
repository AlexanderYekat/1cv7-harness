# Этап 5, задача 005: КУДиР — каталог платформы и правила из подтверждённых случаев

Дата: 15 октября 2026 года. Предшествующий этап — [полный цикл](004-full-cycle.md).
Приёмка — [005-kudir-rules-acceptance.md](005-kudir-rules-acceptance.md).

## Зачем

КУДиР — первый прикладной проект-потребитель. Его [опыт](../../research/kudir/README.md)
содержит ошибки, которые настоящая 1С 7.7 нашла, а `harness77 lint` — нет.
На корпусе КУДиР линтер сейчас ловит P2 (7 из 7 строк, L7706), но в P1 не видит
ни одного корня: параметр `Знач Строка` (строки 63, 66, 304) и реквизит формы
`выбУровеньЛога`, прочитанный до объявления (101, 107). Лишний аргумент
`Опер.ПолучитьПроводку(н)` и строка в 590 символов тоже проходят молча.
Словарь встроенных функций ведётся вручную (254 имени, «начальный, неполный»),
хотя полный справочник есть в установленной платформе.

Задача превращает эти случаи в каталог и правила анализа. Каждое правило
получает отрицательный, положительный и пограничный пример, а уровень
серьёзности — по результату настоящей 1С 7.7, а не по догадке. Прикладные
правила КУДиР (выгрузка, проводки, CSV) в универсальный линтер не переносятся.

## Охват

1. **Каталог платформы — `harness77 catalog`.** Извлечь из `BIN\1cv7Lang.als`
   имена (рус./англ.), вид (ключевое слово, глобальная функция, константа,
   метод, атрибут, предопределённая процедура), папку, компоненты (`A`/`S`/`T`)
   и число параметров каждой сигнатуры по шаблону и строке `@Синтаксис`
   (`...` — без верхней границы). Из строковых ресурсов `1crcrus.dll` —
   пары `English,Русское`. Описания и шаблоны текста не сохраняются.
   Происхождение: имя, размер, SHA-256 каждого файла, версия платформы.
   Одинаковые входы дают одинаковые байты. Выход новый, как у `build`.
   Каталог для 7.70.027 входит в пакет и используется линтером.
2. **Правила `lint`:**
   - **L7708** — имя встроенной функции 7.7 как параметр, `Перем`, счётчик
     `Для` или цель присваивания;
   - **L7709** — у вызова `.Метод(…)` аргументов больше, чем в любой
     сигнатуре метода в каталоге;
   - **L7710** — физическая строка исходника длиннее защитного предела;
   - **L7711** — чтение переменной, не объявленной к этому месту процедуры:
     не параметр, не `Перем`, не присвоена выше по тексту, не реквизит
     диалога и не глобальное имя.
   Словарь L7704 дополняется именами каталога; прежние правила и коды не меняются.
3. **Контекст формы.** Для L7711 нужны идентификаторы диалога. ERT даёт их сама;
   текстовому модулю их даёт `lint --dialog ФОРМА.ert`, а `run` — шаблон сборки.
4. **Нативное подтверждение.** Пробы на закреплённом стенде через
   `harness77 run` (по одной ERT на случай) и одна пакетная проба
   `ВыполняемыйМодуль` 1С++ по всем встроенным именам. Ожидания записываются до
   прогона; итог хранится файлом свидетельств.
5. **Регрессия на корпусе КУДиР.** Скрипт сверяет хеши локального корпуса
   и ожидания: P1 — корни на 63, 66, 304 и 101, 107; P2 — прежние 7 строк;
   OK1/OK2 — без новых ошибок. Корпус остаётся локальным; в Git — только
   синтетические примеры.

**Не входит:** изменение проектов КУДиР и 76.АВ, правила о проводках, CSV
и данных; долгий нативный прикладной отчёт (прогон владельца, см. этап 4);
каталог сообщений компилятора и разметка `root`/`cascade` протокола;
формы и NKDK (этап 5.1).

## План нативных проб

Стенд `local-7.70.027`, база `base-for-test`, шаблон с диалогом
(`Фамилия`, `Имя`, `Отчество`), кооперирующий модуль этапа 4. Ожидание до
прогона: **ошибка** — компиляция отклонена; **успех** — загрузка и исполнение;
**?** — исход неизвестен, проба его устанавливает.

| Группа | Случай | Ожидание |
|---|---|---|
| L7708 | `Знач Строка` (повтор P1) | ошибка |
| | параметр `Число`, `Перем Дата`, `Мин = 1`, `Для Макс = …` | ? |
| | `Знач Строка1`, `ПолучитьПроводку = 1` (имя метода) | успех |
| | пакет: каждое встроенное имя как параметр и как переменная | ? |
| L7709 | `ТЗ.КоличествоСтрок(1)` | компиляция проходит, исполнение — ошибка |
| | `ТЗ.КоличествоСтрок()` | успех |
| L7710 | строка-комментарий и строка с литералом длиной 600 | ? |
| L7711 | чтение необъявленного имени; чтение до присваивания | ошибка |
| | присвоено только в другой процедуре | ? |
| | присвоено в теле модуля после процедур | ? |
| | `Перем` модуля; реквизит диалога `Фамилия` | успех |
| | `Фамилия2` (нет в диалоге) | ошибка |
| | необъявленное имя как аргумент метода и своей процедуры | ? |
| | глобальные имена: `Константа`, `Перечисление`, `Метаданные`, `ФС`… | успех |

Уровень правила: **error** — отказ подтверждён в 7.7 и ложных срабатываний
на корпусе нет; **warning** — подтверждён механизм, но контекст может быть
неполным (COM, 1С++, глобальный модуль), `--strict` делает его ошибкой.
Если 7.7 конструкцию принимает, правило не вводится или сужается.

## Приёмка

Переносимо: каталог из синтетических `.als` и PE-ресурса; повторная
генерация даёт те же байты; пакетный каталог совпадает с генерацией из
установленной платформы (если она есть); у каждого правила отрицательный,
положительный и пограничный тест; все прежние тесты проходят; каталог
входит в wheel. Нативно: таблица выше заполнена исходами настоящей 1С 7.7,
завершение своих сеансов подтверждено, чужие сохранены. На корпусе: P1 —
все пять корневых строк, P2 — 7 из 7, OK1/OK2 — без новых ошибок.
Успех линтера по-прежнему не означает успешной компиляции.
