# Приёмка задачи 014: MCP-сервер над операциями CLI

Дата: 20 октября 2026 года. Статус: **принято**, дополнено проверкой владельца в Claude Code
(C4, C5, N1c, N1d — по его просьбе её выполнил исполнитель). Задание — [014-mcp-server.md](014-mcp-server.md).
Исходный HEAD: `060b4ee`.

## Что реализовано

- **`harness77 mcp`** (`src/harness77/mcp77.py`) — сервер MCP на stdio без новых
  зависимостей: JSON-RPC 2.0, по одному сообщению на строку, рукопожатие
  `initialize` (`2025-11-25` … `2024-11-05`), методы `ping`, `tools/list`,
  `tools/call`, уведомления `initialized` и `cancelled`. Клиенты ревизии `2026-07-28`
  получают `-32601` на `server/discover` и переходят к `initialize`.
- **Восемь инструментов — команды CLI** с теми же ключами: `lint`,
  `compiler-protocol`, `triage`, `extract`, `form-extract`, `build`, `run`,
  `visual-compare`. Каждый вызов — дочерний процесс `python -m harness77 <команда>`
  в рабочем каталоге сервера; ответ — `exit_code`, `stdout`, `stderr` (JSON
  операции или текст), `argv`, `cwd`, `duration_s` в `structuredContent` по
  `outputSchema` и тем же JSON в тексте; `isError` при коде вне 0 и 1. Неверные
  аргументы — `isError` без процесса. `catalog` и `visual approve` в MCP не входят.
- **Долгие вызовы и отмена:** вызовы параллельны (`ping` отвечает во время `run`),
  прогресс каждые 10 с по `progressToken`; `notifications/cancelled` и закрытый stdin
  отменяют `run` новым ключом `run --cancel-file` (как Ctrl+C), остальные операции
  доходят до конца; на отменённый запрос ответа нет.
- **Launcher этапа 4:** `cscript.exe` по `WINDIR`, иначе `SYSTEMROOT` — клиент SDK
  не передаёт серверу `WINDIR`.
- Контракт — [contracts.md](../contracts.md#mcp-сервер--команда-mcp-задача-014).

## Границы

- **Выход из клиента во время `run`.** Claude Code (C3) и клиент SDK снимают сервер
  вместе с `run`, launcher, cdb и своей 1С: 1С останавливается принудительно,
  временная регистрация COM launcher по его устройству остаётся (не воспроизводилось
  на базе), следующий запуск launcher откажет до её удаления. Штатный путь остановки —
  отмена вызова (N2). Защита — следующей задачей по решению владельца.
- **Подключение из Windows PowerShell.** `claude` там — это `claude.ps1`, а PowerShell
  не передаёт скрипту `--`: `claude mcp add harness77 -- python -m harness77 mcp`
  отвечает `unknown option '-m'`. Работает `claude.cmd mcp add harness77 -- python -m harness77 mcp`
  (README).
- **Launcher этапа 4 под нагрузкой** (не MCP; так же через CLI): cdb даётся 20 с на запуск
  своей 1С — на загруженной машине один раз не хватило (C5, второй), отказ до 1С;
  начало остановки 1С launcher видит только в начале круга опроса — при остановке
  за 0,4 с он её пропустил и дал `blocked` «shutdown deadline was not armed» после
  штатного выхода 1С (N1c). Ни одно не оставило следов; изменение проверок launcher —
  отдельной задачей по решению владельца.
- **Общая регистрация COM.** Задания другого проекта владельца (`kudir`) ставят те же
  ключи `Harness77Diagnostic.*`; пока такое задание идёт, launcher harness77 по своему
  устройству откажет (не перезаписывает чужую регистрацию). C5 ждала окончания такого
  задания.
- Проверены один стенд, одна база, шаблон `FIO.ERT`, клиенты Python SDK 2.3.0 и
  Claude Code 2.1.304 на Windows 11.
- Ревизия `2026-07-28` на стороне сервера, ресурсы и подсказки MCP, HTTP, пакеты
  JSON-RPC и CI не реализованы.
