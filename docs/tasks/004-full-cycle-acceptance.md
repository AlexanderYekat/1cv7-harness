# Приёмка этапа 4: первый полный цикл

Дата: 15 октября 2026 года. Статус: **принято в описанном охвате; долгий
прикладной нативный отчёт остаётся отдельным прогоном владельца.**
Задание — [004-full-cycle.md](004-full-cycle.md). Исходный HEAD ветки: `80d9a54`.

## Что реализовано

Команда `harness77 run` поверх существующих операций. Прежние `lint`,
`compiler-protocol`, `extract`, `build` не изменены. Новые модули пакета:

- `deadlines77` — раздел 8.5: пять отдельных сроков, проверка согласованности до
  старта, внешние монотонные часы, абсолютный срок фазы, тишина и прогресс срок
  не меняют;
- `config77` — профили проекта и стенда (TOML), разрешение путей от каталога
  профиля, запрет хранить пароль, редактирование машинных путей и имени
  пользователя в отчёте (имя базы + SHA-256-тег пути);
- `report77` — сборка общего отчёта, свидетельства файлов (размер, SHA-256,
  `complete`), атомарная запись, коды выхода;
- `backends77` — общий драйвер фазы `drive_phase` и бэкенды `simulation`
  (сценарный, для тестов и сред без 1С) и `import` (сохранённый протокол как
  свидетельство); оба всегда `platform_checked=false`;
- `native77` — нативный бэкенд: строгая предпроверка стенда, вызов launcher,
  переcверка файлов результата по диску, запрет вывести успех из выхода процесса;
- `screenshots77` — политика владения окном, запись свидетельства, захват GDI
  (нативно);
- `run77` — оркестратор: run_id, отдельный каталог, связывание по хешам,
  статусы/коды, обработка Ctrl+C.

Нативный мост — `research/platform77/stage4_launcher77.py`: переиспользует
принятый контроллер `session77.run_session` (владение процессом до Initialize,
отдельный desktop, завершение coordinated-icpp-v1, сохранность чужих сеансов) и
пишет `platform-result.json` в контракте нативного бэкенда. Сроки раздела 8.5
применяются в процессе launcher; прототипные 30/145 с в общее ядро не вынесены.

## Воспроизведение

Установка и переносимая проверка (без 1С):

```powershell
python -m pip install --no-build-isolation -e .
python -B -m unittest discover -s tests -v
python scripts/verify_package77.py
```

Переносимый полный цикл (симуляция, мгновенно):

```powershell
harness77 run --project examples/full-cycle/project.toml --stand examples/full-cycle/stand-simulation.toml --output-root .artifacts/runs
```

Нативный полный цикл (реальная 1С 7.7, закреплённый стенд):

```powershell
harness77 run --project .local/stage4-native/project.toml --stand .local/stage4-native/stand-native.toml --output-root .artifacts/runs
```

Профили `.local/stage4-native/*` локальны (машинные пути); образец —
`examples/full-cycle/stand-native.toml.example` и кооперирующий
`examples/full-cycle/module.1s`.

## Границы и минимальное действие владельца

Нативно подтверждён **короткий** полный цикл и его отказы на закреплённом стенде.
**Не выполнены нативно** и остаются прогоном владельца, так как требуют
прикладных данных и запуска на десятки минут против рабочей базы:

- реальный прикладной отчёт длительностью десятки минут с периодами без сообщений;
- полный большой результат из реального отчёта с проверкой содержимого;
- ошибка записи результата в нативном прогоне;
- превышение срока и пользовательская отмена во время настоящего долгого расчёта,
  включая принудительное прерывание блокирующего вызова.

Эти свойства проверены **переносимо** (симуляция, детерминированно), но симуляция
и короткий прогон не доказывают часовые расчёты. Для нативного подтверждения:
задать в профиле проекта реальные данные, ожидаемый результат, контрольный объём
и увеличенные сроки, затем выполнить `harness77 run` с нативным стендом (у владельца
уже есть launcher долгих выгрузок КУДиР, поднимающий сроки ядра в своём процессе).
Короткий нативный цикл использует принятые пределы ядра (операция до суммы
open+calculation, сеанс до total); расширение на произвольную прикладную обработку
требует собственного обоснования и нативных свидетельств. Поддержка часовых
расчётов до соответствующего прогона не заявляется.
