## Реализация и поставка

Профиль схемы 4 принимает steps_file в platform.parameters и expect_json_file
в тесте. Общий загрузчик разрешает пути от профиля, проверяет UTF-8/JSON,
конфликты и структуру. Перед execute файлы читаются снова даже у сохранённого
ProjectProfile; после чтения используются зафиксированные значения.
Файловые ошибки наследуют InputFileError, suite безопасно отклоняет такой
сценарий до создания run и продолжает по прежней политике.

В input-files/steps.json и test-NNNN.expected.json сохраняются точные байты;
inputs.json_files и result_files содержат роль, индекс теста, источник,
размер и SHA-256. Переводы строк эффективного текста нормализуются в LF.
Fixture/reader сохраняют отдельные fixture-inputs и прежний контракт.
При inline входах отсутствуют новые json_files и каталоги снимков JSON.

project-init копирует источники относительно scenario.json, обновляет
локальные ссылки и выбирает схему 4. Один expected получает expected.json,
несколько — отдельные expected-NNNN.json. Встроенные схемы 1–2 и файловая
схема 3 остаются совместимыми. [Реальный запуск опубликованной 0.9.0](../../.artifacts/s103-evidence/old-090-schema-guard.json)
отверг схему 4 до платформы, без каталога результатов.

Локальный wheel 0.10.0 собран из sdist; SHA-256
`b8d1d28e673dccac0353152a2dc876d1b6f01416699dfa666760a7fadd16894e`.
Публикация не выполнялась. Первоначальная [проверка поставки](../../.artifacts/s103-package/summary.json)
завершился passed: 635 тестов установленного пакета — OK, skipped=5;
console lint, compiler-protocol P1=60/P2=7 и все 33 нативных файла проверены.
[Лог тестов](../../.artifacts/s103-package/installed-tests.log).
После исправления проверяющего скрипта [финальная поставка](../../.artifacts/s103-package-final/summary.json)

[полный лог](../../.artifacts/s103-package-final/installed-tests.log).
Все [73 файла кода и ресурсов двух wheel побайтно равны](../../.artifacts/s103-evidence/build-identity.json);
39 файлов исходного пакета совпали с рабочим деревом. Правка относится

## Нативный сценарий

В предварительной серии при ревью найден неверный подсчёт расхождений
в проверяющем скрипте: шаг количества 3→4 меняет также /rows/1/quantity,
поэтому расхождений пять, а не четыре. Основной expected был корректен.
Серия штатно отменена через собственный MCP cancel-файл и не включается
в финальную квалификацию. [Результаты сохранены, очистка и сохранность
стенда проверены](../../.artifacts/s103-evidence/initial-series-cancellation.json).
Финальная серия начинается в новом проекте с исправленным проверяющим скриптом.

Отдельный проект — C:/MyProjects/h77-103-final/, результаты —
C:/MyProjects/h77-103-final-cycle/. Выбранный wheel включён в проект и установлен
в его изолированный cache/venv. Пустой harness77.txt и локальный launcher;
PYTHONPATH/PYTHONHOME отсутствуют, user site отключён. База, компоненты,
платформа, CDB, шаблон и контроллер заданы явно.

Основная серия: исходник, ошибка +1, исправление и повтор с теми же четырьмя
файлами и тестами. Дополнительно встроенная 101 схемы 2 и файловая 102 схемы 3
через run, CLI suite и stdio MCP. Контроли неверной подписи первого открытия
и reopen сохраняются. Прямое открытие фактуры, точная ссылка при reopen
и динамическая подпись «Печать» проверяются прежним способом.

Прежние пробы fixture/reader и 21 отрицательный вход 102 повторяются.
Новые 33 отказа: отсутствующие steps/expected, повреждённые steps/expected,
неверная структура steps, конфликты каждой роли, схема 3 с файловыми JSON,
кодировка, пустой файл и каталог — через каждый интерфейс. Тот же живой
MCP после них выполняет правки и восстановление.

Новые девять нативных проб: steps меняет количество второй строки 3→4,
UI правильно читает 120/170, старое expected даёт пять расхождений;
правка только expected.total 140→141 даёт одно расхождение при правильном UI;
восстановление возвращает passed. Каждый вариант — через run, CLI suite и
живой MCP при неизменном профиле, без project-init и перегенерации.

## Полученные результаты

Основной цикл дал passed / failed / passed / passed через каждый интерфейс.
Регрессия +1 обнаружена с четырьмя прежними расхождениями; исправленный MD
побайтно равен исходному. Обе основные suite завершились с 5 passed,
1 failed, 0 blocked, 0 skipped: единственный failed — запланированная
прикладная ошибка. Два отдельных контроля подписи дали ожидаемые failed.

Встроенная 101 и файловая 102 прошли через run/suite/MCP. Прикладные raw JSON
и MD совпали с исходным вариантом опубликованной 0.9.0; основной цикл
и результаты проб fixture/reader совпали с принятой 102. Эффективные
параметры/тесты всех трёх форматов равны. Один scenario.json во всей серии,
SHA-256 `11d425f0bb98cffbabf2677e79380f0799cb29704f628d954839698835597e59`.

Новые девять запусков JSON-правок дали failed / failed / passed у каждого
интерфейса. Изменённые steps реально сохранили количество 4 и суммы 120/170,
все 25 UI-шагов прошли; прежний expected дал пять расхождений, включая
/rows/1/quantity. Правка только expected.total дала одно расхождение
141/140 при правильном UI. Восстановление — passed. Повторных project-init
и перегенерации не было: SHA-256 того же профиля не менялся, project.toml
и scenario.json сохранены. Все четыре исходных файла восстановлены.

Все 54 неправильных входа дали blocked до 1С, у suite не появился дочерний
run. JSON-пробы прошли через тот же живой MCP после 33 отказов; fixture-пробы
также сохранили работоспособность своего MCP после 21 отказа. Ping успешен;
все три сервера штатно завершились с кодом 0. JSON/JUnit согласованы.

Независимый verifier перечитал все 38 запусков — passed. Дополнительный
аудит сверил 134 точных снимка: 70 fixture/reader в 35 запусках и 64 JSON-входа
в 32 запусках. Хеши/размеры совпали с метаданными; тела fixture/reader найдены
в фактических контроллерах, каждый JSON-шаг сопоставлен с нативным планом
по индексу, операции, цели и всем исходным параметрам. Ожидания совпали
с эффективными тестами. Встроенные варианты не создают лишних снимков.

Прямое открытие/reopen и «Печать» проверены, кода и артефактов журнала нет.
Источник, реестр и список процессов совпали до/после, копия и lock очищены,
forced_cleanup=false. Начальный список чужих сеансов был пуст; совместная
работа с активным чужим сеансом этой серией не подтверждается.
Квалификация ограничена прежним стендом Windows / 7.70.027 / DLL / DBF.
