# Задача 072. Отмена второго сценария suite в очереди стенда

Задача принята владельцем 10 ноября 2026 года.

Если launcher подтверждает отмену до захвата мьютекса стенда,
`suite` сохраняет причину `cancelled` в строке сценария и в JUnit.
Список чужих процессов launcher снимает после захвата мьютекса,
поэтому для этой отмены достаточно подтверждения очистки launcher
без принудительного завершения. Удаление подготовленной копии,
освобождение замка и сохранность источника проверяются отдельно.

## Нативная проверка

Через один MCP-сервер на 1С 7.7.027 запущены `suite` с тремя
сценариями и отдельный `run` на другой временной копии той же базы.
Пока первый сценарий удерживал стенд, отдельный запуск встал в
очередь мьютекса. После штатного выхода первого сценария отдельный
запуск занял стенд. Его launcher удерживал разрешение на
`Initialize`, пока второй сценарий ожидал мьютекс.

- Первый сценарий вызвал `Initialize` один раз и вернул 42. Хеш его
  `run.json` до отмены совпал с хешем в итоговых JSON и JUnit.
- После сообщения MCP «сценарий 2/3 … ждёт освобождения стенда»
  клиент отправил `notifications/cancelled`. Через 0,783 с ожидания
  второй сценарий завершился без захвата мьютекса, старта CDB, 1С
  и OLE-клиента. Launcher подтвердил очистку. Подготовленная копия
  сценария удалена, её замок освобождён.
- Итоговый набор завершился с кодом 2. В JUnit первый testcase
  успешен, второй содержит `error` с причиной `cancelled`, третий —
  `skipped`. Для третьего сценария нет `run_id` и уведомлений о начале.
- Во время отмены у владельца стенда сохранились четыре процесса,
  обе COM-регистрации, метка, замок, опись 855 файлов и хеш `1Cv7.MD`.
  После снятия паузы владелец вызвал `Initialize` один раз, вернул 42
  и штатно завершился.

Снимки исходной базы, списка баз, COM-регистраций и процессов 1С
после прогона совпали с исходными. Обе временные копии и их замки
удалены. Прошли 47 автоматических тестов suite и MCP.

Сводка — `.artifacts/s72-native/verified.json`. Локальная проба
запускается командой `python -B .local/s72-verify.py <новый-суффикс>`.
