## Исправления после ревью

Ревью нашло два дефекта; оба воспроизведены, исправлены и закрыты тестами.

- **P1 — потеря входа.** `lint module.1s --dialog form.ert --output form.ert`
  заменял ERT отчётом и возвращал 0: `--dialog` не входил в защищённые пути.
  Теперь `--dialog`, `catalog77.json` и `lint77-globals.json` защищены так же,
  как входы, включая hardlink; команда возвращает 2, ERT не меняется.
- **P2 — пропуски L7708.** Перебор всех 162 имён нашёл 56 присваиваний без L7708
  (`Не = 1;`, `Возврат = 1;` и другие ключевые слова; по подсчёту ревью у 24 из них
  не было никаких диагностик): проверка цели присваивания стояла после пропуска ключевых слов.
  Шесть из 56 требовали отдельной правки: `Экспорт = 1;` и `Далее = 1;` первой
  строкой тела попадали во флаги заголовка, `КонецПроцедуры = 1;` закрывал
  процедуру. Ещё четыре пропуска были в других позициях: `Знач Знач` / `Val Val`
  в параметре и `Перем Экспорт;` / `Перем Export;`. Теперь присваивание
  распознаётся до ключевых слов, в `Перем` имя ожидается после `Перем` и запятой,
  имя параметра — последний идентификатор до `=`. Тест перебирает все 162 имени
  в каждой позиции пакетной пробы и в счётчике `Для`: пропусков нет.

После исправлений сверка `verify_kudir_rules77.py` дала побайтно тот же итог
(`699ddb1d…d2cd`): 31 из 31, корпус без изменений. 1С повторно не запускалась:
исправления касаются только линтера, нативные исходы прежние.

## Границы

- Успех линтера по-прежнему не означает компиляцию. Методы конфигурации, COM
  и 1С++ не проверяются; L7709 берёт наибольшее число параметров одноимённых
  методов разных объектов и не проверяет английские имена.
- Набор глобальных имён снят на бухгалтерской конфигурации стенда; другие
  компоненты могут добавить имена (`--allow`). Объявление проверяется только
  с известным диалогом; модули MD не проверяются.
- Точный предел длины строки в Конфигураторе не установлен: автоматизации
  Конфигуратора нет. 500 — защитный порог.
- Долгий нативный прикладной отчёт остаётся прогоном владельца (этап 4).
