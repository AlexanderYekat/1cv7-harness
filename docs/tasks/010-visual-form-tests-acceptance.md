# Приёмка задачи 010: визуальные тесты форм

Дата: 19 октября 2026 года. Статус: **принято.** Задание — [010-visual-form-tests.md](010-visual-form-tests.md).
Исходный HEAD: `ec70ab8`, ветка `master`.

## Что реализовано

- **Продукт.** `src/harness77/visual77.py`: PNG без новых зависимостей, сравнение
  по пикселям вне масок с допусками канала и числа пикселей, изображение различий,
  проверка среды снимка, эталоны с записью. Раздел `[visual]` профиля проекта,
  обязательный этап `visual` в `run` после `tests`, запрос снимков у стенда
  (`--captures-json`), снимки в результате платформы с перепроверкой файла с диска.
  `harness77 visual approve` — единственный путь к эталону; `harness77 visual
  compare` — сравнение двух PNG. Контракт —
  [contracts.md](../contracts.md#визуальные-тесты-формы--visual-и-команда-visual-задача-010).
- **Стенд** (`research/forms`): адаптер формы показывает скрытое главное окно
  своей 1С на своём desktop без активации (`ShowWindowAsync(SW_SHOWNOACTIVATE)`
  с перепроверкой идентичности процесса), снимает `PrintWindow` с
  `PW_RENDERFULLCONTENT` серией до двух совпадающих вне курсора, записывает
  прямоугольник курсора (`GetGUIThreadInfo` из потока на desktop сеанса), фокус,
  среду, и скрывает окно обратно. Launcher этапа 4 получил точки расширения
  `request_captures()` и `captures()`; по умолчанию запрос снимков — отказ.

## Границы

- Проверены один шаблон (FIO.ERT) и один стенд: Windows 11 26200, 96 DPI,
  тема Aero, ClearType, локаль 1049. Рамка окна на private desktop рисуется без
  DWM — эталон годится только для снимков того же способа.
- Среда записывается из параметров сеанса пользователя; смена DPI натурно
  не проверялась (V6 моделирует её записью эталона).
- Форма FIO не показывает данных базы. Для форм с данными нужна закреплённая
  копия базы: хеш конфигурации в среде есть, хеша данных нет.
- Состояния — только `open` и `clicked`; другие действия (ввод, выбор) не входят.
- Эталоны утвердил исполнитель после просмотра; владелец их ещё не смотрел.
