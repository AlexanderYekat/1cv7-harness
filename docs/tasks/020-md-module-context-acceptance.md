# Приёмка задачи 020: контекст модулей конфигурации и форм

Дата: 22 октября 2026 года. Задание — [020-md-module-context.md](020-md-module-context.md).
HEAD перед работой — `5f846fc`, ветка `master`. Принята владельцем 22 октября 2026 года.

## Итог

`harness77 lint` 0.5.0 знает контекст модулей `1Cv7.MD` и форм. Модуль конфигурации привязан
к своему объекту по номеру папки; модули документов и их форм, форм справочников и журналов,
отчётов, обработок и глобальный модуль проверяются L7711 (необъявленное имя), реквизиты владельца
читаются без объявления и ведут цепочку L7714 (`Договор.ВестиУчетРасчетовУЕ`). Контекст формы —
элементы диалога, столбцы списка, `Таблица` (если у формы есть таблицы) и именованные области
**таблицы формы**, которую называет `Container.Profile` (`MoxelName`). `'ОК'` — литерал даты.

На 385 модулях рабочей «Торговли+Склада 9.2» — 0 L7711 и 0 L7714 при 2834 сверенных обращениях
к реквизитам. На 422 формах `ExtForms` L7711 — 323 вместо 11 579: остальные 11 246 были
областями таблиц форм, а оставшиеся — глобальные переменные чужих конфигураций. На урезанной
базе стенда 2 L7711 и 49 L7714 — имена, которых в её конфигурации нет; 1С это подтвердила.

Правило таблицы формы установлено пробами: первое предположение («первая таблица списка»)
1С опровергла, вторая и третья серии исключили свойства таблицы и поле `Frame[24]`, четвёртая
подтвердила `MoxelName`.

## Что реализовано

- `metadata77`: `Metadata.owner(папка, номер)` — документ (`Document`, `Transact`), справочник
  (`Subconto`, `SubFolder`, `SubList` — по форме в записи), журнал (`Journal` — по форме).
- `moxcel77` (новый): `area_names` — именованные области листа `MOXCEL` (число и записи в конце
  потока: строка MFC и семь 32-битных полей), `worksheets`, `form_table` (лист, заголовок которого
  назван в `Container.Profile`).
- `lint77` 0.5.0:
  - `load_sources` для `1Cv7.MD`: `md_context` — диалог формы из её `Dialog Stream`, пустой
    контекст у модуля документа и глобального модуля, владелец; формы операций, проводок и плана
    счетов — без контекста (`UNMODELLED_FORMS`);
  - `ert_dialog`: столбцы `Browser/Fixed`, `Таблица` при наличии таблиц (`FORM_TABLE` убрана из
    общих имён), области таблицы формы; нечитаемая таблица формы — контекст неизвестен;
  - `owner_names` — реквизиты владельца и атрибуты его класса (`Код`, `НомерДок`…, у журнала —
    `ТекущийДокумент`) для L7711; `check_attributes` — цепочка от реквизита владельца;
  - лексема `date` для `'…'` в пределах строки;
  - отчёт — `md_context_modules`; `LIMITATIONS` — границы L7711 и L7714.
- Исследование: `research/rules77/probe_context77.py`; `run_cases` в `probe_metadata77.py` принимает
  шаблон и срок случая (случаи 018–019 не изменились); приёмка — `scripts/verify_context77.py`;
  тесты — `tests/test_lint77_context.py` (16, с построителем CFB по путям).

## Границы

- Контекст форм операций, проводок и плана счетов не моделируется — L7711 в них не проверяется.
- Нативно проверены модули документов (в контексте объекта, без методов модуля документа) и формы
  отчётов и обработок (в контексте формы пробы с объявленным контекстом их формы); формы
  документов и справочников — только статически: их контекст — открытая форма объекта.
- Столбцы списка (`Browser/Fixed`) установлены по корпусу (форма списка `Цены` читает
  `Номенклатура`), нативно не проверены.
