# Задача 102. Файловые fixture и reader

Дата — 14 ноября 2026 года. Выполнение поручено владельцем после приёмки 0.8.0.
Статус — принята владельцем 14 ноября 2026 года.
После приёмки поручены [публикация 0.9.0 и проверка скачанного wheel](102-release-090-acceptance.md).

[Результаты проверки](102-file-fixtures-acceptance.md): 26 нативных запусков,
21 отказ входов до платформы, правки файлов без перегенерации через все три
интерфейса и совместимость со встроенными текстами 101. Локальный wheel 0.9.0
прошёл 625 тестов установленной поставки (5 skipped).

Цель — редактировать fixture.1s и reader.1s в прикладном проекте и сразу
повторять run/suite/MCP, без повторного project-init или встраивания текста
в JSON/TOML. Встроенные тексты принятой 101 продолжают работать.

Контракт wheel 0.9.0: schema_version=3 и параметры fixture_setup_file,
fixture_verify_file, пути относительно профиля проекта. Для каждого тела
функции выбирается встроенный текст либо файл. Файлы — непустой UTF-8 без BOM,
NUL и символов, не представимых в Windows-1251. Чтение выполняется общим
загрузчиком и повторяется перед execute даже для ранее загруженного профиля.
Runtime получает обычные тела функций; его протокол и UI не изменяются.
Версия 3 обеспечивает явный отказ старых версий harness.

project-init копирует входы, указанные в сценарии относительно его каталога,
в fixture.1s/reader.1s проекта и сохраняет локальные ссылки. В run сохраняются
точные байты использованных файлов в fixture-inputs/, размеры и SHA-256,
роль и идентификатор исходного пути. После чтения используются именно эти
зафиксированные тела, независимо от последующих правок исходного файла.

Приёмка на принятой фактуре: исходник, ошибка +1, исправление и повтор
с одинаковыми тестами через run, CLI suite и MCP; отдельно встроенный вариант
101 через каждый интерфейс. Правки fixture и reader должны давать наблюдаемые
изменения без изменения профиля, восстановление файлов — возвращать passed.
Отсутствие файла, конфликт, кодировка, недопустимый символ, пустой файл,
каталог вместо файла и старая версия схемы дают blocked до 1С; живой MCP
после них продолжает работу. Нужны snapshots/hash, JSON/JUnit, сохранность
источника/реестра/процессов и очистка копий.

Квалификация — прежний стенд Windows / 7.70.027 / DLL / DBF. Публикация
нового релиза в поручение не входит.
