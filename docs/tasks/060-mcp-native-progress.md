# Задача 060. Прогресс ожидания стенда через MCP

Задача принята владельцем 9 ноября 2026 года.

Для нативного `run` с `_meta.progressToken` launcher отмечает занятый
мьютекс и старт CDB. MCP отправляет «ждёт освобождения стенда» и
«запускает 1С» при ближайшем опросе. Если оба события произошли между
опросами, клиент получает оба в исходном порядке. Периодические
уведомления повторяют состояние ожидания, пока мьютекс занят.

Нативная проверка использует один MCP-сервер и две временные копии базы
1С 7.7.027. Первый клиент удерживается после `check`. Один запрос к другой
копии отменяется через `notifications/cancelled` после сообщения об
ожидании. Следующий запрос к той же копии получает уведомление об
ожидании, затем первый сеанс завершает работу. У каждого запроса свой
`progressToken`. До освобождения стенда проверяется отсутствие CDB у
ожидающих запусков.

## Результаты

- При освобождении стенда MCP прислал «ждёт освобождения стенда» на 3,4 с
  и 13,6 с, затем «запускает 1С» на 23,0 с от начала запроса. Оба
  нативных сеанса вернули 42 после одного `Initialize` каждый.
- При отмене клиент получил уведомление об ожидании. В отчёте есть
  `cancelled=true`, `reason=cancelled` и `registration_wait.acquired=false`.
  MCP не отправил уведомление о запуске 1С. Второй launcher завершился
  до старта CDB, 1С и клиента, вызовов `Initialize` было ноль. PID и
  COM-регистрация первого сеанса сохранились во время отмены.

В первой попытке проверочный скрипт прервал ожидание итогового ответа
через 80 с, уже после уведомления о запуске. Повтор с увеличенным сроком
скрипта завершился полностью. Очистка копий, замков и временных записей
подтверждена. Прошли 88 автоматических тестов и 4 подтеста.
