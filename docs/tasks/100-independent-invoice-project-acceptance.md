## Прикладная проверка

Fixture создаёт покупателя, договор, подразделение, товар, накладную-основание
и фактуру с двумя строками 1×50 и 1×30. Явный период журнала — 1 августа
2026 года. UI выбирает накладную по точной ссылке, открывает связанную фактуру,
меняет вторую строку на 3×30, записывает и повторно открывает ту же ссылку.
Reader заново получает фактуру по сохранённой ссылке, проверяет связь
с основанием и читает строки, товар, комментарий, проведение и итоги.

Ожидание закреплено до серии: первая строка 50, вторая 90, итоги 140,
НДС 0, строк 2, документ не проведён. Регрессия добавляет 1 только в ветке
пересчёта количества/цены штатного модуля формы. Сохраняются 91 и 141;
независимая проверка требует ровно четыре расхождения:
`/amount`, `/total`, `/rows/1/amount`, `/rows/1/total`. Остальные поля
должны совпадать с ожиданием. Исправленный исходник побайтно равен исходному.

Во всех фазах один scenario.json, одни fixture/reader/steps/expected,
ERT и module.1s контроллера. Различаются только директории сборки модуля
конфигурации. Перед исполнением platform-секции всех профилей сравниваются
с исходным сценарием; затем хеши профилей и входов проверяются повторно.

## Найденные ограничения и подготовительные пробы

Прямое открытие этой формы в wheel 0.7.0 даёт ложное расхождение подписи
«Печать...»/«Печать»; прямой reopen не поддерживает нужное исключение кнопки.
Рабочий путь через подчинённый журнал использует существующий точный контракт
`caption_control="кнПечать", caption_text="Печать"`. При reopen уже заданная
подпись наследуется: повторно задавать override кнопки нельзя. Проверки
геометрии/подписей не отключались, провал открытия не объявлялся ожидаемым.

В подготовительных пробах также уточнены явный период журнала и сохранение
CRLF в независимой сверке MD. Сверка отчётов учитывает существующий контракт:
краткая причина содержит первые два расхождения, подробная диагностика — все.
Подготовительные неуспешные каталоги сохранены отдельно; их нельзя считать
успешной серией. Во время итоговой четырёхфазной серии прикладные тесты
не меняются.

Изменения runtime/CLI/MCP для выполнения сценария не потребовались:
исполняется опубликованный wheel без патчей. Практическое препятствие —
необходимость обхода ограничения прямого открытия через более длинную
навигацию журнала. Возможное следующее улучшение — точное описание изменяемой
подписи кнопки для существующей формы без обязательной навигации через журнал.
Поддержка произвольных форм этим результатом не подтверждается.

После приёмки 100 владелец поручил устранить ограничение прямого открытия
в [задаче 101](101-direct-invoice-caption.md); результат 100 относится
к неизменённому опубликованному wheel 0.7.0.
