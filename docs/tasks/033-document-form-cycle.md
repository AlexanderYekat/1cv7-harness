# Задача 033: запись, проведение и повторное открытие через форму

Дата: 7 ноября 2026 года. Предыдущая задача — [032](032-posting-rollback.md).
Поручение владельца: «Хорошо, приступай» к предложенному полному сценарию документа через форму.
Статус: **принято владельцем 7 ноября 2026 года в указанном охвате**
([отчёт](033-document-form-cycle-acceptance.md)). Основание — поручение
«Принимай и коммить»; ожидания записаны до нативного запуска.

## Охват и ожидания

Закреплённые DBF-стенд и платформа 7.70.027, документ «Готовая продукция».
Каждый run работает на новой проверенной копии. Модуль документа, модуль формы
и диалог не меняются. Подготовка создаёт товар и непроведённый документ с двумя
строками (1 × 10 = 10; 2 × 20 = 40); проведение в fixture запрещено.

1. Открыть подготовленный документ; ввести комментарий «Harness77 форма 033»
   и количество первой строки 3 через интерфейс. Проверить пересчёт суммы 30,
   число строк 2 и итог 70.
2. Нажать штатную «Записать», затем «ОК», подтвердить проведение, если штатная
   команда задаёт вопрос.
3. Шаг `{ reopen = true }` закрывает форму через установленный 1С++
   `System.CloseForm(Контекст77Формы, 0)`, без записи изменений. Watcher независимо
   требует исчезновения HWND диалога и его рамки. Только затем второй вызов открывает
   сохранённую ссылку fixture, без повторной подготовки данных и без записи/
   проведения через OLE. Разрешены только существующий документ с fixture_setup/
   fixture_verify на проверенной копии и предшествующие шаги сценария. Если форма
   уже закрыта шагом с closes, первая фаза пропускается. Контроллер подтверждает
   ссылку открытого документа, watcher заново находит его окна в своём процессе.
4. Повторно открытая форма показывает тот же комментарий, две строки с
   количествами 3/2, стоимостью 10/20, суммами 30/40 и итогом 70. Команда result
   завершает работу с формой, завершение своего сеанса проверяется отдельно.
5. Независимая fixture_verify новым объектом читает документ по исходной ссылке,
   комментарий, все строки, их ссылки товара, признак проведения и все проводки.
   Ожидаются признак 1 и ровно две проводки Дт 43 Кт 40, 3/30 и 2/40.

Основной набор — успех и повтор на свежей копии. Отрицательный набор — неверное
ожидание сохранённого количества 999 (failed, ровно один JUnit failure), затем
успешный сценарий. Отдельно проверить отказ неверного ожидания повторно открытой
формы, продолжение набора и отсутствие допуска профиля без копии до запуска 1С.
Неудачные попытки сохранять; ожидания данных не подстраивать под результат.
Точный штатный текст вопроса фиксировать по протоколу при исследовании интерфейса.

Уточнение интерфейса по первым пробам: вопрос — «Провести документ?» с ответом
«Да». В автоматизированном сеансе после этого проведения окно остаётся открытым
даже через 10 секунд; исходное предположение об автоматическом закрытии «ОК»
не подтвердилось; отдельная кнопка «Закрыть» и Escape также не закрыли окно.
Активация MDI и возврат фокуса не решили проблему, эти попытки не приняты.
`Форма.Закрыть(0)` также не уничтожил окна. В исходниках 1С++ CSystem::funcCloseForm
есть специальное освобождение ссылок элементов формы перед WM_CLOSE. Этот метод
на установленном компоненте нативно закрыл оба окна; затем открылась та же ссылка.
Поэтому reopen использует две фазы с System.CloseForm и независимой проверкой
уничтожения окон. Запись и проведение остаются исключительно через UI.
Ожидания записанных данных и проводок сохранены. Табличная часть заполняется
перед комментарием: первоначальная
последовательность «комментарий → таблица» оставила редактор ячейки открытым
и провалила сценарий до записи; этот отказ сохраняется отдельно.

Независимый verifier перечитывает ответы контроллера и протоколы шагов, порядок
записи/подтверждения/закрытия/открытия, чтение полей и проводок, JSON/JUnit, хеши
и очистку. Проверки продукта, форм и платформы; нативная регрессия 030/031.
Критерии: источник и список баз сохранены, свои сеансы завершены, чужие сохранены,
копия удалена, блокировка освобождена. Другие документы, SQL, создание нового
документа через журнал и универсальный UI-конструктор в охват не входят.
