# Этап 5, задача 021: изменение модулей 1Cv7.MD на копии базы

Дата: 22 октября 2026 года. Предшествующая задача — [020](020-md-module-context.md).
Приёмка — [021-md-modules-acceptance.md](021-md-modules-acceptance.md). Статус: **принято** владельцем 22 октября.

## Зачем

До сих пор harness77 менял только внешние обработки: `build` собирает ERT, `run` проверяет её
в 1С на базе стенда, а модули самой конфигурации (`1Cv7.MD`) только читаются — `lint` проверяет
их в контексте объекта (020). Разработчик или агент не может изменить глобальный модуль, модуль
документа или модуль формы и проверить изменение в настоящей 1С. Владелец выбрал это направление
22 октября из четырёх (модули `1Cv7.MD` на копии, копия базы для тестов, формы 5.1 дальше,
остатки 020 по `lint`); оно предлагалось с задачи 018.

Изменённая конфигурация не должна попасть в базу стенда: каждый прогон идёт на своей копии
базы, а `1Cv7.MD` копии — новый файл, собранный и проверенный обратным чтением.

## Охват

1. **Модули `1Cv7.MD` по именам** (`md77`). Каждый модуль конфигурации получает файл в
   читаемой раскладке, имя — по метаданным:

   | Папка `1Cv7.MD` | Файл |
   |---|---|
   | `TypedText/ModuleText_Number1` | `ГлобальныйМодуль.1s` |
   | `TypedText/Transact_Number<n>` | `Документ/<Имя>/МодульДокумента.1s` |
   | `Document/Document_Number<n>/WorkBook` | `Документ/<Имя>/Форма.1s` |
   | `Subconto/Subconto_Number<n>/WorkBook` | `Справочник/<Имя>/ФормаЭлемента.1s` |
   | `SubFolder/SubFolder_Number<n>/WorkBook` | `Справочник/<Имя>/ФормаГруппы.1s` |
   | `SubList/SubList_Number<n>/WorkBook` | `Справочник/<Имя>/ФормаСписка.<Форма>.1s` |
   | `Journal/Journal_Number<n>/WorkBook` | `Журнал/<Имя>/ФормаСписка.<Форма>.1s` |
   | `Report/Report_Number<n>/WorkBook` | `Отчет/<Имя>/Форма.1s` |
   | `CalcVar/CalcVar_Number<n>/WorkBook` | `Обработка/<Имя>/Форма.1s` |
   | прочие (бухгалтерские формы, номер без имени) | `Прочие/<Папка>_Number<n>.1s` |

   `TypedText/UserHelp_*` — описания, не код; в раскладку не входят.
2. **`harness77 md-extract <1Cv7.MD> --output DIR`** — новый каталог: все модули в UTF-8
   (переводы строк как в 1С) и `modules.json` — для каждого файла путь в `1Cv7.MD`, объект и
   SHA-256 текста; хеш и имя конфигурации.
3. **`harness77 md-build --template 1Cv7.MD --modules DIR --output NEW.MD`** — новый `1Cv7.MD`:
   заменяются только модули, текст которых отличается от шаблона (сравнение после приведения
   переводов строк к CRLF); отсутствующий файл — модуль без изменений. Отказ: неизвестный файл,
   модуль, которого в шаблоне нет (новые модули и объекты не создаются), символ вне Windows-1251,
   NUL; с `modules.json` — модуль, изменившийся в шаблоне после извлечения (иначе правка молча
   затёрла бы чужое изменение). Проверка обратным чтением с диска: изменённые модули — новый текст,
   остальные потоки (в том числе `Main MetaData Stream`) и записи каталога — байт в байт; выход
   только новый файл. Отчёт — изменённые модули с хешами до и после.
4. **`run` с `[configuration] modules = "DIR"`** в профиле проекта:
   - этап `configuration`: новый `1Cv7.MD` из `1Cv7.MD` базы стенда (закреплённый хеш обязан
     совпасть) и каталога модулей;
   - `static`: изменённые модули — `lint` в контексте собранной конфигурации (020), модуль ERT —
     с экспортом собранного глобального модуля;
   - копия базы в каталоге запуска (`<run>/base`): все файлы и подкаталоги базы, кроме названных
     в `[stand.base] copy_exclude`; отказ, если база открыта в 1С; `1Cv7.MD` копии — собранный
     (после пробной серии 0 — по одному зарегистрированному пути `[stand.base] copy_path`, см. ниже);
   - 1С открывает копию; launcher принимает её только с хешем собранной конфигурации
     (`--configuration-sha256`), остальные закреплённые файлы — прежние;
   - после прогона копия удаляется (`[configuration] keep_copy = true` оставляет); база стенда
     проверяется неизменной (хеши закреплённых файлов и перечень файлов: имя, размер, время).
5. **MCP:** `md-extract`, `md-build` — те же команды.

**Не входит:** новые модули и объекты, изменение метаданных (реквизиты, диалоги форм, таблицы),
модули бухгалтерских форм по именам, автоматическая проверка Конфигуратором, реструктуризация
и `1Cv7.DD`, SQL-базы, перенос изменённой конфигурации в рабочую базу.

## План нативных проб

Стенд `local-7.70.027`, база `base-for-test`, шаблон обработки `FIO.ERT`; скрипт
`research/md/probe_md77.py`, каждый случай — `harness77 run` с `[configuration]`. Тест —
контрольная функция обработки (`execute`). Копия — без `ExtForms`, `actofsverok`, `temp`.
Ожидание записано до прогона; `?` — исход устанавливает проба.

### Пробная серия 0 и изменённое устройство (до серии 1)

Первый `m-same` с копией в каталоге запуска (`<run>/base`) закончился сроком открытия (120 с):
1С не создала `1Cv7.LCK` копии. Снимок окон своего процесса по истечении срока (добавлен в
ядро сеанса этой задачей, только чтение) показал «Регистрация Информационной Базы» с путём копии:
через OLE 1С 7.7 открывает только базу из списка баз пользователя (`HKCU\Software\1C\1Cv7\7.7\Titles`),
как и в пробе отсутствующей базы задачи 002. Поэтому копия получила один путь — `[stand.base]
copy_path`, зарегистрированный в списке однажды (с разрешения владельца 22 октября:
`…\.local\bases\harness77-copy`); прогон захватывает его замком `<copy_path>.lock`, пересоздаёт копию
с меткой `harness77-copy.json` (свой `run_id`) и удаляет после; удаляется только помеченный каталог.
Launcher отказывает сразу, если метка не этого прогона или путь не зарегистрирован. Копия без
`ExtForms`, `actofsverok`, `temp` — 854 файла, 537 МБ, около 2–3 с.

| `m-export2` | «Поле агрегатного объекта не обнаружено (Харнесс77Документ)» — подтверждено: функция модуля документа не метод объекта |

Без журнала копии такой прогон выглядел бы успешным. Поэтому `run` разбирает записи `GrbgSyntaxErr`
сеанса: ошибка компиляции изменённого модуля делает `platform_check` проваленным
(`configuration_compilation_failed: <файл>:<строка>: <сообщение>`, код 1), если сеанс своей 1С
завершён чисто (при сломанном глобальном модуле 1С++ не загружается и контроллер стенда не работает —
прежде это давало `blocked`). Имена модулей в сообщениях 1С: «Глобальный модуль»,
«Документ.<Имя>.Модуль Документа», «Документ.<Имя>.Форма.Модуль». Статика изменённого модуля
показывает только замечания, которых у того же модуля шаблона не было.

## Приёмка

Переносимо: раскладка всех папок и `Прочие`; извлечение → сборка без правок даёт модули байт
в байт; правка одного модуля меняет только его поток; отказы пункта 3; `modules.json` ловит
изменение шаблона; копия базы — исключения, отказ при открытой базе, удаление, неизменность
источника; `run` с `[configuration]` на симуляционном стенде (этапы, хеши, копия, отчёт);
launcher принимает копию только с хешем собранной конфигурации; MCP; все прежние тесты.
Нативно: таблица заполнена исходами 1С; `m-same`, `m-global`, `m-global-var`, `m-transact`,
`m-form` совпали с ожиданием; для `?` исход записан и отчёт `run` его различает.
