# Приёмка задачи 012: поля ссылочных типов в описании формы

Дата: 19 октября 2026 года. Статус: **принято.** Задание — [012-reference-fields.md](012-reference-fields.md).
Исходный HEAD: `bb47e4e`.

## Что реализовано

- **Продукт** (`src/harness77/metadata77.py`, `form77.py`, `artifacts.py`, `run77.py`,
  `config77.py`). Описание формы — схема версии 3: ссылочный тип
  `{"kind": "reference", "object": "Справочник.Контрагенты"}` (`Справочник`,
  `Документ`, `Перечисление.<вид>`, `Счет`, `ВидСубконто`, `ПланСчетов`, с видом или
  «любой»); вид без имени — номером: `{"kind": "reference", "code": "B", "object_id": 133}`.
  Описания версий 1 и 2 принимаются и собирают те же байты. Контракт —
  [contracts.md](../contracts.md#описание-формы-задачи-008-011-и-012).
- **Метаданные.** `metadata77` читает имена объектов из `1Cv7.MD` и из копии
  метаданных, которую несёт сама ERT. `form-extract` называет виды по `--metadata`,
  без него — по копии ERT. `build --metadata` переводит имя вида в номер
  по метаданным целевой базы, отчёт фиксирует их SHA-256 и имя конфигурации.
- **Новое поле** — `BMASKED` с ссылочным типом по имени; запись — самая частая
  для кода в корпусе (отличается от поля числа только флагами). Если копия
  метаданных шаблона не содержит нового вида, сборка заменяет её метаданными целевой
  базы — только если прежние поля вида шаблона означают в базе те же объекты
  (`form.ert_metadata`: `kept`/`replaced`).
- **`run`:** `[build] metadata` или `1Cv7.MD` базы стенда, если описание называет
  вид; ERT, собранная по другим метаданным, на стенде не проверяется
  (`metadata_mismatch`, 1С не запускается).
- **Явный отказ:** неизвестный тип или вид, вид у `ВидСубконто`/`ПланСчетов`,
  `Перечисление` без вида, номер вместо имени у нового поля, `ПланСчетов` и
  `1CEDIT` как новое ссылочное поле, имя вида без метаданных, другой номер у
  существующего поля, шаблон без копии метаданных, несовместимая копия;
  `--metadata` без `--form`.
- **Нативная проба** (`research/forms`): строки `repr:` обработчика (представление
  значения зависит от данных базы) адаптер пишет в `representations`, а не в
  значение `result`; модуль `references_module77.1s`, профили
  `prepare_references77.py`, приёмка `verify_references77.py`; сверка корпуса
  с `--metadata`.

## Главный результат пробы

Первая проба R1 опровергла исходный план: номера вида в поле 17 недостаточно —
1С ищет вид в **копии метаданных внутри самой ERT** (поток `Main MetaData Stream`).
У FIO.ERT копия пустая, и 1С отвечала «Ошибка создания внешнего отчета». Диагностика
(R1a, по одному полю, R1b, R1c) показала: поля «любой» работают с пустой копией,
поля вида — только если копия содержит вид. По корпусу все 112 полей вида находят
свой номер в копии своей ERT. Способ изменён до повтора (см. задание).

  (`Строка()` — «51»), и у поля счёта нет кнопки «…»;
- `ТипЗначенияСтр` даёт `Справочник`, `Документ`, `Перечисление`, `Счет`,

## Границы

- Проверены один шаблон FIO.ERT (с пустой копией и с копией корпуса), одна
  конфигурация и один стенд (Windows 11, 96 DPI). Сопоставление метаданных разных
  баз не делается: другой номер — отказ.
- Выбор значения пользователем («…», F4) — ручная проверка владельцем после
  приёмки: поле вида «Контрагенты» отработало, как ожидалось; поле «любой документ»
  сначала предлагает вид документа — поведение платформы для неопределённого вида.
  Поле документа с видом (`Документ.Выписка`) нативно не проверялось.
- Другая конфигурация — ручная проверка владельцем после приёмки (подробно — в
  задании): ERT с формой и копией R1 в «Торговля+Склад 9.2», где «Контрагенты» —
  номер 172, а 133 нет, — поле стало «Контрагентами» той базы и выбрало её элемент;
  1С находит вид по имени через копию ERT. Вид, которого в базе нет (`Перечисление.Пол`),
  форму не ломает, но поле теряет тип («Строка»). Правила `metadata_mismatch` и отказ
  при другом номере строже 1С; менять их — решение владельца.
- Новые поля — только `BMASKED`; `1CEDIT` со ссылочным типом и `ПланСчетов`
  не поддерживаются; тип существующих полей не меняется.
- Замена копии метаданных ставит в ERT полные метаданные базы (сотни КБ), а не
  урезанную копию, которую пишет Конфигуратор; как такую ERT откроет Конфигуратор,
  не проверялось.
- Значение флагов поля 19 у записей по умолчанию не установлено.
- Эталоны снимков утвердил исполнитель после просмотра; владелец их ещё не смотрел.
