# Задача 106. Чтение COMBOBOX без изменения выбора

Согласована владельцем 16 ноября 2026 года после приёмки релиза 0.12.0.
Цель — получить точные строки для `select` из открытой формы, без разбора
кода заполнения списка и без пробного выбора. В 104 отмечены трудности
авторства шагов по модулям/описаниям; в 105 чтение пунктов было доступно
только внутри действия `select`.

Реализована, технически проверена и принята владельцем 16 ноября 2026 года.
[Результаты и свидетельства](106-inspect-combo-acceptance.md).

## Охват и контракт

Локальная версия 0.13.0 добавляет единственный новый шаг:

```json
{"inspect_combo": "СписокТиповУслуг"}
```

Других параметров нет. Элемент разрешается по идентификатору, затем подписи
по правилам 105; нужен один COMBOBOX. Шаг поддержан в файловых и inline
steps, включая существующий путь run/CLI suite/stdio MCP. Новых команд
транспорта и новой версии профиля не требуется.

Читаются пункты в порядке native-списка, текущий нулевой индекс и текст,
visible/enabled. При отсутствии выбора индекс и текст равны JSON null;
выбранный пустой пункт имеет числовой индекс и текст `""`. Дубликаты,
пустые строки, пробелы и регистр сохраняются буквально. Скрытый или
заблокированный элемент читается с соответствующими признаками состояния.

Используются поддержанные в 105 drop-down типы COMBOBOX 2/3 со строками,
не более 1000 пунктов по 4096 символов. Проверяются владелец PID/TID,
класс, родитель и ID окна. Чтение не посылает сообщений установки выбора,
фокуса или уведомления обработчику. Два чтения списка и состояния должны
совпасть; фокус до/после чтения также должен совпасть. Нестабильное состояние,
неподдержанный тип и ошибка чтения дают отказ без полного артефакта.

## Артефакт

После успешного round trip и проверенного чтения атомарно сохраняется
`form/combo-step-NNNN.json`, schema_version=1, kind=combobox_inspection.
Поля: step_index, target, record_id, window_id, items, selected_index,
selected_text, visible, enabled, read_only_verified.

В `form-window.json` соответствующий шаг содержит `combo_inspection`
(в том числе focus_before/focus_after) и `inspection_file` с относительным
путём, SHA-256, размером, версией схемы и complete=true. Файл входит в обычный
`run.json.result_files`; backend проверяет его SHA-256. Ссылка доступна через
существующие отчёты suite/MCP. Номера HWND фокуса остаются в диагностике шага,
публичный snapshot можно сравнивать между транспортами без этих переменных значений.
Ошибка round trip, чтения или сохранения не становится успешным шагом.

## Приёмка

1. Оба COMBOBOX формы «Оказание услуг» — СписокТиповУслуг и
   ВариантЗачетаАванса — прочитаны без заданных текстов пунктов.
2. Дубликаты, пустой текст и пустой список прочитаны однозначно;
   отсутствие выбора отличается от выбранного пустого пункта.
3. Фокус и выбор сохраняются. Счётчик в обоих прикладных обработчиках
   остаётся нулевым после чтения, затем увеличивается при контрольном select.
   Каждый вызов публикует маркер и значение счётчика: после чтения маркеров
   нет, контрольный select публикует ровно вызов № 1. Экспортная переменная
   формы не читается через `value`: контекст 1С 7.7 её не предоставляет.
   Независимый reader подтверждает сохранённые данные.
4. Неоднозначный/отсутствующий элемент, неправильный класс, неподдержанный
   тип и ошибка чтения дают явный отказ. При переполнении native-списка
   нет полного snapshot. Suite продолжает работу после отказа, MCP отвечает
   на следующий запрос; JSON/JUnit согласованы.
5. Одинаковые сценарии через run/CLI suite/MCP дают одинаковые snapshots
   и диагностику. Пункты из первого snapshot используются для составления
   select, затем проходят запись/reopen и цикл baseline/regression/fixed/repeat-fixed.
6. Принятые примеры 104–105 сохраняются; источник базы, реестр и процессы
   проверяются до/после, копия и lock очищаются. Геометрия остаётся с допуском 2 px.

Квалификация ограничена прежним Windows/1С 7.70.027/DBF-стендом.
Генератор fixture/reader, универсальный инспектор форм, новые платформы
и публикация релиза в задачу не входят.
