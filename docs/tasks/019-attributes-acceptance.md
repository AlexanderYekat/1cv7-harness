# Приёмка задачи 019: реквизиты объектов в коде модуля

Дата: 21 октября 2026 года. Задание — [019-attributes.md](019-attributes.md).
HEAD перед работой — `f0bd72f`, ветка `master`. Принята владельцем 21 октября 2026 года.

## Итог

`harness77 lint` 0.4.0 сверяет с `1Cv7.MD` базы реквизиты объектов, которые код получает
из `СоздатьОбъект("Справочник|Документ|Регистр.<Вид>")`, и идёт дальше по ссылочным
реквизитам (L7714, warning; `--strict` — error). L7712–L7714 молчат об имени внутри `Если`,
условие которого проверяет его через `Метаданные`. 7.70.027 загружает модуль с любым
отсутствующим реквизитом, а строку прерывает при исполнении — «Поле агрегатного объекта не
обнаружено (Имя)». Линтер совпал с 1С на 27 из 27 проб; 1С перечислила те же 1922 реквизита,
что прочитаны из `1Cv7.MD`, и прочла каждый. На 385 модулях рабочей конфигурации
«Торговля+Склад» L7714 сверил 1155 обращений и не дал ни одного срабатывания. На формах
`ExtForms` базы стенда защита `Метаданные` сняла 630 из 756 L7713.

## Что реализовано

- `metadata77`: `Metadata.attributes(класс, вид)` — реквизиты справочника (`Params`), документа
  (`Head Fields`, `Table Fields`, общие `GenJrnlFldDef`), регистра (`Props`, `Figures`, `Flds`);
  `Attribute` — имя, код типа, вид ссылки (`target` — справочник или документ). Запись другого
  вида, повтор списка или имени у объекта — `ErtError`; `lint` читает реквизиты вместе
  с именами, нечитаемые — код 2. Сборка формы (012–013) реквизиты не читает.
- `lint77` 0.4.0:
  - `check_attributes` (L7714): области модуля (`scopes` — шапка, процедуры, тело программы;
    `check_declarations` переведён на неё без изменения поведения), привязка имени к локальной
    переменной или переменной модуля, отказ от слежения за параметром, `Для`, реквизитом формы,
    глобальным именем, именем, переданным целиком в процедуру модуля, переменной `Экспорт`
    и именем с присваиванием другого вида; реквизиты класса — из каталога платформы
    (`Справочник|Документ|Регистр/Атрибуты`, русские и английские имена);
  - `metadata_guards`: операторы `Если … КонецЕсли` с проверкой `Метаданные.<Класс>("Имя")`,
    `.Реквизит`, `.РеквизитШапки`, `.РеквизитТабличнойЧасти`, `.Измерение`, `.Ресурс`,
    `.Значение`, `Метаданные.ОбщийРеквизитДокумента` в условии `Если` или `ИначеЕсли`;
  - L7713 не проверяет глобальные функции, вызванные через точку (`V77.CreateObject`);
  - отчёт — `metadata_guarded`, `attributes_checked`; `LIMITATIONS` — границы L7714 и защиты.
- MCP `lint` — описания `metadata` и `strict` называют L7714; `run` и MCP передают метаданные,
  как в 018, поэтому L7714 работает в стадии `static` без изменений `run`.
- Исследование: `research/rules77/probe_attributes77.py` (цикл прогона вынесен из
  `probe_metadata77.py` в `run_cases`; случаи и модули 018 не изменились); приёмка —
  `scripts/verify_attributes77.py`; тесты — `tests/test_lint77_attributes.py` (19).
- Документы: задание, приёмка, контракт, README, README исследования, дорожная карта, передача.

## Границы

- Объект распознаётся только из `СоздатьОбъект` с видом строкой в той же области; значения из
  таблиц, параметров, `ТекущийЭлемент()` и реквизиты объекта в его собственном модуле `1Cv7.MD`
  не проверяются. Отслеживание консервативно: любое другое присваивание имени отключает его.
- Защита распознаётся только в условии `Если`/`ИначеЕсли` того же оператора; проверка,
  сохранённая в переменную или с выходом из процедуры, не распознаётся (в корпусе таких
  случаев у оставшихся срабатываний нет).
- Атрибуты класса из каталога (`Владелец`, `Родитель`, `Операция`) принимаются у любого объекта
  класса: `Владелец` у неподчинённого справочника 1С ошибкой не считает.
- Регистры прочитаны статически (база «Торговля+Склад»); нативно регистров нет в базе стенда.
  Проверены одна база и один стенд.
