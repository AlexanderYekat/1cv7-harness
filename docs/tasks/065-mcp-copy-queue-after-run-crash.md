# Задача 065. Очередь MCP после падения run

Задача принята владельцем 9 ноября 2026 года.

Два запроса `run` через один MCP-сервер использовали один временный
`copy_path` на 1С 7.7.027. Первый launcher подтвердил свой OLE-прокси
и остановился перед публикацией `initialize-permit`. После первого
уведомления об ожидании второго запроса проба завершила только первый
CLI по дескриптору процесса, который запустил тестовый MCP-сервер.

## Результаты

- После падения CLI второй запрос снова получил «ждёт освобождения
  пути копии». Таблицы были доступны, а унаследованный дескриптор
  удерживал замок. Опись 855 файлов, SHA-256 `1Cv7.MD`, метка, замок,
  COM-ключи и процессы первого сеанса совпали до и после падения.
  Второй launcher к этому моменту не стартовал.
- Первый launcher после сигнала пробы один раз вызвал `Initialize`,
  вернул 42 и штатно завершился. Очистка подтверждена, принудительного
  завершения нативных процессов не потребовалось.
- Тот же второй запрос продолжился автоматически. После ожидания
  14,702 с MCP сообщил «готовит копию», затем «запускает 1С». Второй
  `run` указал первый UUID в `stale_run_id` и `previous_run_id`,
  создал копию со своим UUID, получил остатки сроков `open` и `total`
  и вернул 42 после одного `Initialize`.

Временная копия, замки и запись пути удалены. Опись исходной базы и
список баз совпали со снимками до пробы. Прошли 66 тестов и 13 подтестов.

Сводка — `.artifacts/stage65-native/verified.json`. Локальная проба
запускается командой `python -B .local/s65-verify.py <новый-суффикс>`.
