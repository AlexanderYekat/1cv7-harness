# Продолжение после задачи 028: выбор ссылочных значений

[Задание](../tasks/028-reference-choice.md), [проверка](../tasks/028-reference-choice-acceptance.md),
[пример](../../examples/reference-choice/README.md). Исходный HEAD — `8c94fbb`, `master`.
Владелец выбрал направление 7 ноября 2026 года. Изменения подготовлены в рабочем дереве.

## Реализация

- `choice77.py`: устройство новой MDI-формы выбора, код контроллера; уникальное полное
  имя элемента справочника, позиционирование списка и сравнение возвращённой ссылки.
  Имя не совпадает с существующим `platform77/reference77.py`.
- `scenario77.py`: шаг `choose` с `text` либо `cancel = true`; только колонка со ссылкой
  на конкретный справочник. Отрицательные номера запросов отделяют этапы выбора
  от обычных вызовов шагов. Итоговая ссылка проверяется после окон формулы.
- `form_launcher77.py`: вид справочника из метаданных колонки, фокус в найденный список,
  проверка HWND, Enter/Escape. Insert на неизменённой форме может сам открыть выбор:
  непосредственный следующий `choose` принимает это окно, без повторного F4.
  Неожиданный выбор отменяется, сценарий падает. Ошибки компиляции контроллера
  сохраняются в `native/controller-errors.txt`.
- `probe_reference77.py`, `scripts/verify_reference_choice77.py`, 10 переносимых тестов.
- Продукт в `src/` не менялся; пример требует checkout и исследовательский launcher.

## Границы

Проверен один справочник в колонке одной формы документа, платформа 7.70.027.
Поиск перебирает элементы, исключая группы; при одинаковых полных именах отказывает.
Большие справочники и другие языки интерфейса не проверены; ответ контроллера ограничен 30 с.
Шапка формы, ERT, выбор групп, поиск по коду/владельцу/родителю, подбор и произвольные
вложенные формы остаются отдельными направлениями. Другие прежние кандидаты —
проведение и движения, набор сценариев за прогон с JUnit XML. Следующее направление
выбирает владелец.
