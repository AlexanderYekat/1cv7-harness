# Контракты harness77 0.1

Реализованы четыре операции: `lint`, `compiler-protocol`, `extract`, `build`.
`harness77 --version` и `python -m harness77 --version` выводят версию пакета.
У каждой операции есть `--help`. Пути разрешаются относительно CWD вызывающего;
пакет, словарь и зависимости от CWD не зависят. Stdout/stderr CLI — UTF-8.

## Статический анализ и импорт протокола

`harness77 lint PATH [--globals FILE] [--allow NAME] [--strict]
[--format text|json] [--output FILE]` сохраняет прежний контракт lint77:
JSON `schema_version=1`, `tool=lint77`, диагностические коды L77xx.
Коды выхода: 0 — нет ошибок (предупреждения возможны), 1 — ошибки кода,
2 — ошибка входа/операции. Отчёт не подтверждает компиляцию. `--output`
сохраняет прежнюю перезапись отчёта, но отклоняет совпадение с входом/контекстом,
включая hardlink; отчёт линтера пока не публикуется атомарно.

`harness77 compiler-protocol INPUT [--encoding auto|utf-8|cp1251]
[--format json] [--output OUTPUT]` сохраняет [контракт 1.1](tasks/001-compiler-protocol.md).
Код 1 и `failed` означают пригодный протокол ошибок; код 2 и `blocked` —
непригодный вход. Ошибки файлов/публикации дают код 2 и сообщение stderr.
Импорт никогда не выдаёт `passed`. Он не связывает старый протокол с новой ERT.

## Сборка и извлечение

```text
harness77 extract INPUT.ert --output NEW.txt
harness77 build --template INPUT.ert --source MODULE.1s --output NEW.ert
                [--encoding auto|utf-8|cp1251|utf-16] [--legacy-normalize]
```

Выход обязателен и должен отсутствовать. Родительский каталог должен существовать.
Существующий файл, каталог, hardlink или symlink не перезаписывается. Входы
перечитываются перед публикацией; обнаруженное изменение останавливает операцию.
Применяются CFB v3 и один поток `MD Programm text`. Контейнеры с несколькими
модулями, включая полную MD, не являются входом сборки.

Извлечение сохраняет текст в UTF-8 без BOM, оставляя исходные переводы строк.
Сборка использует CP1251/CRLF. `auto`: UTF-16 с BOM, затем валидный UTF-8,
иначе CP1251. Автоопределение неоднозначно для части байтов; если кодировка
известна, следует задавать её явно. NUL и некодируемые символы отклоняются.
По умолчанию нет замен символов, в том числе представимых тире и кавычек.
`--legacy-normalize` разрешает прежние замены devtools и перечисляет каждую
в `normalizations`; неизвестный непредставимый символ всё равно даёт отказ.

Запись: подготовка → сверка текста/потоков/каталога → временный файл рядом
с выходом → flush/fsync → повторное чтение и сверка → публикация через hardlink
без замены существующего файла → удаление временного имени. Неподдерживаемая
файловой системой операция даёт отказ, обходного копирования нет. Сохраняется
содержимое посторонних потоков и метаданные записей каталога; физическое
размещение секторов и размеры модульного/root потоков меняются.

Код 0: JSON в stdout, `schema_version=1`, `tool=harness77`, `status=passed`.
`scope` равен `ert_container_build` или `ert_module_extract`.
У результата есть путь, размер и SHA-256; входы также имеют SHA-256.
Сборка дополнительно сообщает выбранную кодировку, хеш текста CP1251,
сохранённые потоки и выполненные сверки. `platform_checked=false` всегда.

Код 2: JSON `blocked` в stderr и сообщение об ошибке; неверные аргументы
дают штатный usage argparse и код 2. При ошибке очистки/stdout файл уже может
быть опубликован: существование файла само по себе не означает успех команды.
Операции не обеспечивают защиту от параллельной враждебной подмены родительских
каталогов; входы и каталог результата должны принадлежать текущей работе.

## Проект контракта платформенного запуска — ещё не реализован

Следующие параметры и поля предназначены для этапа 4. CLI 0.1 их не принимает.
Профиль проекта и стенда TOML появится вместе с исполнителем, без пустой
заглушки. Он задаст явные пути к платформе и выбранной существующей базе,
без паролей в профиле и без обязательного копирования базы.

Планируемые сроки в секундах: `open_timeout_s`, `calculation_timeout_s`,
`cancel_timeout_s`, `shutdown_timeout_s`, `total_timeout_s`. Эффективные значения
и источник (CLI/профиль/умолчание) попадут в отчёт. Значения конечные и
положительные; общий бюджет покрывает сумму разрешённых фаз. Некорректные
сочетания отклоняются до запуска. Измерение внешними монотонными часами;
прогресс не продлевает сроки. Пределы прототипа 30/145 с не являются умолчаниями.

Наблюдение: `run_id`, `phase`, `elapsed_s`, эффективный срок и `progress`
(явно `null`, если недоступен). Тишина не является тайм-аутом. Прикладной отчёт
и журналы сохраняются файлами в отдельном каталоге запуска; общий JSON содержит
пути, размеры, хеши и `complete`, а не полное содержимое больших результатов.
Полная дополнительная копия отчёта в памяти контроллера не требуется.

Пользовательская отмена (в том числе Ctrl+C) запускает ограниченное ожидание
возврата и завершения собственного сеанса. Итог различает `cancelled`,
`calculation_timeout`, `calculation_error`, `shutdown_error`, `artifact_write_error`.
Неполные результаты сохраняются с `complete=false` и не дают успеха.
Доказательство владения процессом и контроль завершения обязательны.

Штатное прерывание блокирующего вызова ещё не доказано. Нативная приёмка должна
включать заранее определённый реальный долгий отчёт, периоды без прогресса,
полный большой результат, превышение срока, отмену и следующий успешный запуск.
Подробные критерии — [раздел 8.5 ТЗ](restructuring-spec.md#85-долгие-расчёты-и-большие-отчёты).
