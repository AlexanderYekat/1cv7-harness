# harness77

Инструментарий для воспроизводимой разработки и проверки кода **1С 7.7**.

Цель проекта: исходники и контекст → статические проверки → сборка ERT → проверка настоящей платформой → тесты на копии базы → отчёт. Сейчас существуют отдельные инструменты чтения, анализа и записи модулей, а также импорт сохранённых ошибок Конфигуратора в JSON. Общий CLI, автоматическое управление платформой и исполнитель тестов ещё не реализованы.

Куда двигаться дальше — в [короткой дорожной карте](docs/roadmap.md). Границы компонентов описаны в [начальной архитектуре](docs/architecture.md), выполненные переносы — в [журнале упорядочивания](docs/housekeeping.md). Подробный проект требований — [методологическое ТЗ](docs/restructuring-spec.md).

## Что находится в проекте

```text
harness77/
  README.md                 назначение и вход в проект
  docs/                     архитектура, ТЗ и журнал изменений структуры
  1cv77-devtools/            существующие инструменты, отдельный Git-репозиторий
  77MCP/                    чтение метаданных и MCP, отдельный Git-репозиторий
  research/
    README.md               назначение исследовательских материалов
    kudir/                  опыт КУДиР, прототипы и корпус примеров
    76av/                   скрипты исследования 76.АВ и инструкция
    archive/                первоначальные вспомогательные материалы
  .local/
    bases/base-for-test/    локальная база, ранее лежала в корне
    configurations/reference/  снимок MD/DD для статического анализа
    research/76av/          локальные выгрузки и исторические отчёты 76.АВ
    maintenance/            снимок и проверки этого упорядочивания
```

`1cv77-devtools` и `77MCP` остаются самостоятельными репозиториями на прежних местах. Их внутреннюю структуру пока не меняем. Исследование 76.АВ разделено на [скрипты](research/76av/README.md) и локальные данные; прежний `.diagnostics` полностью разобран.

MD/DD перенесены из корня в `.local/configurations/reference`. Они совпадали с файлами базы при обследовании; это зафиксированный снимок для анализа, автоматической синхронизации с базой нет. Его происхождение и хеши записаны в локальном `manifest.json`. Не редактируйте обе копии как независимые версии одной конфигурации.

В корневом Git-репозитории хранятся документация, задания и исследовательские скрипты. Код инструментов фиксируется отдельно в `1cv77-devtools` и `77MCP`; их точные стартовые ревизии указаны в [манифесте исходного состояния](docs/baseline.json). Вложенные репозитории исключены из корневого Git, их истории сохранены. Для переноса разработки на другую машину нужны все три репозитория; локальные данные восстанавливаются отдельно.

## Что уже можно использовать

- [lint77](1cv77-devtools/LINT77.md): частичный статический анализ текстовых модулей, ERT и MD, JSON-диагностики. Успех линтера не подтверждает компиляцию или исполнение в 1С.
- [compiler-protocol77](1cv77-devtools/COMPILER-PROTOCOL77.md): импорт сохранённого протокола ошибок Конфигуратора в JSON; сохраняет повторы и частичные диагностики, сообщает о непригодном входе. Не запускает 1С и не подтверждает успешную компиляцию.
- [ert_module.py](1cv77-devtools/ert_module.py): чтение и замена текста внутри ERT. Запись и синхронизация могут менять файлы; для экспериментов используйте копии.
- [77MCP](77MCP/README.md): извлечение метаданных и модулей, поиск, MCP-интерфейс. Требует своих зависимостей; в текущем коде сервер использует порт **8099**, хотя старый README указывает 8080.

В devtools также находятся публикация ККТ-релизов и каталоги ATOL/Штрих. Они принадлежат исходному набору инструментов и не входят в универсальное ядро будущего harness. Во время начального упорядочивания они не переделывались.

## Быстрая проверка без 1С

Из корня рабочей области, при доступном Python:

```powershell
python -B .\1cv77-devtools\lint77.py --version
python -B .\1cv77-devtools\lint77.py .\research\kudir\corpus\ok2-compiled-and-ran\kudir_export_agent.ert
```

Второй пример читает исторический корпус: ожидаются ноль диагностик и код возврата `0`. Он не запускает обработку в 1С и не обращается к данным базы.

Контрольный отрицательный пример:

```powershell
python -B .\1cv77-devtools\lint77.py .\research\kudir\corpus\p2-compile-errors\kudir_export_agent.ert
```

Ожидаются семь ошибок L7706 и код возврата `1`. Это ожидаемый отказ на ошибочном примере, а не поломка инструмента. Исходные тесты и ограничения описаны в [LINT77.md](1cv77-devtools/LINT77.md).

## Данные и исследования

Локальная база теперь находится в `.local/bases/base-for-test`. Если она зарегистрирована в списке запуска 1С по прежнему пути, запись нужно перенастроить на новый путь. Регистрация базы и настройки установленной платформы этим упорядочиванием не менялись.

Состав базы сохранён целиком. Она пока не объявляется минимальным, обезличенным или неизменяемым тестовым эталоном. Сама база, исследовательские выгрузки и исходные журналы исключены из корневого Git.

Новые описания и скрипты исследований размещайте в тематическом каталоге `research`, данные исследований — в `.local/research`, локальные базы — в `.local/bases`. Производные результаты будущих запусков предназначены для `.artifacts`, а не для корня. Пока этот каталог не создаётся без необходимости.
